# 지표·통계 화면

기준은 [지표·통계 설계](../../../docs/specs/crelink-analytics.md), [디자인 인계](../../../design/analytics/handoff.md), [`packages/shared/src/analytics.ts`](../../../packages/shared/src/analytics.ts)입니다. 선행 수집은 [방문 계측](visitor-telemetry.md)을 따릅니다.

## 화면과 조회

| 역할 | 지표 | 통계 | API |
| --- | --- | --- | --- |
| 크리에이터 | `/me/landings/[publicId]/metrics` | `/me/landings/[publicId]/stats` | `GET /api/me/analytics` |
| 관리자 | `/admin/metrics` | `/admin/stats` | `GET /api/admin/analytics` |

네 페이지는 Server Component로 `loadSignedIn`을 사용하며 공용 `AnalyticsReport`를 `AnalyticsDashboard`에서 표시합니다. 크리에이터 범위는 API의 로그인 사용자로 고정하며 화면 URL의 관리자·타인 필터를 API에 보내지 않습니다. 기존 관리 레이아웃의 자기 랜딩 검사도 유지합니다. 관리자 통합은 기본적으로 지표 제외되지 않은 사람 크리에이터이며 `시험 계정 포함`으로 범위를 넓히거나 개별 크리에이터를 선택할 수 있습니다.

기존 `ManagerShell` 메뉴에 두 항목을 추가하고 이 메뉴에서만 휴대폰 편집 미리보기·토글을 숨깁니다. 기존 `AdminShell` 메뉴와 크리에이터 상세에도 연결합니다. 관리자 필터는 기존 크리에이터 검색·페이지 API로 만든 이름/이메일·단축 주소 선택 목록을 사용합니다. 선택한 크리에이터가 검색 결과나 현재 쪽에 없어도 상세 API로 이름과 선택값을 보존하며 UUID 입력란을 만들지 않습니다.

날짜 폼은 GET이며 한국 시간의 양 끝 날짜를 포함합니다. 기본 30일, 최대 366일, 최근 7·30·90일과 직접 입력을 지원합니다. 프리셋·분석 화면 이동·목록 쪽 이동은 현재 기간·크리에이터·시험 포함 조건을 보존합니다. 신규 GET 두 경로는 BFF의 좁은 허용 목록에도 연결하며 API가 역할·소유 범위를 다시 확인합니다.

## 표시 의미

- 지표: 수집된 페이지뷰, 정확한 익명 순 방문자·세션(복원 가능할 때), 클릭·가시 노출, 클릭한 페이지뷰 비율, 평균/누적 활성 체류, 일별 페이지뷰 막대·클릭 점선과 동일 데이터 표.
- 본인 표시(0233): 지표의 페이지뷰·익명 순 방문자 타일과 두 화면의 일별 표에 `본인 N` 뱃지를 붙입니다. 합계에서 빼지 않으며 `null`인 구간은 뱃지가 없습니다. 일별 표는 1 이상일 때만 표시합니다.
- 통계: 일별 수치, 클릭·노출 순 대상별 성과, 스크롤 25/50/75/100% 도달 페이지뷰, 유입·UTM 6종, 국가·도시·기기·브라우저·운영체제·언어·시간대·화면 크기·픽셀 비율 분포. 긴 보조 분포는 접근 가능한 `details`에 둡니다.
- 비율은 횟수 나눗셈으로 새로 만들지 않습니다. 전체는 `clickedPageViews / pageViews`, 대상은 관측 노출 뒤 같은 페이지뷰·대상에서 클릭한 비율이라는 API 정의를 표시합니다. 일반 수량은 발생일, 체류·비율·스크롤은 시작 페이지뷰/노출일 기준입니다.
- `null`을 0으로 바꾸지 않습니다. 정확한 고유 수를 복원하지 못하면 `확인 불가`, 분모·과거 자료가 없으면 `계산 불가`, 분포 미상은 `알 수 없음`, 상위 값 밖은 `기타`로 표시합니다. 과거 일별·페이지별 고유 수 합은 기간 전체 DISTINCT와 다른 이름으로 설명합니다.
- `coverage`의 첫 관측 자료일·원본 보존 경계·과거 합계 포함·복원 불가 분포를 보여줍니다. 첫 날짜를 실제 계측 도입일로 설명하지 않으며 빈 기간에 가짜 차트를 그리지 않습니다. 단축 방문은 있는데 브라우저 표시가 없으면 전송 차단·수집 이전 가능성을 알립니다.
- 기존 서버 리디렉트 방문·클릭은 별도 카드로 표시하며 신규 브라우저 수치와 합산하지 않습니다. 관리자 지표의 기존 운영 목표·가입·활성화·광고 카드는 `/api/admin/metrics`의 별도 전체 서비스/최근 기간 집계이며 날짜·크리에이터 필터를 적용하지 않는다고 명시합니다.

## 상태와 확인

401은 기존 홈 복귀, 관리자 403은 권한 없음, 없는 대상/잘못된 날짜는 조건 초기화, 연결·서버 오류는 다시 시도로 안내합니다. 크리에이터의400/404 조건 초기화는 관리자와 같은 내부 링크 이동으로 기본 기간을 다시 조회하고,500·네트워크 오류의 다시 시도는 레이아웃 조회까지 새로 실행하도록 문서 reload를 유지합니다(`AnalyticsPage.tsx`·`ErrorPanel.tsx`). 관리자 선택 목록·운영 지표만 실패하면 해당 부분을 따로 안내합니다. 크리에이터 두 하위 메뉴에는 진행 상태를 두고 기존 관리자 로딩을 유지합니다.

기존 토큰·카드·숫자·표를 재사용합니다. 700px 이하의 분석 날짜 폼은 한 열이며 날짜·계정 선택·조회는 48px 높이를 확보합니다. iOS 날짜의 고유 외형이 입력 외곽을 늘리지 않도록 `appearance: none`을 사용하되 입력은 native `type="date"`로 유지합니다. 계정 선택은 native `select`의 동작을 유지하고 외형과 높이를 맞춥니다. 빠른 기간은 44px 이상 조작 영역과 현재 선택 표시(`aria-current="date"`)를 제공합니다.

지표는 핵심 숫자를 집계 설명보다 먼저 표시합니다. 집계 상세는 펼침으로 제공하고 수집 이전·보존 집계 경고와 빈 기간 안내는 접힌 상태에서도 남깁니다. 일별 표는 최근 최대7일을 최신순으로 보여주며 이전 날짜는 별도 펼침으로 모두 접근할 수 있습니다. 이는 표시 순서/범위 변경이며 기간 전체의 집계는 바꾸지 않습니다. 날짜 열은 분절하지 않고 표 내부 가로 스크롤 중에도 고정합니다. 대상 제목·유입 값은 기존 줄바꿈을 유지합니다.

차트는 패키지 없이 작은 SVG이며 막대/점선으로 구분하고 같은 수치의 표를 제공합니다. 날짜 레이블은 SVG 밖의 HTML로 표시해 좁은 화면에서도 13px 글자 크기를 유지합니다. SVG 막대의 제목은 단일 문자열로 렌더해 서버/브라우저 hydration 차이를 방지합니다. 원본 IP·UA·방문자/세션 식별자를 표시하지 않습니다.

분석 UI의 변경 영향 검증은 `pnpm e2e --config tests/e2e/analytics-responsive.config.ts`로 세 엔진·네 페이지를 선택 실행합니다. 엔진/viewport 검사와 실제 iOS/Android 기기 검증은 구분하며 상세 범위는 [E2E 안내](../../../tests/e2e/README.md)를 따릅니다.

작은 회귀는 `apps/web`에서 `node --test src/lib/analytics.spec.ts`로 실행합니다. 본인 API 필터 격리, 관리자 선택·검색 분리 및 조건 보존, 잘못된 날짜의 API 검증 연결, null/0·비율·체류·미상/기타 표기를 확인합니다. 타입 검사와 변경 파일 ESLint를 실행하며 실제 390/1280px·역할·DB 수치·오류 흐름 및 전체 검사는 통합 담당이 [0188](../../../docs/work/orchestrator/0188-analytics.md)에 기록합니다.
