# 백엔드 작업 규칙

적용 범위: `apps/api/`와 그 하위 파일. [루트 공통 규칙](../../AGENTS.md)을 함께 따르며 여기서는 백엔드에 필요한 규칙만 정의합니다.

- NestJS 모듈·컨트롤러 등 기존 구성을 기준으로 확장합니다. 제품 기능 없이 공통 베이스 클래스나 계층을 미리 만들지 않습니다.
- 외부 HTTP 입력은 신뢰하지 않습니다. 입력 검증·인증·권한 확인은 각 엔드포인트의 실제 요구사항에 맞게 구현하고 오류 응답도 확인합니다.
- API 계약을 변경하면 웹·앱 소비자와 `packages/shared`의 영향 범위를 함께 확인합니다. 클라이언트 공용 패키지로 NestJS 전용 의존성이나 서버 설정을 내보내지 않습니다.
- DB를 도입하면 스키마·마이그레이션은 백엔드 코드와 함께 관리하고, DB 서버·네트워크 설정은 `infra/`에서 관리합니다. 마이그레이션의 데이터 손실·배포 순서·복구 가능성을 확인합니다.
- 환경변수 도입 시 실제 로딩 경로와 소비 코드를 같이 구현합니다. 파일만 만들어 자동 로딩된다고 가정하지 않습니다. 소유권은 [환경과 비밀값 관리](../../docs/development/environment-secrets.md)를 따릅니다.
- 검증에는 해당 HTTP 경로의 실제 요청·응답을 포함합니다. `/api/health`(liveness)는 DB를 확인하지 않습니다. DB 연결은 `/api/health/ready`(readiness)로 확인하며, 그 응답도 아직 연결하지 않은 캐시 같은 다른 의존성이 정상이라는 근거가 아닙니다.
- 백엔드 구현·운영 안내는 `apps/api/docs/`에 두되 앱·웹과 공유하는 계약 결정은 루트 문서 범위를 검토합니다. 현재 안내: [백엔드 API 운영 안내](docs/README.md)(실행·환경변수·DB 연결 수·종료(graceful shutdown)·인증·단축 도메인·방명록·보존 작업).
- 백엔드 변경은 공개 여부와 관계없이 이 영역의 `CHANGELOGS.md`에 기록합니다. 기록 형식과 공개 릴리스 노트는 [공통 변경 기록 규칙](../../docs/development/repository-policy.md#변경-기록)을 따릅니다.
