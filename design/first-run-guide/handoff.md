# 첫 사용 안내(시작 안내 카드) 인계

가입 직후 빈 랜딩의 관리 화면 `페이지 편집`에 세 단계 안내 카드를 둬서 "링크나 포트폴리오 1개 추가 → 내 크리링 링크 복사 → 인스타그램 프로필에 붙여 넣기"로 이끄는 시안입니다. 목적은 가입한 크리에이터를 실사용자(공개 랜딩에 보이는 외부 링크나 포트폴리오 1개 이상, [PRD 목표](../../docs/product/crelink.md#목표))로 바꾸는 것입니다. 상태: **사용자 승인 대기**.

## 대상

- work item: [0143 첫 사용 안내 디자인(실사용자 전환)](../../docs/work/designer/0143-first-run-guide-design.md)
- 제품 요구: [PRD](../../docs/product/crelink.md#요구사항) R1(인스타그램 프로필 링크에 넣는 단축 주소)·R18(관리 화면). 근거: [초기 사용자 모집 조사](../../docs/product/research/initial-user-acquisition.md#결론), [벤치마킹](../../docs/product/research/link-in-bio-benchmark.md#따라-할-것)(인링크 3단계 안내·"다음 한 걸음" 카드)
- 이어 쓰는 디자인: [미리보기 직접 편집](../preview-direct-edit/handoff.md)(지금 관리 화면 배치), [PC 랜딩 관리 화면](../desktop-landing-manager/handoff.md#화면과-상태)(빈 랜딩·저장 상태 문구)
- OpenDesign 프로젝트: 쓰지 않았습니다. 이번 작업은 시간 상한 안에서 새 생성 run 없이 기존 산출물 패턴과 `design/system/DESIGN.md`·`tokens.css`만으로 정적 HTML을 직접 썼습니다.
- 대표 파일: [index.html](index.html) — 상태 A~E를 1280px·390px으로 나란히 그렸습니다. 1280px 틀(머리글·메뉴·무대·패널)과 390px 틀(가로 탭·sticky 줄·랜딩)은 지금 구현을 줄여 그린 배경이고, 구현 대상은 **시작 안내 카드**(`.guide`)뿐입니다.

## 화면 위치

| 폭 | 위치 | 보이는 조건 |
| --- | --- | --- |
| 1024px 이상 | 오른쪽 편집 패널의 **처음 패널**(`PageOverview`), 제목 `페이지 편집` 바로 아래·`구역 선택` 목록 위. 처음 패널 설명 문장(`미리보기에서 고칠 곳을 눌러요.`)은 카드가 있는 동안 생략 | 구역·항목을 고르면 패널이 그 폼으로 바뀌므로 카드도 같이 빠지고, `← 전체`로 돌아오면 다시 보입니다 |
| 1023px 이하 | `편집` 모드에서 sticky 줄(단축 주소·`복사`·`편집 \| 미리보기`) 아래, 랜딩 내용 위 | `미리보기` 모드에서는 숨깁니다(방문자 화면과 같아야 함, R18) |

- `페이지 편집` 메뉴에만 둡니다. `프로필`·`방명록`·`주소 설정`·운영자 화면에는 두지 않습니다.
- 카드는 미리보기(무대 휴대폰 프레임, 390px의 랜딩) **안에 그리지 않습니다**. 미리보기는 방문자 화면 그대로여야 합니다.

## 단계와 완료 판정

| 단계 | 제목 | 완료 판정 | 저장 위치 | 근거 |
| --- | --- | --- | --- | --- |
| ① | `링크나 포트폴리오 1개 추가하기` | `GET /api/me/landing` 편집 상태에서 **방문자에게 보이는 항목 수 ≥ 1**: 숨기지 않고 차단되지 않은 외부 링크 + 포트폴리오 항목. 실사용자 정의와 같은 기준이고, 공개 랜딩 미리보기 데이터(`toLandingPreview`, 저장값 기준·초안 제외)의 링크 수 + 포트폴리오 수와 같습니다 | 서버(이미 있는 데이터). 새 저장 없음 | 실사용자 정의 |
| ② | `내 크리링 링크 복사하기` | 관리 화면의 단축 주소 `복사` 버튼(카드 안·1024px 이상 주소 막대·1023px 이하 sticky 줄·`주소 설정`의 내 크리링 링크) 중 하나를 눌러 클립보드 쓰기가 **성공**함 | 기기 로컬 저장(`localStorage`) | 복사 여부는 서버가 알 필요가 없음 |
| ③ | `인스타그램 프로필에 붙여 넣기` | 사용자가 `붙여 넣었어요`를 누름(자기 신고) | 기기 로컬 저장 | 크리링은 인스타그램 계정을 볼 수 없고 대신 등록하지 않습니다(R1 전제) |

- 순서: 현재 단계 = 아직 완료하지 않은 첫 단계입니다. 뒤 단계를 먼저 해도 됩니다(②의 `복사`는 0단계에서도 누를 수 있고 누르면 완료). ③의 `붙여 넣었어요`는 ③이 현재 단계일 때만 보입니다(링크가 없는 주소를 인스타그램에 걸어 "준비 중" 페이지로 팔로워를 보내지 않게).
- ①은 서버 데이터라 되돌아갈 수 있습니다: 보이는 항목을 모두 숨기거나 지우면 ①이 다시 미완료가 되고 카드가 다시 현재 단계 ①로 보입니다(닫지 않았다면).
- 로컬 저장 키(제안): `crelink.firstRunGuide.<publicId>` = `{ "copied": true, "instagramConfirmed": true, "dismissed": true }`(있는 키만). 랜딩 단위라 R6(랜딩 n개)이 와도 그대로 씁니다. 값에 주소·이메일 등 개인정보를 넣지 않습니다.

### 서버 저장과 개인정보 판단

- **서버 저장 불필요, 새 API·DB 없음**으로 판단합니다. ①은 이미 있는 편집 상태로 판정하고, ②·③·닫기는 기기 로컬 저장입니다. 다른 기기·브라우저에서는 ②·③이 다시 미완료로 보이지만 `닫기`로 끌 수 있고, 안내 목적상 허용합니다.
- **새 개인정보 수집 없음**: 로컬 저장값은 브라우저 밖으로 보내지 않는 진행 표시(참/거짓)뿐이고 식별자·연락처·행동 기록을 서버에 남기지 않습니다. 따라서 개인정보 처리방침의 수집 항목 범위 안입니다. 다만 처리방침 `쿠키` 구역은 브라우저 저장 항목을 모두 알리고 있어, 투명성을 위해 같은 구역에 한 줄 추가를 권합니다(아래 [미결정](#미결정)).
- 단계 완료·전환을 서버 통계로 보려면(예: ③ 확인 수) 새 이벤트 수집이 되므로 이번 범위에 넣지 않았습니다. 실사용자 전환은 서버의 ① 기준(공개 항목 수)으로 셀 수 있습니다.

## 상태와 전이

[index.html](index.html)의 상태 A~E입니다.

| 상태 | 언제 | 카드 |
| --- | --- | --- |
| A · 0단계 완료 | 공개 항목 0개, 로컬 기록 없음(가입 직후) | 진행 `0/3 완료`. ① 현재 단계(짙은 테두리·흰 숫자 원)와 주요 버튼 `링크 추가` + 보조 `포트폴리오 추가`. ② 주소 칩 + 보조 `복사`. ③ 한 줄 방법 |
| B · 1단계 완료 | 공개 항목 ≥ 1, `copied` 없음 | ① 초록 체크 + `완료 · 방문자에게 n개가 보여요`. ② 현재 단계, `복사`가 주요 버튼. 넘어간 순간 상태 줄 `1단계를 마쳤어요. 이제 내 크리링 링크를 복사해요.` |
| C · 2단계 완료 | ① 완료 + `copied` | ② 체크 + `복사했어요 · <주소>` + 보조 `다시 복사`. ③ 현재 단계: 3줄 방법, 대신 등록하지 않음 안내, 주요 버튼 `붙여 넣었어요`. 복사 직후 상태 줄 `주소를 복사했어요.` |
| D · 모두 완료(사라짐 직전) | 세 단계 완료(`붙여 넣었어요` 누른 직후) | 한 줄 완료 카드(초록 테두리): `준비를 마쳤어요` + `이제 인스타그램 프로필에서 내 크리링으로 들어올 수 있어요. 링크를 더 채워 보세요.` + `닫기`. 자동으로 사라지지 않음 |
| E · 사라진 뒤 | D에서 `닫기`, D를 본 뒤 다시 들어옴, 또는 어느 단계에서든 `시작 안내 닫기`(×) | 카드 없음. 처음 패널 설명 문장과 구역 목록이 그대로 올라옴 |

- 전이: A →(첫 링크·포트폴리오 저장 성공) B →(어느 `복사`든 성공) C →(`붙여 넣었어요`) D →(`닫기`·다음 진입) E. ×는 A~D 어디서든 E로 갑니다(`dismissed`). 세 단계 완료 상태로 다시 들어오면 D를 건너뛰고 E입니다.
- 로딩: 편집 상태를 받기 전에는 카드를 그리지 않습니다(로딩 뼈대에 카드 자리 없음, 받은 뒤 끼워 넣음). 로컬 저장은 하이드레이션 뒤에 읽으므로 서버 렌더에서는 카드를 그리지 않습니다(깜빡임·불일치 방지).
- 불러오기 실패: 지금 `편집 화면을 불러오지 못했어요.` 화면 그대로, 카드 없음.
- 복사 실패(클립보드 권한 거부 등): 지금 `CopyButton`의 실패 처리 그대로이고 ②는 완료되지 않습니다.
- 로컬 저장을 쓸 수 없는 브라우저(사생활 보호 모드 오류 등): 이번 화면 동안만 메모리 상태로 진행하고, 다음 진입에는 다시 보입니다.
- 1024px 이상에서 ①의 `링크 추가`는 지금 미리보기 `+ 링크 추가`와 같은 동작(패널이 `새 링크` 폼으로 바뀜), `포트폴리오 추가`는 `+ 포트폴리오 추가`와 같은 동작입니다. 1023px 이하에서는 같은 폼의 하단 시트를 엽니다. 저장 뒤 패널이 구역 목록으로 돌아오면(지금 구현) 카드는 B 상태로 보입니다.

| --- | --- |

## 컴포넌트와 토큰

- **새 토큰 없음, `tokens.json` 변경 없음.**
- 카드: `--ds-color-surface-default` 면, 1px `--ds-color-border-default`, `--ds-corner-lg`, `--elev-raised`, 안쪽 여백 `--ds-space-20`, 묶음 사이 `--ds-space-16`.
- 단계 행: 1px `--ds-color-border-frame`, `--ds-corner-md`, 안쪽 여백 `--ds-space-12`. 현재 단계는 테두리 `--ds-color-text-primary`(강조색 아님).
- 단계 표시 원(28px): 미완료 1px `--ds-color-border-strong` + `--ds-color-text-secondary` 숫자, 현재 `--ds-color-text-primary` 면 + `--ds-color-text-on-action` 숫자, 완료 `--ds-color-status-positive` 면 + `--ds-color-text-on-positive` 체크 아이콘.
- 진행 막대: 세 칸(높이 4, `--ds-corner-full`), 미완료 `--ds-color-border-default`, 완료 `--ds-color-status-positive`. 장식이며 `n/3 완료` 글자가 정보를 전합니다.

## 상호작용·접근성

- 카드는 `<section aria-labelledby="<제목 id>">`, 단계는 `<ol>`, 현재 단계 `<li aria-current="step">`. 완료 단계의 체크 아이콘은 `aria-hidden`이고 글자(`완료 · …`, `복사했어요 · …`)가 상태를 전합니다(색만으로 전하지 않음).
- 스크린리더: 단계가 넘어가거나 복사가 되면 카드 안 상태 줄(`role="status"`, 정중한 알림)이 위 문구를 읽습니다. 완료 카드의 문장도 `role="status"`입니다.
- 초점: ① 버튼은 지금 `+ 링크 추가`와 같이 폼(패널 제목·시트 첫 입력)으로 초점이 갑니다. 저장 뒤 구역 목록으로 돌아오면 지금 규칙대로 처음 고른 요소로 돌아옵니다. `붙여 넣었어요`를 누르면 초점을 완료 카드 `닫기`로 옮깁니다(누른 버튼이 사라지므로). 카드를 닫으면 1024px 이상은 패널 제목 `페이지 편집`, 1023px 이하는 sticky 줄의 `복사`로 초점을 옮깁니다.
- 키보드: 모든 조작은 버튼(Tab·Enter·Space). 초점 링은 3px `--ds-color-text-primary`, 간격 2px. 누를 수 있는 요소 높이 44px 이상(작은 버튼 `복사`·`다시 복사`·`닫기`는 시안 36px이므로 구현은 44px 터치 영역을 둡니다).
- 대비: 본문 `--ds-color-text-secondary`/흰 면, 숫자 흰 글자/`--ds-color-text-primary`, 체크 흰색/`--ds-color-status-positive`는 `DESIGN.md` 기준 쌍(4.5:1 이상)입니다. 실제 대비를 이번에 측정하지는 않았습니다.
- 모션: 단계 행·표시 원·진행 막대 색 전환 200ms `cubic-bezier(0.23, 1, 0.32, 1)`, `prefers-reduced-motion: reduce`에서 끔. 카드가 사라질 때 높이 애니메이션은 두지 않습니다(바로 빠짐).

- **새 API·공유 계약·DB 변경 없음으로 판단**(디자인 담당 판단, `orchestrator` 디자인 기술 검토는 아직 받지 않음). ①은 지금 `GET /api/me/landing` 편집 상태로, ②·③·닫기는 브라우저 로컬 저장으로 판정합니다. 웹 단독 구현으로 보이므로 `docs/specs/README.md`의 검토 대상(여러 역할이 구현하는 기능)에 해당하지 않는다고 봤습니다. 구현 티켓 분류 때 메인이 다르게 판단하면 검토를 받고 이 항목에 반영합니다.

E2E는 빈 랜딩 화면 단언(`tests/e2e/creator.spec.ts`)이 카드 때문에 깨질 수 있으니 구현 때 확인합니다.

## 미결정

1. **처리방침 고지**: 로컬 저장은 개인정보가 아니라 고지 의무는 없다고 보지만, 처리방침 `쿠키` 구역이 브라우저 저장 항목을 모두 나열하므로 "관리 화면 시작 안내 진행 표시를 이 기기 브라우저에만 저장해요(서버로 보내지 않음)." 한 줄 추가를 권합니다. 추가 여부는 사용자 결정.
2. **기존 링크가 있는 계정의 새 기기**: 공개 항목이 이미 있는 크리에이터가 새 기기로 들어오면 B 상태 카드가 한 번 보입니다(×로 끄면 그 기기에서는 끝). 지금 실사용자가 0명이라 영향이 작다고 봤고, 서버 저장으로 바꾸려면 새 필드·API가 필요해 이번 범위에서 뺐습니다.
3. **닫은 카드 다시 열기**: 다시 여는 입구를 두지 않았습니다. 같은 내용은 `/docs/guide`에 있습니다. 필요하면 처음 패널에 `시작 안내 다시 보기` 링크를 더하는 안이 있습니다.
4. **이메일·알림 재촉**: 티켓 범위 밖(광고성 정보 수신 동의 필요 가능).
