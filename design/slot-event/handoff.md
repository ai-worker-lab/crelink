# 외부 링크 +5 이벤트 인계

이벤트를 신청한 크리에이터에게 보이는 외부 링크 한도 5개를 더 주는 이벤트(PRD R24)의 화면 시안입니다. 관리 화면 `페이지 편집`의 이벤트 띠, `외부 링크` 패널의 신청 줄·한도 안내, 홈 안내, 운영자 `/admin/slot-event`, 운영자 크리에이터 상세의 한도 분해를 다룹니다. 상태: **승인**(2026-10-10, 사용자 위임(2026-10-10, 에픽 0088 진행 기록)에 따른 AI 승인. 근거는 아래 `기술 검토`).

## 위치 결정

| 화면 | 제안 위치 | 시안 | 근거 |
| --- | --- | --- | --- |
| 이벤트 띠 | 편집 화면 위쪽 | 넓은 화면: 처음 패널(`PageOverview`) 머리 아래·`구역 선택` 위. 좁은 화면: sticky 줄(`NarrowBar`) 아래·미리보기 위 | 지금 관리 화면이 화면 단위 알림을 두는 자리(`BannerSlotNotice`)와 같습니다. 넓은 화면의 가운데 무대는 방문자 모습 미리보기라 크리링 안내를 넣지 않고, 머리글 위 전체 폭 띠는 다른 메뉴에도 보여 `페이지 편집`에서만 보인다는 요구와 맞지 않습니다. 넓은 화면에서 다른 구역 패널을 열면 띠는 가려지고, 외부 링크 패널에서는 같은 신청 카드가 보입니다 |
| 외부 링크 패널 신청 줄 | 패널 안 | 한도 배지 바로 아래 한 줄(카드 또는 `신청함` 줄) | 한도와 같은 이야기라 배지 옆에 둡니다. 한도 찬 안내(목록 끝)에는 버튼을 두지 않고 글로만 이벤트를 알립니다. 버튼은 화면에 하나만 둡니다 |
| 홈 안내 | 대표 문장 아래 | 대표 설명 문단 아래, 시작 버튼 줄 위 카드 | 로그인 전에는 카드 안에 버튼을 따로 두지 않고 바로 아래의 기존 `구글로 시작하기`를 씁니다(주요 버튼은 화면에 하나, `DESIGN.md`). 로그인 후에는 카드 안 보조 버튼 `내 크리링에서 신청하기` |
| 운영자 이벤트 | `/admin/slot-event` | 그대로. 운영자 메뉴 `크리에이터 · 차단 도메인 · 광고 배너 · 이벤트 · 내 크리링 · 로그아웃` | 광고 배너와 같은 단독 운영 화면 |
| 크리에이터 상세 | 한도 도움말 | `추가 링크 슬롯` 도움말 분해 + 머리 정보 목록 `이벤트 신청일` 줄 | 신청일은 계정 정보라 이메일·가입일과 같은 목록에 둡니다 |

이름: 사용자에게 보이는 이벤트 이름은 `외부 링크 +5 이벤트`입니다. 관리 화면 구역 이름(`외부 링크`)과 맞추고, 크리에이터에게 낯선 "슬롯"을 쓰지 않습니다. 운영자 메뉴만 짧게 `이벤트`입니다.

## 화면과 상태

데이터는 설계 초안의 `CreatorLandingState.slotEvent { event, entry }`, `limits.visibleMax`(보너스 포함, 50 상한), `PublicSlotEventResponse`, `OperatorSlotEventResponse`, `OperatorCreatorDetail.slotEvent`만 씁니다.

### 관리 화면 `페이지 편집` 띠

| 상태 | 조건 | 모양(states) |
| --- | --- | --- |
| 띠 | `event.status = 'open'` · `entry = null` | A1(끝 있음), A2(`endsAt = null`) |
| 신청 중 | 요청 대기 | A3: 버튼 비활성 `신청 중…`, 띠 `aria-busy="true"`. 같은 화면의 패널 신청 카드도 함께 잠금 |
| 신청 완료 | 201·200(새로 신청·이미 신청 같음) | A4: 띠 자리에 성공 줄, 초점 이동. 한도 숫자는 `reload()`로 다시 읽은 `limits.visibleMax`. 띠는 다시 나오지 않음 |
| 실패 · 기간 아님 | 409 `slot_event_closed` | A5: 띠 자리에 오류 줄, 초점 이동, `reload()`(띠 조건이 풀려 띠는 사라짐). 다시 시도 없음 |
| 실패 · 이벤트 없음 | 404 `slot_event_not_found` | A6: A5와 같은 처리(아래 기술 검토 요청 2) |
| 실패 · 네트워크·그 밖 | 그 밖의 오류 | A7: 띠 유지, 띠 안 오류 줄, 버튼 `다시 시도`, 초점은 그 버튼으로 되돌림 |
| 띠 없음 | 신청함, `scheduled`, `ended`, `event = null` | A8: 지금 화면 그대로. 신청한 계정은 `구역 선택`의 `보이는 링크 n/10`에만 반영 |

- 완료·오류 줄은 `페이지 편집`을 떠나거나 새로 열 때까지 남습니다(저장하지 않음). 띠가 사라져도 남아야 하므로 결과 상태는 띠 바깥(`ManagerContext` 또는 `PageEditor`)이 들고, 넓은 화면은 처음 패널, 좁은 화면은 미리보기 위 같은 자리에 그립니다.
- 다른 편집과의 관계: 신청 중에도 미리보기 고르기·다른 패널은 막지 않습니다(신청은 한도만 늘림). 외부 링크 패널의 끌기·스위치는 기존 `pending` 규칙을 따릅니다.

### `외부 링크` 패널(좁은 화면 하단 시트)

순서: 한도 배지 → 이벤트 줄(있을 때) → 도움말 → 결과 안내(`ActionStatus`) → 링크 행 → `링크 추가` 또는 한도 안내.

| 상태 | 조건 | 배지 | 이벤트 줄 | 목록 끝(states) |
| --- | --- | --- | --- | --- |
| 미신청 · 진행 중 | `open` · `entry = null` | `보이는 링크 3/5` | 신청 카드(보조 버튼 `신청하기`) | `링크 추가`(B1) |
| 신청 중 | 요청 대기 | 그대로 | 버튼 비활성 `신청 중…` | 그대로(B2) |
| 신청 완료 | 201·200 | `보이는 링크 3/10` | `신청함` 줄(초점 이동) + `ActionStatus` 성공 | `링크 추가`(B3) |
| 실패 · 409·404 | 위와 같음 | 그대로 | 카드 자리에 오류 줄(초점 이동) | 그대로(B4) |
| 실패 · 네트워크 | 그 밖 | 그대로 | 카드 유지 + 카드 안 오류 줄 + `다시 시도`(초점 되돌림) | 그대로(B5) |
| 신청함 | `entry ≠ null`(기간과 무관) | `보이는 링크 3/10` | `이벤트 보너스 +5 받음 · 2026년 10월 10일 신청` | 그대로(B6) |
| 한도 참 · 미신청 · 진행 중 | `visibleUsed ≥ visibleMax` | `5/5` 경고 모양 | 신청 카드 | 이벤트 안내가 든 한도 문구(B7) |
| 한도 참 · 신청함 | 위 + `entry ≠ null` | `10/10` 경고 모양 | `신청함` 줄 | 지금 문구, 숫자 10(B8) |
| 한도 참 · 신청 불가 | `scheduled`·`ended`·없음, `entry = null` | `5/5` | 없음 | 지금 문구 그대로(B9) |
| 운영자 추가 슬롯 + 보너스 | `extra = 2` | `4/12` | `신청함` 줄 | B10. 패널은 한도를 나눠 보여 주지 않습니다 |

- 숨긴 링크 포함 전체 상한(50) 문구가 먼저인 지금 `linkLimitNotice` 순서는 그대로입니다. 보이는 한도 문구만 `미신청 · 진행 중`일 때 이벤트 문장으로 바뀝니다. 미리보기 끝의 추가 자리 안내(`.add-slot.is-notice`)도 같은 함수를 쓰므로 같은 문구가 됩니다.
- 신청 카드의 `신청하기`와 띠의 `신청하기`는 같은 요청·같은 진행 상태를 씁니다(좁은 화면에서는 둘이 동시에 DOM에 있음).

### 홈 `/`

| 상태 | 조건 | 모양(states) |
| --- | --- | --- |
| 로그인 전 · 진행 중 | `event.status = 'open'` | 카드 + 바로 아래 기존 `구글로 시작하기`(C1). 끝 없음은 `… 부터`(C2) |
| 로그인 후 · 미신청 · 진행 중 | 위 + 로그인 | 카드 안 보조 버튼 `내 크리링에서 신청하기` → `/me`(C3). 기존 `내 크리링 편집`·로그아웃 줄은 그대로 |

### 운영자 `/admin/slot-event`

| 상태 | 조건 | 모양(states) |
| --- | --- | --- |
| 진행 중 · 신청자 있음 | `status = 'open'` | 상태 배지 `진행 중`(성공 색), 기간 폼, 신청 수 타일, 표, 쪽 넘김(D1, index 5) |
| 시작 전 | `scheduled` | 배지 `시작 전`(경고 색)(D2) |
| 끝남 | `ended` | 배지 `끝남`(흐린 테두리)(D3) |
| 신청자 없음 | `entryCount = 0` | 표 대신 빈 문구(D4) |
| 저장 중 | `PUT` 대기 | 입력·버튼 잠금, `저장 중…`(D5) |
| 저장 성공 | 200 | 성공 줄, `router.refresh()`로 배지·표 갱신(D6) |
| 끝 ≤ 시작 | 화면 검사 또는 400 `slot_event_period_invalid` | `끝` 입력 `aria-invalid`, 오류 줄, 초점 `끝` 입력(D7) |
| 시작 비움 | 화면 검사 | `시작` 입력 `aria-invalid`, 오류 줄(D8) |
| 저장 실패 · 그 밖 | 네트워크·5xx | 오류 줄(`errorMessage`), 버튼 `다시 시도`, 입력 유지(D9) |
| 마지막 쪽 | `page = pages` | `이전 쪽 · 7 / 7`(D10) |
| 없는 쪽 | `entries = []`, `entryCount > 0` | 빈 문구 + `첫 쪽으로`(D13) |
| 불러오는 중 | `loading.tsx` | 제목 + 뼈대(카드 1, 행 3, 반복 애니메이션 없음)(D11) |
| 불러오기 오류 | 404 `slot_event_not_found`·5xx·네트워크 | `AdminShell` `ErrorPanel` 제목 `이벤트를 불러오지 못했어요.` + API 문구 + `다시 시도`(D12) |
| 권한 없음 | 403 | 기존 `AdminShell` 그대로 |

- 이벤트 행은 migration이 시드하므로 "이벤트 없음(설정 전)" 화면은 두지 않습니다(설계 핵심 결정 4). 행이 없으면 D12입니다.
- 표: 신청일시(`formatDateTime`, `--ds-font-mono`) · 이메일(`/admin/creators/{userId}` 링크) · 이름(없으면 `—`) · 단축 주소(`<code>slug</code>`). 신청 최신순 20개, `?page=` 서버 렌더, 쪽 넘김은 크리에이터 목록과 같은 `pagination`. 700px 이하는 카드(신청일시 / 이메일 굵게 / 이름 · 단축 주소). 긴 이메일·이름·주소는 줄을 바꿔 넘치지 않습니다.
- 기간 입력은 광고 배너 대화상자와 같은 `datetime-local` 두 칸(`ad-banner-period` 격자, `lib/seoul-time.ts` 변환, 한국 시간).

### 운영자 크리에이터 상세

| 상태 | 머리 정보 `이벤트 신청일` | `추가 링크 슬롯` 도움말 | 계정 관리 요약 |
| --- | --- | --- | --- |
| 신청함(E1) | `2026년 10월 10일 · 보이는 링크 +5` | `보이는 링크 한도 = 무료 5개 + 추가 슬롯 2개 + 이벤트 5개` | `보이는 링크 4/12 · …` |
| 신청 안 함(E2) | `신청 안 함` | 지금 문구 `… = 무료 5개 + 추가 슬롯 2개` | `4/7` |
| 상한에 걸림(E3) | 신청함 | `… + 추가 슬롯 45개 + 이벤트 5개 → 전체 링크 상한 50개` | `4/50` |

- 도움말은 지금처럼 입력 중인 추가 슬롯 값으로 바로 다시 계산하고, 이벤트 몫은 `slotEvent.bonusLinks`입니다. 운영자가 추가 슬롯을 바꿔도 이벤트 몫은 그대로 보입니다(R24 ②). 날짜는 `formatDate`.

## 문구 원문

`{…}`는 데이터입니다. 날짜·시각은 기존 `formatDate`(신청일)·`formatDateTime`(기간·신청일시) 결과를 그대로 넣고 `<time datetime>`으로 감쌉니다. `{bonus}`는 `event.bonusLinks`(신청함이면 `entry.bonusLinks`), `{max}`는 `limits.visibleMax`.

| 자리 | 문구 |
| --- | --- |

## 상호작용·접근성

- 띠·카드는 `section` + `aria-labelledby`(제목 줄 `외부 링크 +5 이벤트`)입니다. 제목 줄은 `h`가 아니라 `p`입니다. 좁은 화면에서 띠가 화면 숨김 `h1 페이지 편집`보다 앞에 오므로 제목 순서가 뒤집히지 않게 했습니다. 버튼 `신청하기`는 `aria-describedby`로 제목을 잇습니다(같은 이름 버튼이 화면에 둘이라도 구분).
- 신청 중: 버튼 `disabled` + 문구 `신청 중…`, 묶음 `aria-busy="true"`.
- 결과: 누른 버튼이 사라지는 경우(완료·409·404)는 그 자리에 남는 줄(띠: 완료·오류 줄, 패널: `신청함` 줄 또는 오류 줄)에 `tabindex="-1"`을 두고 초점을 옮깁니다. 완료 줄은 `role="status"`, 오류 줄은 `role="alert"`. 네트워크 오류는 버튼이 남지만, 진행 중 `disabled`로 초점이 빠지므로 끝난 뒤 초점을 `다시 시도` 버튼으로 되돌리고 오류는 `ActionStatus`(live region)로 알립니다. 1차 시안 확인(아래 검증)에서 패널 완료와 네트워크 오류 뒤 초점이 문서 처음으로 빠지는 것을 발견해 이 규칙을 더했습니다.
- 외부 링크 패널의 신청 결과는 기존 `ActionStatus`로도 읽힙니다. 한도 배지 숫자가 바뀌는 것은 따로 알리지 않습니다(완료 문장에 새 한도가 있음).
- 홈: 카드 `section` + `h2`(`외부 링크 +5 이벤트`), 기간은 `<time datetime>`. 홈의 주요 버튼은 하나(`구글로 시작하기` 또는 `내 크리링 편집`)이고 카드 버튼은 보조 버튼입니다.
- 운영자: 기간 오류는 해당 입력 `aria-invalid` + 오류 줄(`role="alert"`) + 그 입력으로 초점. 표는 화면 숨김 캡션, 700px 이하 카드 배치에서는 `thead`를 화면에서만 숨깁니다(광고 배너 표와 같음).
- 색만으로 상태를 전하지 않습니다: 배지는 글자(`진행 중`·`시작 전`·`끝남`·`이벤트 보너스 +5 받음`), 한도 찬 배지는 숫자와 안내 문장.
- 초점 링·비활성(0.48)·누를 수 있는 높이 44 이상은 기존 규칙 그대로. 새 움직임 없음.

## 기술 검토

2026-10-10 orchestrator 기술 검토 통과. 결정과 근거는 설계 [crelink-slot-event.md](../../docs/specs/crelink-slot-event.md#디자인-검토-의견) `디자인 검토 의견`에 있습니다. 요약:

1. 로그인 후 홈은 신청 여부를 모릅니다. 이미 신청한 계정에도 C3 카드가 보입니다(계약 그대로).
2. 신청 404는 409와 같이 처리합니다(시안 그대로).
3. 409는 웹 `errors.ts` 고정 문구 하나를 씁니다(시안 그대로).
4. 완료 알림은 `reload()` 뒤 `limits.visibleMax`, 실패 시 대체 문구(시안 그대로).
5. 결과 줄 상태는 `ManagerContext`에 둡니다(`slotNotice`와 같은 구조).
6. 마지막 쪽보다 큰 `page`는 `entries = []`·`entryCount > 0`(D13 그대로). 1 이상 정수가 아닌 `page`는 400이므로 웹이 1로 고칩니다.
7. 상태 배지 클래스 이름은 web 판단.

승인: 사용자 위임(2026-10-10, 에픽 0088 진행 기록)에 따른 AI 승인. R24 ①~⑦이 화면 상태 표(A·B·C·D·E)에 모두 대응되고, 기존 토큰·구성 요소만 쓰며, 390·1280px 가로 넘침 없음과 `pnpm design:check --require-lint` 통과가 아래 `검증`에 기록되어 있습니다. `formatDateTime` 표기 차이는 분류 대기 [0126](../../docs/work/web/0126-format-datetime-server-locale.md)으로 등록했습니다.

## 기술 검토 요청

설계 초안(2026-10-10)의 계약과 맞춰 본 결과, 아래를 확인해 주세요.

1. **로그인 후 홈에서 이미 신청한 계정.** 시안은 신청한 계정에는 홈 카드를 숨기기를 제안합니다(C4, 할 일이 없는 안내를 줄임). 지금 계약은 홈이 `GET /api/public/slot-event`만 읽어 신청 여부를 모릅니다. (a) 로그인 상태에서 홈이 신청 여부를 알 수 있게 할지(예: `MeResponse`에 신청 여부 한 필드, 또는 로그인 홈만 `CreatorSlotEventState`를 읽음), (b) 그대로 둘지 정해 주세요. (b)면 신청한 계정에도 C3 카드가 보이고, `/me`에서는 띠 없이 패널의 `신청함` 줄만 보입니다. 시안 문구는 두 경우 모두 그대로 씁니다.
2. **신청 404 처리.** 설계 표는 "이벤트 없음·네트워크 → 다시 시도 가능"이지만, 시안은 404를 409와 같이 처리합니다(오류 줄 + `reload()`, 다시 시도 없음). 이벤트 행이 없으면 다시 눌러도 같기 때문입니다. 이대로 맞춰도 될까요?
3. **409 문구.** API가 409 문구로 시작 전·끝남을 나누지만, 시안은 웹 `errors.ts`에 코드별 고정 문구 하나(`이벤트 신청 기간이 아니어서 신청하지 못했어요.`)를 두는 지금 방식을 씁니다. 띠는 `open`일 때만 보여서 409는 거의 "그 사이 끝남"이고, 시작 전 409는 운영자가 시작을 미룬 드문 경우입니다. API 문구를 그대로 보일지 고정 문구를 쓸지 정해 주세요.
4. **완료 알림의 새 한도.** 완료 문장은 `reload()` 뒤 `limits.visibleMax`를 씁니다. `CreatorSlotEventState` 응답에는 한도가 없어서, 다시 읽기가 실패하면 대체 문구(`보이는 외부 링크가 {bonus}개 늘었어요.`)를 씁니다. 응답에 `limits`를 넣을지, 대체 문구로 충분한지 확인해 주세요.
5. **결과 줄의 수명.** 409·404 뒤 `reload()`로 띠가 사라져도 오류 줄은 남아야 합니다. 결과를 띠 밖(`ManagerContext`)에 두는 구현이 지금 구조(`BannerSlotNotice`의 `slotNotice`)와 맞는지 확인해 주세요.
6. **운영자 없는 쪽.** `?page=`가 마지막 쪽보다 크면 `entries = []`, `entryCount > 0`으로 오는지 확인해 주세요. 시안은 D13(`이 쪽에는 신청자가 없어요.` + `첫 쪽으로`)을 둡니다.
7. **상태 배지 클래스.** `ad-status-*`를 그대로 쓸지 공용 이름으로 옮길지는 web 판단입니다. 모양은 같아야 합니다.

참고(범위 밖 발견): 로컬 Node 22.23(ICU 78)에서 `Intl.DateTimeFormat('ko-KR', { dateStyle: 'medium', timeStyle: 'short' })`가 `2026. 11. 30. PM 11:59`를 돌려주고, Chromium은 `오후 11:59`를 돌려줍니다. 서버 렌더 화면(홈·운영자)의 `formatDateTime` 결과가 브라우저와 다를 수 있습니다. 시안은 `오전/오후` 표기로 그렸습니다. 이 에픽 전부터 있는 `formatDateTime` 공통 문제라 분류 대기 work item 후보로 남깁니다.
