# 페이지 편집 미리보기 직접 편집·프로필 메뉴 인계

관리 화면(0051 시안, 0053 구현)의 `페이지 편집`을 **미리보기 직접 편집**으로 바꾸고 프로필·SNS 채널을 별도 `프로필` 메뉴로 빼는 시안입니다. 휴대폰 미리보기를 화면 가운데 무대에 두고, 미리보기 안 구역·항목을 누르면 오른쪽 편집 패널(휴대폰은 하단 시트)이 그 폼으로 바뀝니다. 상태: **사용자 승인 대기**. 승인 전 결정 거리는 [사용자 결정 필요](#사용자-결정-필요)에 있습니다.

- OpenDesign 프로젝트 id: `crelink-preview-direct-edit`(디자인 시스템 `user:crelink`, 실행 방식 Local Codex, 생성 1회 + 다듬기 5회). 프로젝트의 `reference/brief.md`가 생성에 준 요구 정리, `reference/current-manager.html`이 0051 시안 사본입니다.

## 정보 구조

```text
헤더: 크리링 · [운영자 화면](운영자만) · 로그아웃                      오른쪽 아래 떠 있는 `의견 보내기`(0057)
├─ 메뉴           ├─ 무대(가운데)                                └─ 편집 패널(오른쪽)
│  페이지 편집     │  주소 막대: 단축 주소 · 복사 · 주소 변경 ·        │  메뉴 제목(h1) + 메뉴별 내용
│  프로필(새)      │            공개 페이지 열기 · [저장하지 않은 변경 포함]
│  방명록          │  휴대폰 프레임(방문자 랜딩 그대로)
│  주소 설정
```

| 메뉴 | 주소 제안 | 무대(미리보기) | 패널 |
| --- | --- | --- | --- |
| 페이지 편집(기본) | `/me/landings/{publicId}` | 고르기 가능한 방문자 랜딩(편집 표시·추가 자리) | 처음: 구역 목록 / 고른 뒤: 그 구역·항목 폼 |
| 프로필(새) | `/me/landings/{publicId}/profile` | 맨 위로 스크롤, 프로필 머리·SNS 줄만 강조(나머지 흐리게) | 프로필 카드(사진·이름·소개·`프로필 저장`) + SNS 채널 카드(`SNS 채널 저장`) |
| 방명록 | `…/guestbook`(그대로) | 방명록 탭을 연 방문자 시점(비밀·숨긴 글 없음) | 지금 `GuestbookManager` 그대로 |
| 주소 설정 | `…/settings`(그대로) | 표시 없는 방문자 모습 | 지금 `AddressSettings` 그대로 |

- 메뉴 순서: 페이지 편집 → 프로필 → 방명록 → 주소 설정(0051 `확장 지점`의 자주 쓰는 순, 설정류 맨 끝).
- 모든 메뉴 위에 있던 `내 페이지` 머리 카드(사진·이름·단축 주소·`주소 변경`)는 없애고, 단축 주소·`복사`·`주소 변경`(→ 주소 설정 메뉴, 새 주소 입력 초점)·`공개 페이지 열기`(새 창)를 무대 위 **주소 막대**로 모읍니다. 머리글의 `공개 페이지 열기`도 이 막대로 옮깁니다. 사진·이름은 바로 아래 미리보기에 보이므로 다시 두지 않습니다.
- 메뉴 이름이 패널 머리 제목(h1)이고 문서 제목입니다(지금과 같음). 무대에는 제목을 두지 않습니다.

## 페이지 편집 상호작용

### 고르기

| 미리보기에서 누르는 것 | 패널(휴대폰 시트) 제목 | 패널 내용 |
| --- | --- | --- |
| 외부 링크 구역(목록 바깥 여백·구역 테두리) | `외부 링크` | 숨긴·차단 링크를 포함한 전체 목록(끌기 손잡이·숨기기 스위치·`수정`), 배지 `보이는 링크 n/5`, `숨긴 링크 포함 전체 n/50개`, `링크 추가` |
| 링크 하나 | `링크 · <표시 이름>` | 그 링크의 수정 폼(표시 이름·주소·설명·썸네일, `저장`·`취소`·`삭제`) |
| `+ 링크 추가` 자리 | `새 링크` | 새 링크 폼 |
| 포트폴리오 구역 | `포트폴리오` | 목록(위로·아래로·`수정`), `포트폴리오 추가` |
| 포트폴리오 하나 / `+ 포트폴리오 추가` | `포트폴리오 · <제목>` / `새 포트폴리오` | 그 폼 |
| 방명록 탭 | `방명록` | 방명록 켜기 스위치(즉시 저장), `방명록 글 관리`(→ 방명록 메뉴) |
| 프로필 머리·SNS 줄 | `프로필` | 요약(사진·이름·소개)과 `프로필에서 고치기`(→ 프로필 메뉴). 페이지 편집에서는 고치지 않음 |

- 마우스를 올린 구역·항목에 얇은 테두리와 테두리 위에 걸친 이름표(`외부 링크 · 편집`, `링크 · 유튜브 최신 브이로그 · 편집`)를 띄웁니다. 내용 흐름을 밀지 않는 절대 위치입니다. 고른 대상은 굵은 테두리와 이름표를 유지합니다. 평소에는 표시가 없고, 목록 끝의 점선 `+ 링크 추가`·`+ 포트폴리오 추가` 자리만 늘 보입니다.
- 미리보기 안 링크·SNS·포트폴리오는 이동하지 않고 고르기만 합니다(지금 미리보기와 같음). 탭(`링크`·`방명록`)은 전환되고, `방명록` 탭을 누르면 방명록 패널을 엽니다.
- 처음(아무것도 고르지 않음) 패널: 메뉴 제목 `페이지 편집`, 안내 `방문자 화면에서 구역이나 항목을 선택해 편집해요.`, `구역 선택` 목록 버튼(외부 링크 `보이는 링크 n/5` · 포트폴리오 `n/20` · 방명록 `켜짐`/`꺼짐`, 초안이 있으면 `저장 안 함`), `프로필 머리와 SNS 채널은 프로필 메뉴에서 수정할 수 있어요.` + `프로필에서 고치기`. 이 목록이 키보드·스크린리더로 구역을 고르는 길입니다.
- 고른 뒤 패널 머리: `← 전체`(처음 패널로), 제목, 한 줄 설명. 폼은 카드 테두리 없이 머리 아래 바로 둡니다(목록처럼 여러 묶음일 때만 카드).
- 숨긴 링크·차단 링크는 방문자에게 보이지 않으므로 **미리보기에 그리지 않고** 외부 링크 패널 목록에서만 고릅니다(숨김 행 흐림 + `숨김`, 차단 행 `차단됨` 위험 배지·사유·스위치 잠김 — 지금 `LinksSection` 그대로). 근거: 미리보기는 방문자 화면과 같아야 한다는 R18 원칙을 지키고, 흐린 가짜 줄이 실제 공개 화면과 헷갈리게 만드는 것을 피함.
- 링크 한도 도달: 배지 경고 모양, 패널의 `링크 추가` 자리에 지금 한도 안내 문구, 미리보기의 `+ 링크 추가` 자리도 같은 안내로 바꿉니다.

### 초안과 저장

- 저장 방식은 0051 [저장 방식](../desktop-landing-manager/handoff.md#저장-방식지금-코드와-같음) 그대로입니다(폼은 버튼 저장, 순서·숨기기·방명록 켜기는 즉시 저장 후 실패하면 되돌림).
- 입력이 저장값과 달라지면 패널 제목 옆 `저장 안 함`, 주소 막대 끝 `저장하지 않은 변경 포함`, 처음 패널 구역 목록 해당 줄 `저장 안 함`. 폼을 열기만 해서는 붙지 않습니다.
- 초안은 항목(링크 id·포트폴리오 id·새 항목)별로 남아 `← 전체`·다른 항목 고르기·메뉴 이동 뒤에도 그대로이고, 미리보기는 초안을 덮어 그립니다(지금 `ManagerProvider`·`toLandingPreview`). `취소`와 저장 성공만 지웁니다. 시안은 `← 전체`로 돌아간 뒤 미리보기가 저장값으로 돌아가는데, 구현은 초안을 계속 그립니다.

## 프로필 메뉴

- 패널: 프로필 카드(원형 사진 56px + `사진 고르기`·`지우기` 한 줄, 이름 `n/40`, 소개 `n/300`, 안내 문구, `프로필 저장`) → SNS 채널 카드(플랫폼 선택·계정 주소·`빼기` 행, `SNS 채널 추가`(10개면 안내), `SNS 채널 저장`). 필드·문구·검증은 지금 `ProfileSection`·`SocialsSection`과 같습니다.
- 무대: 미리보기를 맨 위로 스크롤하고 프로필 머리·SNS 줄을 강조 테두리로, 나머지를 흐리게 그립니다. 고르기·추가 자리는 없습니다.
- 페이지 편집에서 프로필 머리·SNS 줄을 누르면 패널 안내의 `프로필에서 고치기`로 이 메뉴에 옵니다.

## 반응형

| 폭 | 배치 |
| --- | --- |
| 1200px 이상 | 머리글 60 / 왼쪽 메뉴 208(고정) · 무대(남는 폭, 회색 바탕) · 패널 380~430(세로 스크롤) |
| 1024~1199px | 메뉴 약 170 · 무대 · 패널 330~390. 무대 휴대폰 안쪽 폭은 320px 아래로 줄지 않음 |
| 1023px 이하(900·390·320 확인) | 머리글 / 가로 탭 메뉴 / sticky 줄(단축 주소·`복사`, 오른쪽 `편집 \| 미리보기` 두 칸 전환) / 내용 최대 600 가운데. 페이지 편집은 프레임 없이 전체 폭 랜딩이 곧 편집 화면이고 구역마다 작은 `<구역> · 편집` 칩. 구역·항목을 누르면 하단 시트(머리 제목 + `닫기` 아이콘 버튼, 내용 스크롤, 아래 고정 `저장`·`삭제`). 프로필·방명록·주소 설정은 패널 내용(폼·목록)이 기본이고 `미리보기`로 방문자 모습 |
| 320px | 가로 넘침 없음(시트 포함) |

- 무대 휴대폰 프레임 화면 높이: `min(760px, 100dvh − 머리글 − 주소 막대와 여백 − 72px)`, 최소 420px. 72px는 오른쪽 아래 `의견 보내기`(48) + 간격(24) 자리라 버튼이 프레임을 덮지 않습니다(1280×820·1280×720 확인). 프레임 안만 스크롤합니다.
- 휴대폰 `편집 | 미리보기`: `미리보기`면 편집 칩·추가 자리를 숨겨 방문자 모습만 보입니다. 0053의 떠 있는 `미리보기` 버튼 + 전체 화면 대화상자를 대신합니다(떠 있는 버튼은 오른쪽 아래 의견 아이콘 버튼과 아래쪽을 다투고, 미리보기가 곧 편집 화면이라 따로 열 필요가 없음).
- 휴대폰 링크 끌어 정렬은 `외부 링크` 구역 시트의 목록에서 합니다.

## 상호작용·접근성

- 미리보기 안 고르기 대상은 이름 있는 버튼입니다: `외부 링크 구역 편집`, `<표시 이름> 링크 편집`, `포트폴리오 구역 편집`, `<제목> 포트폴리오 편집`, `방명록 탭 편집`, `프로필 편집`, `SNS 채널 편집`. 미리보기 안의 원래 링크(`<a>`)는 탭 순서에서 빼고(이동하지 않음) 고르기 버튼만 초점을 받습니다.
- 고르면 초점을 패널 제목으로 옮기고, `← 전체`로 돌아오면 고른 대상으로 초점을 돌려줍니다. 하단 시트는 Esc·`닫기`로 닫히고 연 대상으로 초점이 돌아옵니다(390px 확인).
- 휴대폰 `편집 | 미리보기`는 두 칸 전환(`aria-label="미리보기 모드"` 묶음, 고른 칸 `aria-pressed` 또는 라디오)입니다.
- 끌기 정렬의 키보드 조작·스크린리더 안내, 스위치 `aria-disabled`, 메뉴 `aria-current="page"`는 지금 코드 그대로.
- 초점 표시 3px, 반복 애니메이션 없음, `prefers-reduced-motion`에서 전환 효과 없음.
