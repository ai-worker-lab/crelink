# 광고 블록·배너 슬롯 인계

공개 랜딩의 크리링 광고 블록(R20)과 유료 회원용 크리에이터 배너 슬롯(R21), 이를 다루는 관리 화면 `페이지 편집`과 운영자 화면 시안입니다. 관리 화면은 승인된 [미리보기 직접 편집](../preview-direct-edit/handoff.md) 틀을 그대로 잇고 광고 블록·배너 슬롯만 더합니다. 상태: **사용자 승인(2026-10-09)**. 승인 때 정한 것은 [사용자 결정](#사용자-결정)에 있습니다.

## 대상

- work item: [0064 광고 블록과 배너 슬롯 디자인](../../docs/work/designer/0064-ad-banner-block-design.md), 다음 단계 [0065 기술 설계](../../docs/work/orchestrator/0065-ad-banner-block-design-spec.md)
- 제품 요구: [PRD R20·R21](../../docs/product/crelink.md#요구사항)과 관련 R4·R5·R13·R14·R18·R19
- OpenDesign 프로젝트 id: `crelink-ad-banner-block`(디자인 시스템 `user:crelink`, 실행 방식 Local Codex, 생성 1회 + 다듬기 11회). 프로젝트의 `reference/brief.md`가 생성에 준 요구 정리, `reference/preview-direct-edit.html`이 0056 승인 시안 사본, `reference/web-styles.css`·`reference/*.tsx.txt`가 운영자 화면을 그리려고 넣은 지금 웹 CSS·마크업 사본입니다.
- 대표 파일
  - [index.html](index.html): 눌러 볼 수 있는 시안. 점선 `시안 상태` 상자(페이지 편집 1024px 이상은 무대 아래, 1023px 이하는 주소 줄 아래, 공개 랜딩·운영자 화면은 본문 맨 위, 접힘)에서 바꿉니다. 이 상자는 제품 UI가 아닙니다.
    - 화면: 페이지 편집(처음) · 공개 랜딩 · 운영자 · 광고 배너 · 운영자 · 크리에이터 상세
    - 계정: 무료 · 광고 블록 / 배너 슬롯 부여됨
    - 배너 수: 기본(광고 게시 중 3장, 배너 슬롯은 보이는 2장 + 숨김 1장) · 1장 · 0장
    - 블록 위치: 맨 앞 · 사이(2번째 링크 뒤) · 맨 뒤(처음)
    - 방명록 탭: 켬 · 끔
    - 상태: 데이터 있음 · 로딩 · 저장 실패 · 배너 한도 도달 · 차단 배너 · 빈 랜딩
  - [states.html](states.html): 공개 랜딩 상태 모음(광고 블록 맨 앞·사이·맨 뒤, 1장, 여러 장 2번째 배너, 다음 버튼 초점, 숨김: 게시 0장·링크·포트폴리오 없음, 배너 슬롯 1장·여러 장·0장, 링크 0개·포트폴리오만, 방명록 탭 안).
- 기준: [디자인 시스템](../system/DESIGN.md)의 `광고 블록(R20)·배너 슬롯(R21)` 컴포넌트 줄과 `하지 말 것`의 공개 랜딩 장식 줄(이번에 고침).

## 정보 구조

```text
공개 랜딩 /p/{publicId}
└─ 프로필 머리 · SNS 줄 · [링크 | 방명록] 탭(방명록을 켠 경우)
   └─ 링크 목록(ul)
      ├─ 링크 카드 …
      ├─ 광고 블록 또는 배너 슬롯(li, 링크 목록 맨 앞·사이·맨 뒤 중 한 곳, 랜딩당 1개)
      └─ 링크 카드 …
   └─ 포트폴리오
└─ 바닥글: 크리링 · 개인정보 처리방침

관리 화면 /me/landings/{publicId} `페이지 편집`(0056 틀)
├─ 미리보기: 링크 목록 안 광고 블록/배너 슬롯(고르기 대상)
├─ 처음 패널 구역 목록: 외부 링크 · 광고 블록(또는 배너 슬롯) · 포트폴리오 · 방명록
├─ 외부 링크 패널: 링크 행 사이에 광고 블록/배너 슬롯 행이 섞여 함께 끌어 정렬
├─ 광고 블록 패널: 안내·지금 위치(편집 없음)
└─ 배너 슬롯 패널: 배너 목록 → 배너 폼(휴대폰은 하단 시트)

운영자 화면
├─ /admin/ad-banners(새 메뉴 `광고 배너`): 크리링 배너 목록·걸러보기·등록/수정 대화상자·내리기
└─ /admin/creators/{userId}: `계정 관리` 카드에 `배너 슬롯` 부여·회수, 새 `배너` 카드
```

- 무엇이 나오는지: 계정에 배너 슬롯이 없으면 광고 블록, 있으면 같은 자리에 배너 슬롯입니다. 위치 값은 하나이고 부여·회수로 바뀌지 않습니다.
- 운영자 메뉴 순서: 크리에이터 · 차단 도메인 · 광고 배너 · 내 크리링 · 로그아웃.

## 공개 랜딩

### 모양

| 요소 | 결정 |
| --- | --- |
| 자리 | 링크 목록(`ul.link-list`) 안의 `li` 하나. 링크 카드와 같은 폭(가운데 단 최대 480 − 좌우 여백)·같은 간격 |
| 틀 | 흰 카드 `--ds-color-surface-default`, 1px `--ds-color-border-default`, `--ds-corner-lg`, 링크 카드와 같은 옅은 그림자, 안쪽 여백 8 |
| 배너 | 3:1(`aspect-ratio: 3 / 1`, `object-fit: cover`, 가운데 기준), `--ds-corner-md`. 390px 화면에서 약 342×114 |
| 조작 줄 | 이미지 아래 높이 44. 왼쪽 `광고` 배지(광고 블록만), 오른쪽 위치 `2 / 3`(`--ds-font-mono`, 보조 글자)과 이전·다음 44px 원형 버튼(보조 버튼 모양, 선 화살표 아이콘) |
| 배너 1장 | 광고 블록: 조작 줄에 `광고` 배지만. 배너 슬롯: 조작 줄 없음(이미지 카드만). 다만 그 1장이 움직이는 배너면 아래 [움직이는 배너](#움직이는-배너-멈춤-버튼)처럼 멈춤 버튼만 있는 조작 줄을 둡니다 |
| 누르기 | 연결 URL이 있으면 배너 이미지 전체가 링크(링크 카드처럼 같은 창, 클릭 기록 주소). 없으면 누를 수 없는 이미지. hover는 링크 카드와 같이 카드 테두리를 `--ds-color-text-primary`로 |

- 링크 카드와의 구별: 링크 카드는 글자 줄(사이트 아이콘 + 굵은 표시 이름)이고, 광고 블록은 이미지가 먼저인 3:1 면과 늘 보이는 `광고` 배지입니다. 틀에 크리링 로고·강조색·장식을 넣지 않습니다.
- 크리링 표시 줄(바닥글)과의 관계: 바닥글은 그대로 두고, 광고 블록이 이를 대신하지 않습니다. 크리링 것이 랜딩에 나오는 곳은 이 둘뿐입니다.

### 넘기기

- 가로 `scroll-snap` 트랙(손가락 스와이프·트랙패드), 이전·다음 버튼, 블록 안에 초점이 있을 때 ←/→ 키. 처음에서 `이전`, 끝에서 `다음`은 비활성(순환하지 않음).
- 자동으로 넘어가지 않습니다. `prefers-reduced-motion: reduce`에서는 버튼으로 넘길 때 부드러운 스크롤을 끕니다.
- 위치 표시와 버튼은 스와이프로 넘긴 뒤에도 맞춥니다(스크롤 끝에서 현재 장 계산).

### 움직이는 배너 멈춤 버튼

사용자 결정(설계 미정 1 C, 2026-10-09)에 따른 디자인 보강입니다(work item 0076).

- 언제: 블록 안에 움직이는 배너(GIF·움직이는 WebP·APNG, 응답의 `stillImageUrl`이 있음)가 한 장이라도 있으면 둡니다. 정지 배너만 있으면 두지 않습니다.
- 자리: 조작 줄 오른쪽 끝, 이전·다음 버튼 오른쪽입니다. 44px 원형 보조 버튼이며 새 토큰은 없습니다. 조작 줄이 원래 없는 1장짜리 배너 슬롯은 높이 44 조작 줄을 만들어 오른쪽에 이 버튼만 둡니다. 1장짜리 광고 블록은 `광고` 배지 오른쪽 끝에 둡니다.
- 아이콘·이름: 재생 중에는 두 줄 일시정지 아이콘과 `aria-label="움직임 멈추기"`, 멈춘 뒤에는 삼각형 재생 아이콘과 `aria-label="다시 재생"`입니다. `aria-pressed`는 쓰지 않고 이름을 바꿉니다. 툴팁은 없습니다.
- 동작: 누르면 블록 안 모든 움직이는 배너가 정지 이미지로 바뀝니다. 장을 넘겨도 멈춘 상태가 유지되고, 페이지를 다시 열면 재생으로 돌아갑니다(저장하지 않음). 정지 배너는 바뀌지 않습니다.
- `prefers-reduced-motion: reduce`: 처음부터 정지 이미지를 보이고 버튼은 숨깁니다(CSS 미디어로만 정해 서버 렌더와 첫 그림을 맞춤).
- 320px: 조작 줄은 `광고` 배지·위치·이전·다음·멈춤을 한 줄에 둡니다. 넘치면 위치 표시 `2 / 3`을 숨기고, 장이 바뀔 때 `aria-live` 알림은 그대로 둡니다.
- 관리 화면 미리보기에서도 같은 버튼이 동작합니다(이동이 아니라서 막지 않음).

### 숨김(자리 없이 사라짐)

| 경우 | 공개 랜딩 | 관리 화면 미리보기(`편집`) |
| --- | --- | --- |
| 게시 중인 크리링 배너 0장 | 광고 블록 없음 | 그 자리에 점선 자리 `광고 블록 · 지금은 게시 중인 크리링 광고가 없어 방문자에게 보이지 않아요` |
| 랜딩에 보이는 링크·포트폴리오 0개 | 광고 블록 없음 | 빈 랜딩 그대로(추가 자리만) |
| 배너 슬롯의 보이는 배너 0장 | 배너 슬롯 없음 | 점선 자리 `배너 슬롯 · 보이는 배너가 없어 방문자에게 보이지 않아요` + 누르면 배너 슬롯 패널 |
| 보이는 링크 0개, 포트폴리오만 있음 | 링크 목록 자리에 광고 블록만(포트폴리오 위) | 같음 |

- 방명록 탭을 켠 랜딩에서는 `링크` 탭 안에만 있고 `방명록` 탭에는 없습니다.
- 위치는 숨긴·차단 링크를 포함한 전체 순서 안의 자리입니다. 바로 앞 링크가 숨겨지면 방문자 화면에서는 남은 링크 사이 같은 상대 자리에 보입니다.
- 광고 블록과 배너 슬롯은 빈 랜딩에서 다르게 동작합니다. 광고 블록은 보이는 링크·포트폴리오가 0개면 숨지만, 배너 슬롯은 보이는 배너가 있으면 빈 랜딩에도 보입니다(PRD R20 ⑥과 R21 ③의 차이, [사용자 결정](#사용자-결정) 7번에서 그대로 두기로 함). 숨김 조건은 서버와 관리 화면 미리보기가 같은 공유 함수로 계산합니다.

## 관리 화면 `페이지 편집`

0056 [페이지 편집 상호작용](../preview-direct-edit/handoff.md#페이지-편집-상호작용)에 다음을 더합니다.

| 미리보기에서 누르는 것 | 패널(휴대폰 시트) 제목 | 패널 내용 |
| --- | --- | --- |
| 광고 블록 | `광고 블록` | `크리링 광고가 나오는 자리예요. 지우거나 숨길 수 없고, 링크 사이 원하는 위치로 옮길 수 있어요.`, 지금 위치(`링크 목록 맨 앞`/`2번째 링크 다음`/`링크 목록 맨 뒤`), `외부 링크 목록에서 끌어 옮기기`(→ 외부 링크 패널, 광고 행 손잡이에 초점), `광고 블록은 보이는 링크 한도(5개)에 들지 않아요.`, 게시 배너 0장이면 `지금은 게시 중인 크리링 광고가 없어 방문자에게 보이지 않아요.` |
| 배너 슬롯 | `배너 슬롯` | 아래 [배너 슬롯 패널](#배너-슬롯-패널) |
| 배너 슬롯 안 배너 하나 | `배너 · <대체 문구>` | 그 배너 폼 |

- 이름표: 광고 블록 `광고 블록 · 위치 이동`, 배너 슬롯 `배너 슬롯 · 편집`. 고르기 버튼 이름 `광고 블록 위치 안내`, `배너 슬롯 편집`. 미리보기 안 이전·다음은 동작하지만 배너 링크는 이동하지 않습니다(0056 원칙).
- 처음 패널 구역 목록: 외부 링크 다음 줄에 `광고 블록`(보조 줄 `링크 목록 맨 뒤`·`링크 목록 맨 앞`·`2번째 링크 다음`) 또는 `배너 슬롯`(보조 줄 `보이는 배너 2/5장 · 전체 3장`). 초안이 있으면 `저장 안 함`.
- 외부 링크 패널 목록: 광고 블록/배너 슬롯 행이 링크 행 사이에 섞이고 같은 손잡이로 끌어 정렬합니다(즉시 저장, 실패하면 되돌림 — 링크 순서와 같은 방식).
  - 광고 행: 손잡이 · `광고` 배지 · `크리링 광고 블록` · `지울 수 없고 위치만 바꿀 수 있어요`. **숨기기 스위치·`수정`·삭제 없음.**
  - 배너 슬롯 행: 손잡이 · `배너 슬롯` · `보이는 배너 2장` · `수정`(→ 배너 슬롯 패널). 스위치·삭제 없음(슬롯을 감추려면 배너를 모두 숨김).
  - 한도 배지 `보이는 링크 n/5`와 `숨긴 링크 포함 전체 n/50개`는 이 행을 세지 않습니다.
  - 링크가 0개일 때: 지금 빈 문장(`LinksSection`) 위에 광고 행(또는 배너 슬롯 행) 하나만 보입니다. 옮길 자리가 없으므로 손잡이는 `aria-disabled`이고, 보조 줄은 `링크를 추가하면 그 사이로 옮길 수 있어요`입니다.
  - 키보드: 손잡이에 초점 → 스페이스·엔터로 들기 → ↑↓ → 스페이스·엔터로 놓기, Esc 취소. 안내 문장은 지금 `LinksSection`과 같고, 광고 행 이름은 `크리링 광고 블록`, 배너 슬롯 행은 `배너 슬롯`입니다.

### 배너 슬롯 패널

| 부분 | 내용 |
| --- | --- |
| 머리 | `← 전체` · `배너 슬롯` · `링크 사이에 넣는 내 배너예요. 여러 장이면 방문자가 넘겨 봐요.` |
| 배지 | `보이는 배너 2/5장`(보이는 배너만 셈, 상한은 설정값 n. 시안은 5)과 `숨긴 배너 포함 전체 3/20장`(보관 상한, 설정값). 가득 차면 경고 모양. 링크의 `보이는 링크 n/5`·`전체 n/50개`와 같은 방식 |
| 목록 행 | 끌기 손잡이 · 3:1 썸네일 96×32 · 대체 문구(한 줄 말줄임) · 연결 도메인 또는 `연결 없음` · 숨기기 스위치 · `수정` |
| 숨긴 배너 | 내용 흐림(0.45) + `숨김` |

## 운영자 화면

### 광고 배너(`/admin/ad-banners`, 새 화면)

- 제목 `광고 배너`, 설명 `게시 중인 배너는 배너 슬롯이 없는 모든 랜딩의 광고 블록에 나와요. 여러 장이면 아래 순서대로 넘겨 봐요.`, 주요 버튼 `배너 등록`.
- 순서(결정 4): 운영자가 정합니다. 표 첫 열에 끌기 손잡이를 두고, 지금 관리 화면 링크 정렬과 같은 끌기·키보드 정렬을 씁니다(스페이스·엔터로 들기 → ↑↓ → 놓기, Esc 취소, 즉시 저장, 실패하면 되돌림). 안내 문장은 `<대체 문구> 배너를 3번째로 옮겼어요.`입니다. 새 배너는 맨 뒤에 들어갑니다. 순서는 `전체` 걸러보기에서만 바꿀 수 있고, 다른 걸러보기에서는 손잡이를 숨깁니다. 방문자에게는 게시 중인 배너만 이 순서대로 보입니다.
- 걸러보기 버튼 묶음 `전체 n · 게시 중 n · 예약 n · 끝남 n`(`aria-pressed`).
- 목록: 1280px 표(손잡이 · 썸네일 120×40 · 대체 문구 · 연결 URL · 게시 기간 · 상태 · 노출 · 클릭 · 행동), 700px 이하 카드(노출·클릭은 `노출 1,240 · 클릭 38` 한 줄). 노출·클릭은 게시 시작부터의 누적이고, 숫자는 `--ds-font-mono`로 오른쪽 정렬합니다(결정 6). 기록 기준은 기술 검토 `계약 가정 수정` 10번입니다. 표 위에 도움말 `노출은 방문자가 랜딩을 열었을 때 첫 장 기준으로 세요. 크리링 안에서 연 화면은 세지 않아요.`를 둡니다.
- 상태 배지: `게시 중`(성공 색), `예약`(경고 색), `끝남`(흐린 테두리). 상태는 지금 시각과 게시 기간으로 정합니다.
- 행동: 게시 중·예약은 `수정`·`내리기`, 끝남은 `수정`(기간을 다시 열 수 있음). `내리기` 확인 `이 배너를 내릴까요? 게시 끝을 지금으로 바꿔 모든 랜딩에서 바로 빠져요.` → 끝남.
- 게시 중 0장 경고 줄: `지금 게시 중인 배너가 없어 모든 랜딩에서 광고 블록이 숨어 있어요.`
- 빈 목록 `등록한 광고 배너가 없어요.`, 로딩 뼈대, 불러오기 오류(`ErrorPanel`: `광고 배너를 불러오지 못했어요.` + `다시 시도`).
- 등록·수정 대화상자(1280px 가운데 최대 560, 700px 이하 하단 시트): 이미지(필수)·대체 문구(필수 n/100)·연결 URL(필수, http/https·차단 목록)·게시 시작(날짜·시각, 필수)·게시 끝(선택, `비워 두면 내릴 때까지 게시해요.`)·`방문자에게 이렇게 보여요` 미리보기(광고 블록 틀)·`저장`·`취소`. 오류: `게시 끝은 시작보다 뒤여야 해요.`, 차단 도메인, 저장 실패 + `다시 시도`.

## 접근성

- 광고 블록·배너 슬롯은 `section`(`role="region"`) + `aria-roledescription="캐러셀"` + `aria-label`입니다. 영역 이름은 `크리링 광고`이고, 배너 슬롯은 `<크리에이터 이름> 배너`(표시 이름이 없으면 `크리에이터 배너`)입니다. 각 배너는 `role="group"` + `aria-roledescription="배너"` + `aria-label="2 / 3"`.
- 스와이프 대체 수단: 이전·다음 버튼(`aria-label="이전 배너"`·`"다음 배너"`, 끝에서 `disabled`)과 블록 안 ←/→ 키. 장이 바뀌면 `aria-live="polite"` 영역이 `3장 중 2번째 배너`를 읽습니다. 장 넘김이 자동이 아니므로 캐러셀 일시정지 버튼은 두지 않습니다. 움직이는 배너의 움직임은 [움직이는 배너 멈춤 버튼](#움직이는-배너-멈춤-버튼)으로 멈춥니다(WCAG 2.2.2).
- 보이지 않는 배너는 구현에서 `inert`로 초점·읽기에서 뺍니다(`aria-hidden`만 쓰지 않음). 시안은 보이지 않는 배너 링크에 `tabindex="-1"`만 둡니다.
- 배너 이미지 `alt`는 크리에이터·운영자가 넣은 대체 문구. 연결 URL이 있으면 링크 이름이 곧 대체 문구입니다.
- `광고` 배지는 화면 글자 그대로 읽힙니다(색만으로 구분하지 않음). 광고 블록 영역 이름에도 `광고`가 들어갑니다.
- 관리 화면 정렬은 지금 dnd-kit 키보드 정렬과 스크린리더 안내를 그대로 쓰고, 광고 행에는 스위치가 없으므로 초점 순서가 손잡이 하나입니다.
- 초점 링 3px `--ds-color-text-primary`, 반복 애니메이션 없음, `prefers-reduced-motion` 존중.

| 관리 화면 패널 | 링크·포트폴리오·방명록·프로필 안내 | `광고 블록` 안내, `배너 슬롯` 목록·폼 추가 |
| 운영자 메뉴 | 크리에이터 · 차단 도메인 | 크리에이터 · 차단 도메인 · 광고 배너 |
| 운영자 크리에이터 상세 | 추가 링크 슬롯·이용 정지·통계·링크 | `배너 슬롯` 부여·회수, `배너` 카드 |

## 기술 검토

2026-10-09 orchestrator가 디자인 기술 검토를 했습니다(`docs/specs/README.md` 1단계, 읽기 전용). 판정은 **통과(주의점 있음)**이고, 막는 문제는 없습니다. 아래 `A` 주의점과 `계약 가정 수정`은 이 문서 본문에 반영했습니다(반영 결과는 절 끝). `B` 구현 주의점과 `0065 설계로 넘길 항목`은 [0065 기술 설계](../../docs/work/orchestrator/0065-ad-banner-block-design-spec.md)에서 다룹니다. 이 절이 디자인 쪽 계약 가정의 기준이며, 검토 전에 적었던 가정(공개 응답 최상위 슬롯, `ReorderRequest.ids` 특수 id, 배너 id만 담은 클릭 주소)은 아래 `계약 가정 수정`으로 대체합니다.

### 판정

**통과(주의점 있음)**

지금 스키마·API·웹 구성 요소로 구현할 수 있습니다. 구현을 막는 문제는 없습니다. 다만 다음 두 가지는 사용자 승인 전에 고쳐 두는 것을 권합니다.

- `계약 가정 수정` 절의 1·2·3·6번은 handoff `기술 검토` 절의 가정과 지금 코드가 달라서 바로잡아야 합니다.
- `주의점`의 A1~A4는 handoff에 문구·상태를 한두 줄 더하면 됩니다.

### 막는 문제

없음.

### 주의점

**디자이너가 handoff에서 보강할 것**

- **A1. 차단 배너를 `수정`했을 때의 동작이 링크와 다릅니다.**
  - handoff는 "`수정`으로 주소를 바꿔 저장하면 다시 검사"라고 적었습니다.
  - 지금 링크는 주소를 바꿔도 차단이 풀리지 않고, 운영자가 풀어야만 풀립니다. 근거: `apps/api/src/creator/links.service.ts:94-119`의 update는 `blocked_at`을 건드리지 않습니다. `EditableLinkCard.tsx:11`에도 "수정·삭제는 가능"이라고만 적혀 있습니다.
  - 운영자가 직접 차단한 배너를 크리에이터가 주소만 바꿔 풀 수 있으면 우회로가 됩니다.
  - 권장: 링크와 같게 "수정해도 차단은 운영자가 풀 때까지 유지"로 문구를 고칩니다.
- **A2. 배너 이미지 형식 오류 문구가 맞지 않습니다.**
  - handoff는 지금 `file_type_unsupported` 문구를 쓴다고 했습니다. 그런데 그 문구는 `JPG·PNG·WebP·GIF 이미지만 올릴 수 있어요.`라서 GIF를 허용한다고 안내합니다(`apps/web/src/lib/api/errors.ts:16`).
  - `ImageField`도 GIF가 들어 있는 `ALLOWED_IMAGE_TYPES`로 검사합니다(`apps/web/src/components/me/ImageField.tsx:37`).
  - 결정 3에서 GIF를 받지 않기로 하면 배너용 문구가 따로 필요합니다(예: `배너는 JPG·PNG·WebP 이미지만 올릴 수 있어요.`).
- **A3. 빠진 상태가 하나 있습니다.**
  - 크리에이터가 배너 슬롯 패널이나 배너 폼을 연 채로 운영자가 슬롯을 회수하면, 배너 API가 권한 오류(새 코드)를 돌려줍니다. 그때의 문구와 이동(예: `배너 슬롯이 회수되어 광고 블록으로 돌아갔어요.` → 상태 다시 읽기)이 없습니다.
  - 빈 상태도 하나 빠졌습니다. 링크가 0개인 외부 링크 패널(`LinksSection.tsx:138-140`의 빈 문장)에서 광고 행만 보일 때의 모양이 정해져 있지 않습니다.
- **A4. 최소 크기 600×200을 막을지 정해야 합니다.**
  - 업로드 제한 표에는 `최소 600×200`이 있지만, 오류 문구·상태는 없습니다.
  - 지금 업로드는 매직 바이트로 형식만 봅니다(`apps/api/src/files/files.service.ts:13-20`). 크기를 막으려면 이미지 머리 정보를 읽는 코드를 더하고 오류 상태도 하나 더해야 합니다.
  - 권장: `권장`만 두고 최소 크기는 막지 않습니다. 막는다면 오류 문구를 더합니다.
- **A5. 크리에이터 배너 영역 이름의 빈 값을 정해야 합니다.**
  - 영역 이름은 `<크리에이터 이름> 배너`인데, 표시 이름은 null일 수 있습니다(`PublicLandingView.displayName`).
  - 이름이 없을 때 쓸 문구(예: `크리에이터 배너`)를 정해야 합니다.
- **A6. 노출·클릭 수를 보는 화면이 없습니다.**
  - R20 ⑧은 기록과 내부 열람만 요구합니다.
  - 운영자가 화면에서 수치를 봐야 한다면 `/admin/ad-banners` 표나 크리에이터 통계 카드에 열이 필요합니다. 필요한지 사용자에게 확인합니다. 필요 없으면 이번에는 DB 조회로 충분합니다.
- **A7. 이 비대칭이 의도인지 확인합니다.**
  - 보이는 링크·포트폴리오가 0개이면 광고 블록은 숨기지만, 배너 슬롯은 보이는 배너가 있으면 빈 랜딩에도 보입니다. PRD R20 ⑥과 R21 ③이 실제로 다릅니다.
  - handoff 숨김 표가 이 차이를 분명히 적어 두면, 서버와 미리보기의 숨김 조건이 어긋나지 않습니다.

**구현 주의점(0065와 구현 티켓에서 다룰 것)**

- **B1. 미리보기 안 광고 블록은 `EditItem`이 아니라 `EditRegion` 식으로 감싸야 합니다.**
  - `EditItem`은 내용을 `<button>`으로 감쌉니다(`LandingEdit.tsx:114-123`). 그 안에 이전·다음 버튼을 넣으면 버튼 안에 버튼이 들어가 HTML 규칙에 어긋납니다.
  - `EditRegion`은 안쪽 버튼 누르기를 무시하므로(`LandingEdit.tsx:54`) 이전·다음이 그대로 동작합니다.
  - 이름표 `광고 블록 · 위치 이동`을 그리려면 `EditRegion`에 고정된 ` · 편집` 꼬리(`LandingEdit.tsx:68`)를 바꿀 수 있게 해야 합니다.
  - 배너 슬롯 안의 배너는 장마다 `EditItem`으로 그려도 됩니다. 이전·다음 버튼이 장 밖에 있기 때문입니다.
- **B2. 넘기기(캐러셀)**
  - iOS WKWebView(인스타그램 인앱 브라우저)는 Safari 26 전에는 `scrollend` 이벤트가 없습니다. 지금 장 계산은 `IntersectionObserver`나 스크롤 디바운스로 해야 합니다.
  - 초점이 트랙 안 링크에 있으면 ←/→ 키가 브라우저 기본 가로 스크롤과 겹칩니다. 기본 동작을 막고(`preventDefault`) `scrollTo`로 넘깁니다.
  - React 19.2.3이라 `inert` 속성을 그대로 쓸 수 있습니다.
  - `Landing`은 서버·클라이언트가 함께 쓰는 구성 요소입니다. 캐러셀만 `'use client'`로 두면 됩니다.
- **B3. 이미지를 불러오지 못한 장 건너뛰기**
  - 하이드레이션 전에 실패한 `<img>`에는 `onError`가 오지 않을 수 있습니다. 마운트할 때 `complete && naturalWidth === 0`도 확인합니다.
  - `RemoteImage`는 크기 조절 없이 원본(최대 4MB)을 그대로 보냅니다(`apps/web/src/components/RemoteImage.tsx`). 첫 장이 아닌 장은 `loading="lazy"`로 둡니다. 배너만 용량 한도를 낮출지도 검토합니다.
- **B4. 끌어 정렬하기**
  - dnd-kit 목록에 슬롯 행을 섞는 것은 화면 쪽에서만 쓰는 특수 id로 됩니다.
  - 스크린리더 안내(`LinksSection.tsx:104-123`)는 `… 링크를 들었어요`처럼 "링크"가 박혀 있습니다. `크리링 광고 블록을 들었어요` / `배너 슬롯을 …`처럼 종류마다 이름이 바뀌어야 합니다.
- **B5. 단축 도메인 경로가 막혀 있습니다.**
  - 운영 Caddy는 단축 도메인에서 `/{slug}`와 `/c/[a-z0-9]{10}`만 API로 넘기고 나머지는 404를 줍니다(`infra/prod/Caddyfile:42-77`).
  - 배너 클릭 경로를 새로 만들면 Caddy와 `SHORT_DOMAIN_ROUTES`(`apps/api/src/short-link/short-link.controller.ts:18-21`)를 함께 고쳐야 하므로 infra 티켓이 필요합니다.
  - 단축 주소는 3자 이상이므로 1~2자 접두사(`a`, `b`)는 단축 주소와 겹치지 않습니다.
- **B6. 새 API 경로는 BFF 허용 목록에 하나씩 넣어야 합니다.**
  - 대상: `apps/web/src/app/api/backend/[...path]/route.ts:13-40`, 그리고 `/api/me/banners…`와 `/api/admin/ad-banners…` 등.
- **B7. 운영자가 올린 이미지 파일의 삭제 규칙**
  - `files.owner_user_id`는 `ON DELETE CASCADE`입니다(`0001_crelink_mvp.sql:38`). 운영자 계정이 지워지면 크리링 배너 이미지 행도 사라집니다.
  - 크리링 배너의 이미지 FK는 `RESTRICT`로 두거나, 그 동작을 설계에 적습니다.
- **B8. 차단 도메인을 추가할 때 기존 배너도 차단해야 합니다.**
  - 차단 도메인을 추가하면 기존 링크를 같은 트랜잭션에서 차단합니다(`apps/api/src/admin/admin.service.ts:186-206`). 크리에이터 배너도 같이 막아야 R14 ③과 맞습니다.
  - 크리링 배너에도 적용할지 정합니다.
- **B9. 운영자 게시 기간 입력의 시간대**
  - 날짜·시각 입력(`datetime-local`)은 Asia/Seoul 기준으로 ISO 문자열로 바꿔 보냅니다. 집계 테이블의 날짜 기준과 같습니다.
  - `게시 중`·`예약`·`끝남` 상태와 걸러보기 수는 서버가 `now()`로 계산합니다.
- **B10. 디자인 토큰**
  - handoff·DESIGN.md가 쓰는 토큰(`--ds-color-border-strong`, `--ds-corner-sm/md/lg`, `--ds-font-mono`, `--ds-color-status-*-subtle`, `--ds-space-8`)은 모두 `packages/design-tokens/generated/tokens.css`에 있습니다.
  - 숨김 흐림 0.45는 지금 `.link-edit-item.is-hidden`과 같습니다(`apps/web/src/styles.css:2004`).
  - `index.html`에는 색 리터럴이 없습니다. 새 토큰은 필요 없습니다.

### 계약 가정 수정 사항

1. **공개 응답 모양**
   - 슬롯을 `PublicLandingView`의 최상위가 아니라 `PublicBlockView` 안에 둡니다: `slot: { kind: 'ad' | 'creator'; afterLinkCount: number; banners: Array<{ id; imageUrl; alt; clickUrl: string | null }> } | null`.
   - 슬롯은 리스트 구역의 한 항목이고, 위치도 구역(`landing_blocks`)에 저장하므로 이 자리가 맞습니다.
   - `afterLinkCount`는 그 구역의 보이는 링크 중 슬롯 앞에 오는 수입니다. 숨김 조건을 서버가 계산해 `null`을 보내자는 가정은 맞습니다.
2. **미리보기가 공개 API를 쓰지 않습니다.**
   - 관리 화면 미리보기는 `GET /api/me/landing`(`CreatorLandingState`)을 화면 쪽에서 `toLandingPreview`로 바꿔 그립니다(`apps/web/src/lib/landing-preview.ts:139-218`, `ManagerPreview.tsx:145`).
   - 따라서 슬롯 배치·숨김 규칙을 `packages/shared`에 순수 함수 하나로 두고, API와 `toLandingPreview`가 함께 써야 합니다.
   - 미리보기는 실제 캐러셀을 그리므로, 편집 상태에는 게시 중 크리링 배너 "수"가 아니라 **목록(이미지·대체 문구)**이 있어야 합니다.
   - 미리보기의 `clickUrl`은 링크처럼 저장된 주소를 그대로 씁니다. 감싸는 쪽이 이동을 막습니다(`ManagerPreview.tsx:185-186`).
3. **위치 저장**
   - `ReorderRequest.ids`에 특수 id를 섞는 방식은 안 됩니다.
     - `orderedIds`는 지금 id 집합과 정확히 같아야 통과합니다(`apps/api/src/common/input.ts:54`).
     - 저장 쿼리는 `unnest($2::uuid[])`로 uuid로 바꿉니다(`links.service.ts:147-151`).
     - `ReorderRequest`는 포트폴리오 정렬과도 함께 씁니다.
   - 권장: 링크 전용 `LinkOrderRequest { ids; slotIndex?: number }`(숨김·차단 포함 전체 순서에서 슬롯 앞 링크 수). 응답은 `{ links: LinkView[]; slotIndex }`로 바꿉니다. 호출하는 곳은 `LinksSection.tsx:98` 한 곳입니다.
   - `slotIndex`를 생략하면 지금 위치를 유지합니다(웹·API 배포 순서와 상관없게).
4. **위치 모델(AI 제안)**
   - `landing_blocks.slot_position integer NULL`. `NULL`은 맨 뒤이고 기본값이라, R20 ① "처음 위치 맨 뒤"를 백필 없이 지킵니다.
   - 값이 k이면 "`links.position < k`인 링크들 다음"입니다. 정렬할 때 링크를 0..n-1로 다시 매기고, `slotIndex ≥ n`이면 `NULL`로 저장합니다.
   - 새 링크는 지금처럼 `max(position)+1`이라 맨 뒤 슬롯 앞에 들어가고, 사이 슬롯 뒤에 들어갑니다.
   - 링크를 지워도 순서를 다시 매기지 않으므로(`links.service.ts:132-137`) 슬롯은 같은 뒤 링크 앞에 남습니다.
   - 부여 여부는 계정 단위인 `users.banner_slot_granted_at timestamptz`로 둡니다. 이 값이 handoff의 "부여일"이 됩니다.
5. **관리 화면 편집 상태(`CreatorLandingState`)에 더할 것**
   - `slot { kind; slotIndex }`
   - `adBanners`(게시 중 목록)
   - 배너 슬롯이면 `banners`(숨김·차단·사유·순서 포함)와 `bannerLimits { max; used }`
6. **클릭 주소**
   - 크리링 배너는 모든 랜딩이 함께 쓰므로, 링크의 `{SHORT}/c/{id}`처럼 배너 id만으로는 R20 ⑧의 "랜딩·배너별" 기록을 할 수 없습니다. 주소에 랜딩을 넣어야 합니다. 예: `{SHORT}/a/{bannerPublicId}/{landingPublicId}`.
   - 크리에이터 배너는 `{SHORT}/b/{bannerPublicId}`로 둡니다.
   - 두 경로 모두 DB에 저장된 주소로만 보냅니다(열린 리디렉트 방지). 숨김·차단·회수·정지·게시 끝이면 지금처럼 `link_unavailable` 안내 화면으로 보냅니다.
7. **운영자 API**
   - `OperatorCreatorDetail`에는 수가 아니라 다음이 필요합니다: `bannerSlot { granted; grantedAt }`, `banners`(보관 포함 목록, 숨김·차단·사유), `bannerMax`. `배너` 카드와 `배너는 n장까지` 문구에 씁니다.
8. **오류 코드**
   - 다시 쓰는 코드: `link_url_invalid`, `link_domain_blocked`. 웹 문구가 handoff와 같습니다(`errors.ts:23-24`).
   - 새 코드: `banner_not_found`, `banner_limit_reached`, `banner_slot_not_granted`, `ad_banner_not_found`, 게시 기간 오류(`banner_period_invalid`). 지금 `date_range_invalid`는 통계 기간용 문구입니다.
   - GIF 거부는 배너를 저장할 때 `files.content_type`(매직 바이트로 정한 값)을 보고 `file_type_unsupported`로 돌려줍니다. 업로드 경로 `POST /api/me/files`는 그대로 씁니다.
9. **상한 n**
   - `CRELINK_LIMITS` 상수가 아니라 `AppConfig` 환경변수(예: `BANNER_SLOT_MAX`, 처음 값 5)로 둡니다(`apps/api/src/config.service.ts`). `apps/api/docs/README.md#환경변수`에도 적습니다.
   - 웹은 응답의 `bannerLimits.max`만 씁니다.
   - 값을 지금 장수보다 낮추면 있는 배너는 그대로 두고 추가만 막습니다.
10. **노출·클릭 기록 방식**
    - 지금 가정(서버 렌더와 클라이언트 비콘 중 미정)을 아래처럼 정리합니다.
    - **노출(AI 제안)**: 공개 랜딩 API가 `passAccepted === true`일 때만(`public-landing.controller.ts:75`), 슬롯이 보이면 첫 장 배너 1건을 백그라운드로 기록합니다.
      - 이렇게 하면 R7 ⑥이 저절로 지켜집니다. 서비스 화면에서 연 랜딩은 같은 출처 요청이라 통과 표시가 없고(`apps/web/src/app/(public)/p/[publicId]/page.tsx:34-49`), 관리 화면 미리보기는 공개 API를 부르지 않습니다.
      - 새 공개 쓰기 엔드포인트도 필요 없습니다. 통과 표시는 60초 안에서만 유효합니다(`landing-pass.service.ts:5`).
      - 한계: 이 호출은 웹 서버가 하므로 방문자 쿠키·IP가 없습니다(`apps/web/src/lib/api/server.ts:40-50`, `cl_vid`는 단축 도메인 쿠키). 그래서 노출은 수(랜딩·배너·시각)만 남습니다.
      - 한계: "렌더"를 세므로 화면 아래에 있어 보지 못한 경우와 넘겨 본 장은 세지 않습니다. 미리보기 봇도 방문처럼 셉니다.
    - **클릭**: 링크 클릭은 지금 어디서 연 랜딩이든 `/c/`로 셉니다(`short-link.controller.ts:57-89`).
      - R20 ⑧을 지키려면 API가 `passAccepted`일 때만 기록 주소를 주고, 아니면 저장된 주소를 그대로 줍니다.
      - 그 대가로, 로그인하고 돌아온 방문자처럼 같은 출처에서 다시 그린 경우에는 덜 셉니다.
    - **비콘 방식(장마다·실제로 본 것)**은 다음이 모두 필요해 비용이 큽니다: BFF 공개 POST, 서버가 서명한 노출 토큰(통과 표시와 묶기), 본 도메인 방문자 쿠키, 남용 방지.

### 결정 5개에 대한 기술 의견

1. **배너 비율**
   - 세 선택지 모두 구현 비용이 같습니다. CSS `aspect-ratio`와 `object-fit`만 바뀌고, 이미지는 잘라 채우므로 나중에 바꿔도 migration이 필요 없습니다.
   - 공개 랜딩·관리 미리보기·운영자 미리보기가 같은 값을 쓰도록 비율을 `packages/shared` 상수 하나로 둡니다.
   - 2:1·16:9는 휴대폰 첫 화면에서 차지하는 높이(LCP 후보)가 커집니다. 기술 쪽에서는 3:1에 이견이 없습니다.
2. **한도 n이 세는 것**
   - **전체 장수(추천과 같음)가 훨씬 단순합니다.** 행 수 하나만 검사하면 됩니다.
   - 보이는 배너만 세면 더 필요한 것이 많습니다: 숨김을 풀 때 한도 검사, 409가 나면 스위치 되돌리기(링크 `toggleHidden`과 같은 흐름), 숨긴 배너의 별도 상한(링크의 `totalLinks: 50`처럼), 오류 코드 2개.
   - 회수 뒤 보관된 배너도 전체 수에 들어간다는 점을 handoff에 적어 둡니다.
3. **GIF 배너**
   - **받지 않음(추천)**이 가장 쌉니다. 저장할 때 `files.content_type`을 확인하고, `ImageField`에 허용 형식 prop을 더하고, 문구를 하나 더하면 됩니다(A2).
   - 다만 움직이는 WebP와 APNG는 매직 바이트 검사를 통과합니다. 자동 움직임 금지를 끝까지 지키려면 다음 검사를 더해야 합니다(새 의존성 없이 수십 줄).
     - WebP: `VP8X` 애니메이션 플래그 또는 `ANIM` 청크
     - PNG: `acTL` 청크
   - 첫 장면만 정지 이미지로 보여 주려면 둘 중 하나가 필요합니다.
     - 서버 변환: `sharp` 같은 새 의존성, CPU 사용, ADR·infra 검토
     - 브라우저 캔버스 변환: 의존성은 없지만, PNG로 바꾸면 4MB를 넘길 수 있고 운영자 화면에도 같은 처리가 필요합니다.
   - 받으면 비용은 없지만 DESIGN.md의 `반복 애니메이션 없음`과 부딪칩니다.
4. **광고 배너 순서와 첫 장**
   - **게시 시작이 이른 순(추천)**은 `ORDER BY starts_at, created_at` 한 줄이고, 시험도 결정적입니다.
   - 방문마다 첫 장을 바꾸는 것도 서버가 정하면 비용이 크지 않습니다. 노출을 "첫 장" 기준으로 세는 방식(계약 수정 10)에서는 오히려 배너별 노출이 고르게 됩니다. 다만 시험·재현이 어렵고 기록 해석을 문서로 남겨야 합니다.
   - 운영자가 순서를 정하려면 `sort_order` 컬럼, 정렬 API, 운영자 표 끌기 UI가 더 필요합니다.
   - 이른 순으로 시작하고, 순환은 나중에 서버만 고쳐 더할 수 있습니다.
5. **크리에이터 배너 차단**
   - **배너마다 차단(추천)**을 권합니다. 링크 차단(`PUT /api/admin/links/{id}/block`, `admin.service.ts:156-172`)을 그대로 따라 엔드포인트 하나와 카드 UI만 더하면 됩니다.
   - `blocked_at`·`blocked_reason` 컬럼은 차단 도메인을 나중에 추가할 때 기존 배너를 막는 데(B8) 어차피 필요합니다.
   - "자동 검사만"으로 가도 저장 이후에 추가된 차단 도메인을 반영해야 합니다. 그러려면 같은 컬럼이 필요하거나, 공개 랜딩을 그릴 때마다 `blocked_domains`와 호스트를 비교하는 조회가 필요합니다. 그래서 비용 차이가 작습니다.
