# 지표·통계 화면 인계

- 기준: [기존 스튜디오 라이트](../system/DESIGN.md), [기술 설계](../../docs/specs/crelink-analytics.md), [PRD R10·R28](../../docs/product/crelink.md).
- 방식: 기존 제품의 ManagerShell·AdminShell·카드·표·날짜 폼을 확장한다. OpenDesign 신규 생성이나 별도 디자인 시스템을 만들지 않았다. 이 문서는 구현 배치와 상태를 설명하며 실제 UI 확인 결과는 통합0188에 남긴다.

## 정보 구조

크리에이터 관리 메뉴의 주소 설정 앞에 지표·통계를 넣는다. 해당 메뉴에서는 편집 전용 휴대폰 미리보기와 편집/미리보기 토글 대신 본문 폭을 사용한다. 관리자 메뉴에도 지표·통계를 두고 기존 크리에이터 목록·상세와 연결한다. 네 화면의 h1은 지표 또는 통계이며 소유 범위·선택 기간을 바로 아래에 표시한다.

지표는 기간 폼→핵심 카드→열람/클릭 추이→상세 통계 이동 순서다. 통계는 같은 필터→일별 수치→대상별 성과→스크롤 도달→유입/캠페인·지역·기기/환경 분포 순서다. 긴 세부 분포는 제목이 명확한 details/summary로 접을 수 있다. 실제 값만 표시하며 예시 값을 실제 성과로 넣지 않는다.

관리자만 계정 검색·선택과 시험 계정 포함을 제공한다. UUID를 입력하게 하지 않는다. 기존 운영 목표 카드는 분석 기간과 다른 시간 기준을 명시해 별도 영역에 둔다.

## 시각·반응형

배경은 --ds-color-background-stage, 카드는 --ds-color-surface-default, 경계는 --ds-color-border-default, 본문은 --ds-color-text-primary·secondary. 색·간격·크기·모서리는 기존 --ds-* 토큰만 쓴다. 새 토큰은 필요하지 않다. 숫자는 기존 숫자 정렬과 단위를 쓰고, 주요 행동은 기간 적용 한 곳으로 제한한다.

1280px에서는 관리 메뉴 옆 최대1060px 본문 안에서 카드와 분포를 여러 열로 둔다. 390px에서는 메뉴가 내부 가로 스크롤을 하고 필터는 줄바꿈, 카드는 두 열/한 열, 분포는 한 열로 접는다. 넓은 표는 table-scroll 안에서만 스크롤하고 본문 폭을 넘기지 않는다. 실제 두 폭에서 확인한 결과를 검증 기록에 남긴다.

## 상태·의미

0은 관측된 건수가 없는 경우, 미수집/계산 불가는 null인 경우로 구분한다. 수집 이전·과거 요약자료의 한계를 설명하고 정확한 순 방문자와 일별 합산 고유 수를 같은 이름으로 표시하지 않는다. 서버 방문·302 클릭은 브라우저 열람·클릭과 다른 영역에 둔다. 분포 미상은 알 수 없음, 잘린 나머지는 기타, 삭제 대상은 삭제된 항목으로 쓴다. 제품 문구에 raw/rollup/SQL 같은 구현 용어를 넣지 않는다.

로딩에는 진행 상태, 오류에는 읽기 실패 이유와 다시 시도/기간 수정, 권한 없음에는 적절한 복귀 링크를 둔다. 빈 기간에 가짜 차트를 그리지 않는다.

## 접근성·기술 검토

이동은 링크와 aria-current, 기간 폼은 label·날짜 입력·submit, 표는 caption/th scope를 사용한다. 차트는 같은 수치의 표 또는 상세 경로와 요약을 제공하고 색만으로 계열을 구분하지 않는다. 초점 링과44px 조작 높이를 유지한다. 의미 없는 애니메이션·새 차트 의존성은 없다.

API/웹 검토: 서버 컴포넌트로 조회하고 기존 세션/BFF를 재사용한다. 공용 AnalyticsReport를 두 화면이 나누어 쓰므로 API를 네 개로 중복하지 않는다. 공개 랜딩의 방문자 수집기는 관리 화면에 마운트하지 않는다.
