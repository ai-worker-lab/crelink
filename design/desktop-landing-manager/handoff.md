# PC 랜딩 관리 화면 인계

크리에이터 관리 화면 두 곳(`/me`, `/me/landings/{publicId}`)을 한 화면 틀로 모으고, PC에서는 왼쪽 메뉴·가운데 관리 패널·오른쪽 휴대폰 미리보기로, 휴대폰에서는 한 열 패널과 전체 화면 미리보기로 쓰는 시안입니다. 상태: **사용자 승인**(2026-10-08). 결정은 [사용자 결정](#사용자-결정), 구현 기준 요구는 [PRD R18](../../docs/product/crelink.md#요구사항)입니다.

## 정보 구조

```text
헤더: 크리링 · [운영자 화면](운영자만) · 공개 페이지 열기(새 창) · 로그아웃
├─ 메뉴(랜딩 단위)      ├─ 관리 패널                                  └─ 미리보기(방문자 화면)
│  페이지 편집(기본)    │  내 페이지 머리 카드(모든 메뉴 공통)
│  방명록              │    사진(R17)·표시 이름·단축 주소+복사·주소 변경
│  주소 설정           │  메뉴별 내용
```

| 메뉴 | 내용 | 지금 화면에서 온 것 |
| --- | --- | --- |
| 페이지 편집 | 공개 랜딩에 보이는 순서대로 카드: 프로필 → SNS 채널 → 링크 → 포트폴리오 → 방명록 켜기 | `/me`의 프로필·SNS·포트폴리오, `/me/landings/{publicId}` 편집 모드의 링크 편집·방명록 스위치 |
| 방명록 | 방명록 켜기 스위치, 글 목록(공개·비밀글·숨긴 글 표시), 글마다 숨기기·숨김 해제, 더 보기 | 보기 모드 방명록 탭의 크리에이터 숨기기(`GuestbookPanel`의 `isOwner`) |
| 주소 설정 | 내 크리링 링크(복사), 주소 바꾸기(R8 규칙·입력 중 확인·30일 제한), 계정(구글 이메일) | `/me`의 `ShortLinkSection`, 페이지 부제목의 이메일 |

- 카드 순서는 고정입니다. 공개 랜딩의 구역 순서(R5 리스트형 구역 1개, R12 항목)를 그대로 따르고, 끌어 정렬하는 것은 링크 구역 안 링크뿐입니다(포트폴리오는 지금처럼 위로·아래로 버튼).
- 머리 카드에 방문 수·통계를 두지 않습니다(R10). 인포크 머리의 `통계`·`디자인` 버튼 자리는 두지 않고, 그 기능은 생길 때 메뉴로 더합니다([확장 지점](#확장-지점)).
- 머리 카드의 `주소 변경`은 `주소 설정` 메뉴로 옮기고 새 주소 입력에 초점을 둡니다(대화상자를 따로 두지 않음: 30일 제한·확인 문구가 길어 한 곳에서만 관리).

### 주소 제안

| 화면 | 제안 주소 | 지금 |
| --- | --- | --- |
| 페이지 편집 | `/me/landings/{publicId}` | 같은 주소(편집 모드) |
| 방명록 | `/me/landings/{publicId}/guestbook` | 없음(보기 모드 방명록 탭) |
| 주소 설정 | `/me/landings/{publicId}/settings` | `/me`의 주소 카드 |
| `/me` | 내 랜딩(MVP는 1개)의 페이지 편집으로 이동 | 프로필·SNS·포트폴리오 편집 화면 |
| `/me/landings/{publicId}?mode=view` | 페이지 편집으로 이동(보기 모드는 미리보기가 대신함) | 보기 모드 |

메뉴를 랜딩 아래 경로로 두는 이유: R6(유료 단축 주소 n개 = 랜딩 n개)이 오면 메뉴 내용은 랜딩마다 다르고, 계정 단위 기능(로그아웃·계정)은 헤더에 남습니다. 이 주소 체계는 2026-10-08 사용자가 정했습니다([사용자 결정](#사용자-결정) 2번).

### 저장 방식(지금 코드와 같음)

| 영역 | 저장 | API |
| --- | --- | --- |
| 프로필(사진·이름 40자·소개 300자) | `프로필 저장` 버튼 | `PATCH /api/me/landing` |
| SNS 채널(최대 10) | `SNS 채널 저장` 버튼(전체 교체) | `PUT /api/me/socials` |
| 링크 추가·수정·삭제 | 폼의 `저장`·`삭제`(삭제는 확인 대화상자) | `POST /api/me/links`, `PATCH`·`DELETE /api/me/links/{id}` |
| 링크 순서 | 놓는 즉시 | `PUT /api/me/links/order` |
| 링크 숨기기 | 스위치 즉시 | `PATCH /api/me/links/{id} { hidden }` |
| 포트폴리오(최대 20) | 폼 `저장`, 위로·아래로 즉시, 삭제 확인 | `/api/me/portfolio`, `/{id}`, `/order` |
| 방명록 켜기 | 스위치 즉시 | `PATCH /api/me/landing { guestbookEnabled }` |
| 방명록 글 숨기기 | 버튼 즉시 | `PUT /api/guestbook/{id}/hidden` |
| 주소 바꾸기 | `주소 바꾸기` 버튼 | `GET /api/me/short-link/availability`, `PUT /api/me/short-link/slug` |

저장 방식을 한 가지(모두 즉시 저장 또는 모두 버튼)로 맞추는 것은 이번 시안에서 바꾸지 않았습니다. 바꾸려면 별도 결정입니다.

## 미리보기

- 내용은 공개 랜딩 `Landing`과 같은 구성 요소·모양이고, 데이터는 `toLandingPreview`(숨긴·차단 링크 제외)에 **저장하지 않은 입력(초안)을 덮어쓴 값**입니다. 초안이 있으면 미리보기 머리에 `저장하지 않은 변경 포함` 칩을 둡니다. 새 링크 초안의 파비콘은 저장 전이라 서버 값이 없으므로 기본 아이콘(또는 입력 주소의 호스트로 만든 값)을 씁니다.
- 미리보기 안 링크·SNS·포트폴리오는 이동하지 않습니다(누름 무시). 탭 전환과 스크롤만 됩니다. 공개 페이지 확인은 헤더의 `공개 페이지 열기`(새 창)입니다.
- 탭 상태는 미리보기 안에서만 바뀝니다. 지금 `LandingTabs`는 주소 해시(`#guestbook`)가 원본이므로, 미리보기에서는 관리 화면 주소를 바꾸지 않는 제어형 탭이 필요합니다.
- `방명록` 메뉴에 들어가면 미리보기가 방명록 탭을 엽니다. 방문자 기준이므로 비밀글·숨긴 글을 빼고 공개글만, 작성 자리에는 비회원 안내(`방명록은 로그인한 회원만 남길 수 있어요.` + `로그인하고 남기기` 비활성 모양)를 보여 줍니다. 목록 API는 크리에이터에게 모든 글을 `secret`·`hidden` 표시와 함께 주므로 브라우저에서 걸러 그립니다.
- 1280px: 오른쪽 열 `position: sticky`(헤더 아래 24px), 휴대폰 프레임 안쪽 폭 360, 높이 `min(760px, 화면 높이 − 헤더 − 여백)`, 프레임 안만 스크롤. 프레임 테두리 `--ds-color-background-device`, 화면 `--ds-color-background-screen`.

| 폭 | 배치 |
| --- | --- |
| 1200px 이상 | 헤더 / 왼쪽 메뉴(약 200) · 관리 패널(최대 약 600) · 미리보기(약 384, sticky) 3단 |

## 상호작용·접근성

- **링크 추가·수정(PC)**: 대화상자가 아니라 패널 안 펼침 편집입니다. `수정`을 누르면 그 행 바로 아래에 폼이 펼쳐지고(행과 폼이 한 카드 테두리, 행의 `수정`은 `접기`로 바뀜) `링크 추가`는 목록 끝에 `새 링크` 폼을 엽니다(열린 동안 `링크 추가` 버튼은 숨김). 한 번에 하나만 열리고, 열린 동안 끌기를 막습니다. 입력은 미리보기에 바로 반영되고 `저장 안 함`·`저장하지 않은 변경 포함` 칩이 붙습니다. 근거: 가운데 대화상자는 덮개가 미리보기를 가려 입력이 미리보기에 바로 반영되는 것을 볼 수 없고, 오른쪽 미리보기를 가리지 않는 것이 이 화면의 목적입니다. 포트폴리오가 이미 패널 안 펼침 폼을 쓰므로 같은 패턴입니다(리틀리 블록 카드 펼침과도 같음).
- **링크 추가·수정(1023px 이하)**: 지금 `LinkSheet` 하단 시트(`<dialog>` `showModal`, 바깥 비활성, 표시 이름에 초점, Esc·배경·`닫기`로 닫힘, 저장 중 Esc 무시) 그대로입니다(R18 ②). 같은 폼 구성 요소를 폭에 따라 펼침/시트로 감쌉니다.
- 폼 필드: 표시 이름(필수, 60자), 주소(필수, `http://`·`https://`), 설명(120자), 썸네일. 닫히면 연 버튼으로, 지워졌으면 링크 구역 제목으로 초점을 돌립니다(지금 동작).
- **순서**: 손잡이를 마우스·터치로 끌거나, 손잡이에서 Space/Enter로 든 뒤 ↑↓, Space/Enter로 놓기, Esc 취소. 스크린리더 안내 문구는 지금 `LandingEditor`의 `announcements`·`SCREEN_READER_INSTRUCTIONS`를 그대로 씁니다(`@dnd-kit` 유지).
- **스위치**: 링크 숨기기·방명록 켜기는 `role="switch"` 버튼, 켜진 면 `--ds-color-text-primary`, 저장 중에는 `aria-disabled`로 누르기만 무시(초점 유지).
- **메뉴**: 세로 메뉴·가로 탭 모두 `<nav aria-label="관리 메뉴">` 안 링크, 현재 항목 `aria-current="page"`. 메뉴는 주소가 바뀌는 이동이므로 탭 위젯(`role="tablist"`)으로 만들지 않습니다.
- **복사**: 누르면 버튼 글자가 1.5초 `복사했어요`로 바뀌고 `aria-live`로 알립니다(`CopyButton`).
- **미리보기 대화상자(1023px 이하)**: `<dialog>` 전체 화면, 제목 `미리보기`, 닫으면 `미리보기` 버튼으로 초점 복귀.
- 초점 링 3px `--ds-color-text-primary`, offset 2px. 누를 수 있는 요소 44px 이상. 상태는 색과 함께 글자(`숨김`, `차단됨`, `비밀글`, 오류 문장)로 알립니다. 모션 150~200ms, `prefers-reduced-motion: reduce`에서 끕니다.
- 강조색 버튼은 페이지 편집에서 `프로필 저장` 하나, 펼침 폼이 열리면 그 폼의 `저장`입니다. 나머지(`링크 추가`, `SNS 채널 저장`, `주소 바꾸기` 등)는 보조 버튼입니다.

## 확장 지점

- 메뉴 항목 = 랜딩 아래 경로 한 개(`/me/landings/{publicId}/<메뉴>`). 새 기능은 카드나 머리 카드 버튼이 아니라 메뉴 항목으로 더합니다. 순서는 자주 쓰는 순: 페이지 편집 → (디자인) → 방명록 → (문의) → (통계) → 주소 설정. 설정류는 항상 맨 끝입니다.
- 벤치마킹 기능이 들어갈 자리:
  - **디자인**(테마·버튼 모양, PRD R5 이후 버전): `페이지 편집` 바로 아래 메뉴. 미리보기가 그대로 쓰이는 화면입니다.
  - **문의**(인링크 `문의` 탭): 방명록 아래 메뉴.
  - **통계**(PRD R10이 크리에이터 공개를 정하면): 주소 설정 위 메뉴. 머리 카드에 방문 수를 다시 넣지 않습니다.
  - **블록 추가·표시 종류**(R5 이후): 페이지 편집의 링크 카드가 `구역` 목록이 되고 구역 사이에 추가 버튼이 생깁니다. 카드 순서 고정 규칙은 그때 다시 정합니다.
  - **여러 랜딩**(R6 유료): 머리 카드 위에 랜딩 전환(선택 상자)이 들어가고 메뉴 주소의 `{publicId}`가 바뀝니다.
- 메뉴가 7개를 넘으면 세로 메뉴를 묶음 제목(예: `페이지`, `소통`, `설정`)으로 나누고, 휴대폰 가로 탭은 가로 스크롤을 유지합니다.
- 지금 없는 메뉴를 "준비 중" 자리표시로 미리 그리지 않습니다.

SNS 플랫폼 변경 시 미리보기 아이콘·초안 칩 반영. 링크 추가 펼침 폼(표시 이름에 초점, 입력 즉시 미리보기 카드, 저장 → `'경품 이벤트' 링크를 추가했어요.`, 배지 4/5), bit.ly 주소 저장 시 폼 안 `크리링 차단 목록에 있는 도메인이라 저장할 수 없어요.`, Esc 취소 뒤 `링크 추가`로 초점 복귀. `시안 상태`의 저장 실패 → `프로필 저장` 시 오류 줄+`다시 시도`. `주소 변경` → 주소 설정 메뉴·입력 초점, `haru` 사용 불가 문구(aria-live), `harufilm-trip` 사용 가능 → 바꾸기 → 머리 카드 주소 갱신·30일 제한 상태(입력 비활성). 방명록 메뉴 글 4개, 숨기기 결과 문구, 미리보기 방명록 탭은 공개글만.
  - 1100px: 시안은 3단을 좁혀 그림(가로 넘침 없음). 구현 기준은 [반응형](#반응형) 표.
  - 390px: 가로 탭 메뉴, 압축 머리 카드, 떠 있는 `미리보기` 버튼 → 전체 화면 미리보기(Esc로 닫히고 버튼으로 초점 복귀), 링크 `수정` → 하단 시트(표시 이름 초점, Esc로 닫힘), 빈 랜딩·한도 도달 상태. 가로 넘침 없음(`scrollWidth` 390).
  - 320px: 가로 넘침 없음(`scrollWidth` 320).
  - `states.html` 1280px: 상태 24개, 데스크톱 상태는 패널+미리보기 2열. 390px에서는 상태 보드 자체가 넘침(보드용 파일이라 의도된 것, 휴대폰 배치는 보드 안 390×844 기기 영역으로 확인).
