# crelink 디자인 시스템

> Category: Product

crelink 웹·앱이 함께 쓰는 시각·컴포넌트·반응형 규칙과 검수 기준입니다. 이 패키지는 OpenDesign에 가져와(`pnpm design:sync`) 모든 OpenDesign 산출물의 디자인 시스템으로 씁니다. 값의 원본은 `packages/design-tokens/src/tokens.json`이고, 같은 폴더의 `tokens.css`·`manifest.json`은 `pnpm tokens:generate`가 만듭니다. 앱 토큰 CSS 변수 이름의 접두사는 `tokens.json`의 `$cssPrefix`가 정하며, `pnpm design:check`가 이 문서의 토큰 이름을 원본과 대조합니다. 이 문서는 값 대신 쓰임새와 규칙을 설명합니다.

시각 방향은 **스튜디오 라이트**입니다(2026-10-07 사용자 확정, 시안 A). 크리에이터의 사진·이름·링크가 주인공이고 크리링의 색은 뒤로 물러납니다.

## 시각 테마와 분위기

- 차가운 흰 회색 바탕 위에 흰 카드를 띄운 밝은 화면입니다. 방문자는 대부분 휴대폰의 인스타그램 인앱 브라우저로 들어오므로, 처음 보는 사람도 어디를 누르면 되는지 바로 알아야 합니다.
- 강조색(산호빛 빨강)은 화면마다 주요 행동 한 곳, 많아도 두 곳에만 씁니다. 나머지 위계는 글자 굵기·크기·명도로 만듭니다. 공개 랜딩에서는 강조색을 거의 쓰지 않고 크리에이터 콘텐츠와 SNS 아이콘이 색을 맡습니다.
- 카드와 입력은 둥글고, 주요 버튼은 알약형입니다. 그림자는 카드가 바탕에서 살짝 뜰 정도로만 씁니다.

## 색 역할

| 역할 | 앱 토큰 | OpenDesign 슬롯 |
| --- | --- | --- |
| 페이지 바탕 | `--ds-color-background-stage` | `--bg` |
| 입력·화면 안쪽 바탕(흰색) | `--ds-color-background-screen` | — |
| 기기 테두리(목업 전용) | `--ds-color-background-device` | — |
| 카드·컨테이너(흰색) | `--ds-color-surface-default` | `--surface` |
| 선택 행·팝오버 같은 옅은 면 | `--ds-color-surface-raised` | `--surface-warm` |
| 머리글 막대 | `--ds-color-surface-bar` | — |
| 본문 글자 / 보조 / 흐린 글자 | `--ds-color-text-primary` / `-secondary` / `-subtle` | `--fg` / `--fg-2` / `--muted` |
| 카드 테두리 / 약한 구분선 | `--ds-color-border-default` / `--ds-color-border-frame` | `--border` / `--border-soft` |
| 입력·컨트롤 테두리 | `--ds-color-border-strong` | — |
| 주요 행동 / 눌림 / 옅은 배경 | `--ds-color-action-primary` / `-primary-pressed` / `-primary-subtle` | `--accent` / `--accent-active` |
| 강조색 위 글자 | `--ds-color-text-on-action` | `--accent-on` |
| 성공 / 경고 / 위험 | `--ds-color-status-positive` / `-warning` / `-danger` | `--success` / `--warn` / `--danger` |
| 덮개·그림자 | `--ds-color-overlay-scrim` / `-shadow` | — |

- 흰 카드(`--ds-color-surface-default`)는 페이지 바탕(`--ds-color-background-stage`) 위에 놓습니다. 카드 안의 입력도 흰색(`--ds-color-background-screen`)이며 `--ds-color-border-strong` 테두리로 구분합니다(흰 바탕 대비 3:1 이상).
- 상태 색은 글자색과 테두리·옅은 배경(`*-subtle`)으로 씁니다. 위험 상태의 카드 테두리는 `--ds-color-border-danger`입니다.
- 강조색과 위험색은 둘 다 붉은 계열입니다. 위험색은 더 짙은 진홍이고, 위험은 항상 글자(“차단됨”, 오류 문장)와 함께 보여 줍니다. 강조색을 경고·오류 표시에 쓰지 않습니다.
- 장식선·스위치 손잡이처럼 글자가 아닌 흐린 요소는 `--ds-color-decoration-subtle`을 씁니다.

## 타이포그래피

- 글꼴은 `--ds-font-sans`(Pretendard 우선) 하나로 제목과 본문을 씁니다. 숫자·주소·코드는 `--ds-font-mono`입니다. 제품 도구 성격이 강하고 크리에이터 콘텐츠가 표현을 맡으므로 글꼴을 늘리지 않습니다.
- 크기는 `--ds-font-size-*` 스케일만 씁니다. 본문 15, 보조 13, 캡션 11~12, 소제목 18~22, 화면 제목 27~38, 첫 화면 대표 제목 64(작은 화면에서 38까지 줄임). 공개 랜딩의 크리에이터 이름은 22, 링크 카드 제목은 15 굵게입니다.
- 제목은 `--ds-font-weight-extrabold`, 강조 본문은 `--ds-font-weight-bold`, 나머지는 `--ds-font-weight-regular`입니다.
- 줄 간격은 본문 1.65, 제목 1.15이고 자간은 0입니다. 한국어 제목·본문은 어절 단위로 줄바꿈합니다(`word-break: keep-all`).

## 간격과 레이아웃

- 간격은 `--ds-space-*`(2·4·6·8·10·12·16·20·24·32·40·48)만 씁니다. 같은 묶음 안은 8~12, 묶음 사이는 16~24, 구획 사이는 32~48입니다.
- 내용 폭은 최대 1060px이고 좌우 여백은 데스크톱 32, 태블릿 24, 휴대폰 16입니다. 공개 랜딩 본문은 휴대폰 폭에 맞춘 한 열이며 넓은 화면에서도 가운데 좁은 단(최대 480px 안팎)으로 둡니다.
- 최소 폭 320px에서 가로 넘침이 없어야 합니다. 700px 이하에서는 한 열로 접습니다.
- 누를 수 있는 요소의 높이는 44px 이상입니다.

## 기기·OS·브라우저 대응

기존 토큰과 스튜디오 라이트를 적용하면서, 공통 컴포넌트가 좁은 화면·터치·브라우저 차이까지 처리하도록 설계합니다. 색과 간격의 일관성에 더해 입력 겹침·잘림·읽기 어려운 표·핵심 정보의 과도한 스크롤을 검수합니다. 아래 브라우저 기준은 웹 화면에 적용합니다.

### 반응형 배치와 정보 우선순위

- 화면 이름이나 특정 휴대폰 모델보다 사용 가능한 너비·콘텐츠 길이·입력 방식을 기준으로 배치를 정합니다. Grid/Flex의 자식과 입력이 부모보다 커지지 않도록 실제 외곽 크기를 확인합니다. 문서 전체의 가로 넘침을 숨기는 것만으로 겹침이나 카드 경계 넘침을 해결했다고 판정하지 않습니다.
- 모바일에서는 핵심 숫자·현재 상태·주요 행동이 설명보다 먼저 보이도록 합니다. 긴 집계 기준·보조 설명은 짧은 요약과 펼침으로 제공하되 수집 이전·자료 부족·계산 불가 같은 중요한 의미를 보존합니다.
- 주소창·하단 도구 막대·안전 영역·화면 회전·키보드로 줄어드는 가용 높이를 고려합니다. 고정 머리글·탭·하단 행동이 입력·초점·현재 읽는 정보를 가리지 않도록 합니다.
- 날짜 필터·탭·표·차트의 대응 규칙은 공통 컴포넌트에 적용합니다. 같은 컴포넌트를 쓰는 모든 페이지에서 함께 검증합니다.

### 입력과 조작

- 기본 날짜·선택 입력의 모양과 고유 크기는 OS·브라우저마다 다를 수 있습니다. 좁은 화면의 시작일·종료일은 한 열을 기본으로 하고, 두 열은 각 입력의 실제 최소 너비를 확보한 경우에만 씁니다. 입력끼리 겹치거나 카드 밖으로 나오는 상태는 허용하지 않습니다.
- `width`, `min-width`, `max-width` 선언만 확인하지 않고 native 입력의 값 영역·내부 여백·포커스·날짜 선택·검증 메시지를 목표 브라우저에서 확인합니다. 기본 입력을 사용하면 해당 OS의 선택 UI가 달라질 수 있음을 전제로 설계합니다.
- 입력 UI 자체의 일관성이 필요하면 접근성·터치·키보드·국제화를 지원하는 공통 컴포넌트 라이브러리(예: React Aria Components)를 검토하고 기존 토큰으로 스타일링합니다. 이 규칙은 특정 라이브러리의 설치나 Tailwind CSS로의 이관을 확정하지 않습니다.
- 빠른 기간 선택·날짜 열기·아이콘·탭도 44px 조작 높이를 지킵니다. hover 없이 터치로 사용할 수 있고 키보드 초점과 선택 상태가 보여야 합니다. 선택한 기간과 일치하는 프리셋은 시각 상태와 접근 가능한 상태를 함께 표시합니다.

### 표와 차트

- 날짜·시각·숫자처럼 한 값으로 읽어야 하는 칸은 불필요하게 분절하지 않고 필요한 너비를 확보합니다. 긴 제목·설명은 별도로 줄바꿈하며, 모든 칸에 같은 줄바꿈 규칙을 일괄 적용하지 않습니다.
- 넓은 표는 이름과 초점을 가진 내부 스크롤 영역에서만 가로 이동합니다. 모바일에서는 날짜·대상과 수치를 함께 비교할 수 있는지 확인하고 필요하면 기준 열 고정·요약 표시를 사용합니다.
- 긴 일별 표는 최근 자료를 먼저 찾을 수 있게 하고 접기·더보기·페이지 나누기로 다음 구간 접근을 보장합니다. 전체 조회 기간의 집계와 표에 현재 표시한 범위를 구분하며, 중요한 성과·유입 정보가 긴 표 뒤에 묻히지 않도록 합니다.
- 차트를 좁힐 때 축·날짜 글자를 함께 축소하지 않습니다. 모바일 차트 레이블은 화면에 실제 렌더된 크기로 최소 12px를 확보합니다. SVG 내부 글꼴 선언뿐 아니라 화면 변환 배율까지 확인하며, 필요하면 레이블을 차트 밖의 HTML로 배치합니다.

### 웹 검수와 완료 기준

| 구분 | 확인 범위 |
| --- | --- |
| 화면 크기 | 최소 320px 경계, 360px·390px 세로, 768px 태블릿, 1280px·1440px 데스크톱. 배치가 바뀌는 경계 전후와 모바일 가로 회전도 변경 범위에 맞춰 확인 |
| 브라우저 엔진 | Chromium·WebKit·Firefox에서 변경한 핵심 흐름 확인. 모바일 입력·레이아웃 변경은 Chromium과 WebKit의 모바일 조건 포함 |
| 조작·상태 | 날짜/선택 입력·조회·선택 상태·초점·터치·세로/표 가로 스크롤, 로딩·데이터·빈 상태·오류·복구 |
| 스크린샷 | 변경한 각 페이지의 데스크톱·모바일 첫 화면과 전체 페이지, 겹침·표·차트 같은 주요 구간. 같은 URL·기간·데이터 조건과 실제 viewport를 기록하고 원본을 직접 열어 검토 |
| 실물 증거 | 보고된 실물 결함은 해당 OS·브라우저에서 재확인. 기종·OS·브라우저/버전·확대 설정·확인 방법을 남기고 모르는 값은 미상으로 표시 |

- Playwright 등으로 엔진별 조작·크기·스크린샷 회귀를 검사하고, 시각·정보 우선순위는 사람이 읽을 수 있는 화면으로 함께 검수합니다. 기본 smoke 검사만으로 변경한 내부 페이지의 UI/UX까지 통과했다고 보고하지 않습니다.
- 기기 프리셋·모바일 크기·User-Agent 변경과 실제 iOS/Android 실행을 구분합니다. 데스크톱 WebKit 검사도 실물 Safari 확인과 같은 증거로 취급하지 않습니다. 사용자 실물 첨부에서 추가 결함이 보이면 검수 결과에 반영합니다.
- 실제 확인한 엔진·버전·OS·viewport·데이터 조건·원본 경로·문제·재검증 결과를 인계 문서나 작업 기록에 남깁니다. 실물 결함을 해당 환경에서 재확인하지 못하면 그 항목을 미검증으로 남기고, 전체 대응 완료라고 보고하지 않습니다.
- 구현·검사 명령과 현재 자동화 범위는 [검증 루프](../../docs/development/verification.md)를 따릅니다. 이 문서에 기준을 적은 것과 검사 자동화·제품 수정이 실제로 완료된 것은 구분합니다.

## 컴포넌트

- 모서리: 카드·링크 카드·빈 상태는 `--ds-corner-lg`, 입력·선택 상자·하단 시트 안 요소는 `--ds-corner-md`, 배지·작은 칩은 `--ds-corner-sm`, 주요 버튼·보조 버튼·모드 전환은 알약형 `--ds-corner-full`입니다. 프로필 사진은 원형입니다.
- 주요 버튼: 배경 `--ds-color-action-primary`, 글자 `--ds-color-text-on-action`, 굵기 extrabold, 높이 44~48, 안쪽 여백 12·20. 눌림·hover는 배경을 `--ds-color-action-primary-pressed`로 바꿉니다. 화면당 하나만 둡니다(예외는 아래 로그인 전 홈 소개의 같은 행동 반복뿐).
- 보조 버튼: 배경 `--ds-color-surface-default`, 1px 테두리 `--ds-color-border-default`, 글자 `--ds-color-text-primary`. hover는 테두리를 `--ds-color-text-primary`로 바꿉니다.
- 카드·링크 카드: 배경 `--ds-color-surface-default`, 1px 테두리 `--ds-color-border-default`, 옅은 그림자(`--ds-color-overlay-shadow`, OpenDesign `--elev-raised`), 안쪽 여백 12·14(링크 카드)·20(일반 카드). hover는 테두리를 `--ds-color-text-primary`로 바꾸고 글자색은 바꾸지 않습니다.
- 링크 관리 편집 행: 카드와 같은 면에 끌기 손잡이(`--ds-color-text-subtle`), 제목·도메인, 숨기기 스위치를 둡니다. 숨긴 링크는 내용만 흐리게(불투명도 0.45) 하고 “숨김” 글자를 붙입니다. 켜진 스위치는 `--ds-color-text-primary` 면입니다(강조색을 쓰지 않음).
- 하단 시트·대화상자: 배경 `--ds-color-surface-default`, 위쪽 모서리 `--ds-corner-lg`, 덮개 `--ds-color-overlay-scrim`.
- 상태 배지: 1px 테두리와 글자를 상태 색으로, 배경은 `*-subtle`로 둡니다.
- 모든 화면은 로딩·성공(데이터 있음)·빈 상태·오류 상태를 함께 설계합니다. 오류에는 다시 시도할 수 있는 행동을 둡니다.
- SNS 브랜드 아이콘(인스타그램·유튜브 등)은 디자인 시스템 적용 제외입니다. 공식 파일을 원본 색·모양 그대로 쓰고 토큰·테마·모서리·필터를 걸지 않습니다(`apps/web/docs/sns-icons.md`).
- 광고 블록(R20)·배너 슬롯(R21): 공개 랜딩 링크 목록 안의 한 항목으로, 링크 카드와 같은 폭·같은 간격의 흰 카드(`--ds-color-surface-default`, 1px `--ds-color-border-default`, `--ds-corner-lg`, 안쪽 여백 8) 안에 3:1 배너 이미지(`--ds-corner-md`, 가운데 기준 잘라 채움)를 둡니다. 배너가 여러 장이면 이미지 아래 44px 조작 줄에 위치 표시(`2 / 3`)와 이전·다음 44px 원형 버튼을 두고, 손가락 스와이프·버튼·←/→ 키로만 넘깁니다(자동 넘김 없음, 처음·끝에서 멈춤). 광고 블록은 조작 줄 왼쪽에 `광고` 배지(1px `--ds-color-border-strong`, `--ds-color-text-secondary` 글자, `--ds-corner-sm`)를 늘 보이고, 배너가 1장이어도 이 배지 줄은 남깁니다. 배너 슬롯은 같은 틀에서 `광고` 배지만 빼고, 1장이면 조작 줄도 없습니다.
- 로그인 전 홈 소개(`/`): 첫 화면(제목·설명·`구글로 시작하기`) → 예시 랜딩 → 사용 3단계 → 무료로 쓸 수 있는 것 → 마지막 `구글로 시작하기` 순서의 한 화면입니다. 긴 소개 화면이라 같은 행동의 주요 버튼을 첫 화면과 맨 끝 두 곳에 둘 수 있고(한 화면 높이에 함께 보이지 않게), 다른 주요 버튼은 두지 않습니다. 예시 랜딩은 가상의 크리에이터로 휴대폰 틀(`--ds-color-background-device`) 안에 그리고 `예시 화면` 표시를 늘 보이며, 누를 수 없게 둡니다. 실제 크리에이터의 이름·사진·링크, 가짜 사용자 수·후기, 다른 서비스와의 비교는 넣지 않고, 무료 범위 숫자는 공유 상수에서 가져옵니다.

## 상태와 접근성

- 키보드 초점은 요소 바깥 3px 실선 링이며 색은 `--ds-color-text-primary`, 간격(`outline-offset`) 2px입니다. 강조색 버튼 위에서도 보이도록 강조색 대신 본문 글자색을 씁니다.
- 비활성은 불투명도 0.48과 `not-allowed` 커서입니다.
- 일반 글자 대비 4.5:1, 큰 글자 3:1 이상을 실제 배경 쌍에서 확인합니다. 현재 값에서 흐린 글자는 페이지 바탕 위 5.6:1, 상태 색 글자는 흰 카드 위 5:1 이상입니다.
- 색만으로 상태를 전달하지 않고 글자·아이콘을 함께 둡니다.

## 모션

- 상태 변화는 150~200ms, `cubic-bezier(0.23, 1, 0.32, 1)`입니다. 들어올 때 `ease-in`을 쓰지 않습니다.
- `prefers-reduced-motion: reduce`에서는 애니메이션과 전환을 사실상 끕니다.
- 장식용 반복 애니메이션은 두지 않습니다. 예외는 크리에이터·운영자가 올린 배너 이미지(GIF 등) 안의 움직임뿐입니다(2026-10-09 사용자 결정). 광고 블록·배너 슬롯의 틀과 넘기기는 움직이지 않습니다.

## 하지 말 것

- `tokens.css`의 `:root` 밖에서 색 리터럴(hex, `rgb()`, `hsl()` 등)을 쓰지 않습니다. 새 색이 필요하면 `tokens.json`에 쓰임새 이름으로 추가합니다.
- 계단형(픽셀) 모서리(`clip-path` 다각형)를 쓰지 않습니다. 모서리는 `border-radius`와 `--ds-corner-*`로만 만듭니다.
- 그라디언트 배경, 보라·남색 계열 강조색, 짙은 그림자, 강조색을 넓은 면(배경 전체·카드 전체)에 칠하는 것을 하지 않습니다.
- 크리에이터 콘텐츠 영역(공개 랜딩)에 크리링 장식을 더하지 않습니다. 예외는 아래쪽 크리링 표시 줄(바닥글)과 링크 목록 안의 광고 블록 하나(R20)뿐입니다. 크리링 표시 줄은 한 줄 글자 링크 `나도 크리링 만들기`(크리링 홈 `/`, `크리링`만 16px 굵게, 나머지 14px)와 `개인정보 처리방침`만 두는 작은 줄이며, 활성화 실험(0164)에서는 같은 구조·주소·굵기 규칙 안에서 결과 행동을 설명하는 `나도 크리링 만들고 첫 링크 추가하기` 변형을 쓸 수 있습니다. 강조색·로고 이미지·배지 면·아이콘·움직임은 넣지 않습니다. 배너 슬롯(R21) 계정도 같은 줄이고, 랜딩 오류 화면(404·410·불러오기 실패)은 가입 유도 없이 `크리링` 글자 링크만 둡니다. 광고 블록은 이미지가 먼저인 3:1 면과 늘 보이는 `광고` 배지로 글자 줄인 링크 카드와 구별하고, 틀에는 크리링 로고·강조색·장식을 넣지 않습니다(크리링 것은 배너 이미지 내용뿐). 광고 블록은 프로필 머리 위·바닥글 옆이나 링크 목록 밖에 두지 않고, 크리링 표시 줄을 대신하거나 없애지도 않습니다.
- 자리표시 문구(lorem ipsum)나 임의 이미지를 넣지 않습니다. 실제 화면 문구와 상태를 씁니다.
- 디자인 도구 내부 파일을 웹·앱 런타임에서 불러오는 구조를 전제로 그리지 않습니다.

## 산출물 작성 규칙(OpenDesign 에이전트용)

- 산출물 CSS는 `var(--ds-*)`를 우선 씁니다. 웹·앱 구현이 같은 이름을 쓰므로 그대로 옮길 수 있습니다. OpenDesign 템플릿이 쓰는 공통 슬롯(`--bg`, `--accent` 등)은 같은 값을 가리킵니다.
- 산출물 첫 `<style>`에 `tokens.css`의 `:root` 블록을 그대로 붙입니다. 저장소 `design/<기능>/`에 옮길 때는 그 블록을 `<link rel="stylesheet" href="../system/tokens.css">`로 바꿉니다.
- 웹 산출물은 [기기·OS·브라우저 대응](#기기os브라우저-대응)의 페이지별 스크린샷·조작·엔진 검수 범위를 인계합니다. 정적 산출물에서 확인할 수 없는 native 입력과 실제 기기 검증은 구현 단계의 확인 항목으로 명시합니다. 모바일 앱 화면은 390×844를 기본으로 하며 실제 기기별 가용 영역도 확인합니다.
