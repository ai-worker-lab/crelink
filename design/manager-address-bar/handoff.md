# 관리 화면 주소 막대 입력형·프로필 메뉴·`주소 설정` 메뉴 제거 인계

관리 화면(`/me/landings/{publicId}`)의 주소 막대에서 주소를 바로 고치게 하고, 계정 정보를 머리글 프로필 메뉴로 옮기고, 할 일이 없어진 `주소 설정` 메뉴를 없애는 설계입니다. 상태: **구현 완료, 화면 실측 반영(CTO 교차 확인 반영, 사용자 확인 항목은 권장안 채택. [0234](../../docs/work/orchestrator/0234-address-bar-inline.md))**. 사용자 검토사항(2026-11-10, 화면 스크린샷 1장)을 UX/UI 담당이 평가하고, CTO 교차 확인 결과를 코드로 다시 확인해 고쳤습니다. 지적별 처리는 [검토 반영](#검토-반영)에 있습니다.

## 대상

- 작업: 0234(브랜치 `work/0234-address-bar-inline`). 티켓은 `역할: orchestrator`입니다(선례 [0058](../../docs/work/orchestrator/0058-preview-direct-edit.md)). `web` 역할이면 이 문서·E2E·PRD·기술 설계가 소유 경로 밖이 됩니다. 메뉴 제거와 대체 경로가 동시에 나가야 하므로 티켓 하나, PR 하나로 묶습니다.
- 제품 요구: [PRD R7·R8·R17·R18](../../docs/product/crelink.md#요구사항)
- 앞선 인계: [미리보기 직접 편집](../preview-direct-edit/handoff.md)(주소 막대의 원본), [PC 랜딩 관리 화면](../desktop-landing-manager/handoff.md)(상태·저장 방식의 원본). 이 문서는 달라지는 것만 적습니다.
- 코드: `apps/web/src/components/manage/AddressBar.tsx`·`SlugSheet.tsx`·`use-slug-change.ts`·`ProfileMenu.tsx`·`ManagerPreview.tsx`(`NarrowBar`), `components/CopyButton.tsx`, `lib/slug-change.ts`, `app/me/landings/[publicId]/layout.tsx`. 이 문서의 `지금 SlugSection`·`지금 코드`는 구현 전(`889b878`) 기준입니다.
- **OpenDesign 산출물을 만들지 않았습니다.** 새 화면이 아니라 이미 있는 막대·머리글의 작은 변경이라 이 문서로 충분하다고 판단했습니다. 그래서 `index.html`·프로젝트 id가 없고, 시각 확인은 구현 화면으로 합니다. 이 기기에는 로컬 OpenDesign이 없어 `pnpm design:check --require-lint`가 실패합니다(2026-11-10 실행, `od lint: 건너뜀`). **티켓에 예외 사유를 적고, 구현 화면의 1024·1280·390·320px 실측 스크린샷을 티켓 `진행 기록`에 남겨 대신합니다.**

## 제안별 판정

| 제안 | 사용자의 의도 | 판정 | 수정·조건 |
| --- | --- | --- | --- |
| 1. 복사를 아이콘으로, 주소 옆에 | 복사와 주소를 한 덩어리로 묶고 버튼 줄의 소음을 줄인다 | **그대로 진행** | 복사 결과·실패를 막대 아래 문장으로 보여 준다. 입력 중에는 아이콘을 뺀다. 1023px 이하도 같은 아이콘 |
| 2. `주소 변경`을 입력란으로 노출 | 주소를 고칠 수 있다는 것을 막대만 보고 알게 하고, 메뉴를 옮기지 않고 고친다 | **수정해서 진행** | 입력란은 상시 노출. 저장은 `변경` → 확인 대화상자 두 단계. 잠금 중에는 입력란을 없앤다. 1023px 이하는 하단 시트 |
| 3. 로그아웃을 프로필 드롭다운으로, 이메일도 그 안에 | 계정 정보를 머리글 한 곳에 모으고 머리글을 비운다 | **그대로 진행** | 범위는 관리 화면만. 프로필 사진은 저장값을 실시간으로 |
| 4. `주소 설정` 사이드 제거 | 내용이 다른 곳으로 옮겨지면 메뉴가 필요 없다 | **수정해서 진행** | 왼쪽 메뉴·오른쪽 패널·경로를 같이 없애되 1~3과 **같은 변경**에서. 옛 주소 이동, 좁은 화면 경로, 인스타그램 안내 자리, 문서 수정 필요 |

### 사용자 확인이 필요한 것

사용자 제안에 없던 것을 설계에 넣었거나 제품 요구를 바꾸는 항목입니다.

| 항목 | 권장 | 이유 |
| --- | --- | --- |
| 저장 2단계(`변경` → 확인 대화상자) | 유지 | 저장하면 30일 동안 되돌릴 수 없고 오타도 그대로 30일을 씁니다 |
| 잠금 중 입력란을 없애고 `12월 10일부터 변경 가능` 글자로 대신 | 유지 | R8 ③이 다음 변경 가능일 표시를 요구하고, 비활성 입력은 핵심 주소를 흐리게 합니다 |
| PRD R18 ⑦에서 `주소 설정` 메뉴 제거 | 사용자 검토사항 4가 근거. 최종 문구를 보고 | 요구 확정은 사용자가 결정합니다(`AGENTS.md`) |

### 제안 1이 만드는 문제

- 복사는 이 막대에서 가장 자주 쓰는 행동입니다(시작 안내 ②). 글자를 아이콘으로 바꾸면 처음 보는 사람에게는 덜 분명합니다. 시작 안내 카드의 글자 `복사` 버튼이 그대로 남아 첫 동선은 유지되고, 아이콘에 `title`을 줍니다.
- 지금 막대는 `.address-bar .copy-feedback`을 화면에서 숨기고(`styles.css`), 복사 실패 시 버튼 글자가 그대로 `복사`입니다. 실패가 눈에 보이지 않는 **지금 결함**입니다. 아이콘으로 바꾸면 전달 수단이 더 줄어드므로 결과 문장을 화면에 보여 줍니다.

### 제안 2가 만드는 문제

- 주소는 인스타그램 프로필에 이미 붙어 있을 수 있는 공개 자산입니다. 저장하면 **30일 동안 되돌릴 수 없고**(자동 발급 주소의 첫 변경도 그 뒤 30일 잠김), 옛 주소는 90일 뒤 끊깁니다. 오타를 저장하면 그 오타로 30일을 씁니다. 다른 입력처럼 가볍게 보이면 안 됩니다.
- 다만 입력란을 건드리는 것만으로는 서버 상태가 바뀌지 않습니다. **위험은 노출이 아니라 저장 순간에 있습니다.** 그래서 노출은 사용자 제안 그대로 두고 저장에 단계를 더합니다.
- 입력 중에는 보이는 주소와 저장된 주소가 달라집니다. 이때 복사가 살아 있으면 고치던 값이 복사된다고 믿고 옛 주소를 붙여 넣게 됩니다.
- 막대는 높이 60px로 고정이고(`.preview-screen` 높이 계산이 184px를 씀), 1024px에서는 폭이 약 432px로 줄어듭니다([폭 계산](#폭-계산)). 사용 가능 확인 문구가 들어갈 자리가 막대 안에 없습니다.
- 1023px 이하 막대(`NarrowBar`)에는 입력란을 둘 폭이 없습니다.

### 제안 3이 만드는 문제

- 로그아웃이 두 번 눌러야 하는 행동이 됩니다. 자주 쓰는 행동이 아니라 받아들입니다.
- 프로필 사진은 머리글 밖 `ManagerProvider`에 있습니다. 머리글은 서버 레이아웃이라 그대로 두면 사진을 바꿔도 머리글 사진이 새로고침 전까지 옛것으로 남습니다. [프로필 메뉴](#프로필-메뉴)의 구조 변경이 필요합니다.
- `GET /api/me`에는 사진이 없습니다(`SessionUser`는 `id`·`email`·`role`). `/admin`에 같은 메뉴를 쓰면 기본 아바타만 나옵니다. 범위를 관리 화면으로 둔 이유 중 하나입니다.

### 제안 4가 만드는 문제

- `사이드`는 왼쪽 메뉴 항목과 오른쪽 패널 둘 다로 읽었습니다. 패널만 없애면 메뉴를 눌러도 내용이 없어서 다른 해석은 성립하지 않습니다.
- 1023px 이하에서 주소를 바꾸는 길이 이 메뉴뿐입니다. 먼저 대체 경로가 있어야 합니다.
- 인스타그램 붙여넣기 안내(`인스타그램 프로필 편집 > 링크에 이 주소를 붙여 넣으세요.`)가 있던 곳이 사라집니다.
- PRD R18 수용 기준 ⑦이 `주소 설정` 메뉴를 적고 있습니다. 공개 문서 3곳도 메뉴 이름을 안내합니다.
- 지표·통계에는 주소 막대가 없습니다. 지금도 그 화면에서 주소를 바꾸려면 메뉴를 한 번 옮겨야 하므로 비용은 그대로입니다.

## 주소 막대(1024px 이상)

높이 60px, 폭 `min(100%, 600px)`는 그대로입니다.

```text
기본    go.shaul.kr/ [zbx9a07            ] [복사]            [공개 페이지 열기]
입력 중  go.shaul.kr/ [my-name            ]                  [취소] [변경]
잠금    go.shaul.kr/zbx9a07 [복사]      (자물쇠) 12월 10일부터 변경 가능 [공개 페이지 열기]
```

- 도메인 앞부분은 입력란 밖의 글자입니다. 고칠 수 있는 곳이 끝부분뿐임을 모양으로 보여 줍니다(지금 `SlugSection`과 같은 구성). 값은 `shortLink.url`에서 `shortLink.slug`를 뺀 나머지이고 `https://`는 뺍니다.
- 입력란은 **실제 `<input>`이고 저장된 slug가 채워져 있습니다.** 테두리 `--ds-color-border-strong`로 고칠 수 있는 칸임을 보여 줍니다. 초점을 받아도 전체 선택하지 않습니다(누른 글자 하나로 전체가 지워지지 않게). 브라우저는 Tab으로 들어오면 전체 선택하므로 `onKeyUp`의 Tab에서 커서를 끝으로 옮깁니다.
- 복사 아이콘은 입력란 바로 오른쪽(간격 `--ds-space-4`)입니다. 복사 아이콘은 `.address-actions` 밖으로 옮기고, `.address-actions`(잠금 글자·열기 또는 `취소`·`변경`)에 `margin-left: auto`를 줘 오른쪽에 붙입니다.
- 잠금 때도 복사 아이콘은 주소 바로 옆입니다. 지금 `.address-bar > .url-text`의 `flex: 1 1 auto`를 그대로 두면 주소 칸이 늘어나 아이콘이 밀리므로 `flex: 0 1 auto`로 바꿉니다.
- 1279px 이하에서 `공개 페이지 열기`는 아이콘만(`icon-only`, 지금 `NarrowBar`와 같음, 이름은 그대로), 잠금 글자는 `12월 10일부터`로 줄입니다(`변경 가능`은 시각적으로만 숨김).

- 넓은 화면 입력란은 저장값으로 채워져 있으므로, 값이 저장값과 같아지면 **`localReason`보다 먼저** `idle`로 돌립니다. 지금 `onInput` 순서대로 두면 `same_as_current`로 위험 테두리가 그려집니다. `same_as_current` 문구는 빈 입력에서 시작하는 좁은 화면 시트에서만 보입니다. 공용 hook에 저장값 시작 여부를 옵션으로 둡니다.
- 메시지 둘째 줄(입력란 초점·입력 중 내내 같음, `--ds-color-text-subtle`): 자동 발급이면 `자동 발급 주소는 지금 바로 바꿀 수 있어요. 그 뒤로는 30일에 한 번 바꿀 수 있어요.`, 아니면 `지금 바꿀 수 있어요. 바꾸면 30일 동안 다시 바꿀 수 없어요.`(지금 `SlugSection` 문구).
- 입력 규칙은 저장값 처리(위 항목)를 빼면 지금 `SlugSection`과 같습니다: `trim`·소문자화, `maxLength` 30, 400ms 멈춘 뒤 조회, 늦게 온 응답 버리기(`latest` 비교), `autoComplete="off"`·`autoCapitalize="none"`·`spellCheck={false}`.
- 빈 값 되돌림은 초점이 막대 밖으로 나갈 때만 합니다(`blur`의 `relatedTarget` 확인). `취소`에는 `onPointerDown`에서 `preventDefault()`를 줘 입력란 초점을 유지합니다. 그러지 않으면 누르는 순간 되돌림이 일어나 `취소`가 사라지고 초점을 잃습니다(Safari는 버튼을 눌러도 초점을 주지 않아 `relatedTarget`만으로 막히지 않습니다).
- 메뉴를 옮겨도 무대가 그대로면 입력값이 남습니다. 지표·통계로 가거나 폭이 1023px 이하로 줄어 막대가 사라지면 버려집니다. 주소 초안은 오래 살 이유가 없고 미리보기에 영향이 없어서 `dirty`·`저장하지 않은 변경 포함`에 넣지 않습니다.

### 실수 방지

1. 자동 저장 없음. 초점이 나가도, Enter만으로도 저장되지 않습니다.
2. `변경`을 누르면 **확인 대화상자**를 엽니다. 자동 발급 주소도 같습니다(그 뒤 30일 잠기므로 오타 위험은 같음).
3. 대화상자는 `EditSheet`를 재사용합니다(`<dialog showModal>`, 저장 중 닫힘 막음, 700px 초과는 가운데: `.ad-banner-dialog`와 같은 규칙으로 이름을 일반화). **첫 초점은 `취소`**입니다(`data-autofocus`). 입력란에서 Enter를 두 번 눌러도 저장되지 않게 합니다. 좁은 화면의 같은 보호는 [1023px 이하](#1023px-이하)의 시트 4번입니다. `data-autofocus`는 마운트 때 한 번만 실행되므로 시트처럼 본문을 바꾸는 흐름에서는 효과가 없습니다.
4. 내용: 제목, 지금 주소 → 새 주소(`--ds-font-mono`), 영향 3줄, 버튼. [문구 원문](#문구-원문).
5. `취소`·Esc·배경을 누르면 대화상자만 닫히고 입력값은 남으며 초점은 `변경`으로 돌아옵니다.
6. 막대의 `취소`·Esc는 입력값을 저장값으로 되돌립니다.

### 복사와 입력의 관계

- 복사하는 값은 언제나 `state.shortLink.url`입니다. 입력값을 넘기지 않습니다.
- 값이 저장값과 다른 동안 복사 아이콘과 `공개 페이지 열기`를 **그리지 않고** 그 자리에 `취소`·`변경`을 둡니다. 비활성으로 남기면 왜 안 되는지 알 수 없고, 1024px에서는 자리도 없습니다.
- 저장 성공으로 `shortLink.slug`가 바뀌면 입력 상태를 비웁니다.

**적용 범위: 관리 화면 머리글만**(`app/me/landings/[publicId]/layout.tsx`, 지표·통계 포함). 다른 세 곳의 `LogoutButton`은 그대로 둡니다.

**트리거**: 44×44 원형 버튼, 안에 36px 원형 사진. `state.landing.avatar`(저장값, 초안 아님)가 있으면 `RemoteImage`(`alt=""`), 없으면 `DefaultAvatar`. 테두리 1px `--ds-color-border-default`, hover `--ds-color-text-primary`. 이름 `계정 메뉴`.

| 순서 | 내용 | 비고 |
| --- | --- | --- |
| 1 | 이메일(글자, 누를 수 없음) | 14px `--ds-color-text-secondary`, `overflow-wrap: anywhere`, 안쪽 8·12. 아래 구분선 `--ds-color-border-default`. `me` 실패면 이 줄과 구분선을 그리지 않음 |

| 3 | `로그아웃`(버튼) | 왼쪽 정렬 행, 44px, hover `--ds-color-surface-default` |

**위젯 종류는 `menu` 역할이 아니라 공개/숨김(disclosure)입니다.** `role="menu"`는 메뉴 항목만 담을 수 있어 이메일 글자가 맞지 않습니다. 항목도 둘뿐이라 화살표 키가 필요 없습니다.

- 트리거: `aria-expanded`, `aria-controls`. `aria-haspopup`을 쓰지 않습니다.
- Enter·Space·누르기로 열고 닫음. 열어도 초점은 트리거에 둡니다. 다음 Tab이 패널 첫 항목으로 갑니다(패널은 DOM에서 트리거 바로 뒤). 닫힌 패널은 `hidden`입니다.
- Esc: 닫고 초점을 트리거로. 바깥 누름: 닫음(초점 이동 없음). Tab으로 패널을 벗어나면 닫음.
- 메뉴 이동으로 주소가 바뀌면 닫음.
- 모든 항목 44px 이상, hover 없이 동작.

**로그아웃**: 동작은 지금 `LogoutButton`과 같습니다(`POST` 성공 시 `window.location.assign('/')`). 로직을 hook으로 빼서 두 곳이 같이 씁니다.

| 상태 | 화면 |
| --- | --- |
| 진행 중 | 글자 `로그아웃 중…`, `aria-disabled`(초점 유지). `aria-disabled`는 클릭을 막지 않고 `useAction`에 중복 실행 방지가 없으므로 **pending 중 클릭은 핸들러 첫 줄에서 무시**합니다. Esc·바깥 누름으로 닫지 않음 |
| 실패 | 패널 유지, 버튼 아래 `role="alert"` `.form-error-inline` 문구. 같은 버튼으로 재시도 |

**구조 변경**: 머리글을 `ManagerProvider` 안으로 옮겨야 저장 직후 사진이 반영됩니다. 프로바이더는 DOM을 만들지 않으므로 레이아웃에 영향이 없다고 봅니다. `useManager`는 프로바이더 밖에서 예외를 던지므로 `ProfileMenu`는 `useManager`를 쓰지 않고 props(`email`·`isOperator`·`avatar`)만 받습니다. `own` 분기에만 `state.landing.avatar`를 읽어 넘기는 얇은 감싸개를 두고, `!result.ok`·`!own` 분기는 `avatar` 없이 `ProfileMenu`를 바로 그립니다. `email`은 머리글 쪽에서 쓰게 되어 `ManagerProvider`의 `email`은 지웁니다.

## 컴포넌트와 토큰

- **새 토큰 없음.** `tokens.json` 변경 없음.
- 입력란 `--ds-color-background-screen`, `--ds-color-border-strong`, `--ds-corner-md`, `--ds-font-mono`, `--ds-font-size-14`. 도메인 글자 `--ds-color-text-subtle`.
- 메시지 `--ds-color-surface-raised`, `--ds-color-border-default`, `--ds-corner-md`, `--ds-font-size-13`, 안쪽 `--ds-space-10`·`--ds-space-12`, `--card-shadow`. 상태 글자 `--ds-color-status-positive`·`-danger`. 계산상 이 면 위 대비 4.5:1 이상(흐린 글자 약 5.4, 성공 약 5.1, 위험 약 6.0). `--ds-color-status-warning`은 약 4.45라 이 면의 글자로 쓰지 않습니다.
- 잠금 글자 `--ds-font-size-13`, `--ds-color-text-subtle`.
- 재사용: `.input`(변형), `.secondary`·`.icon-only`, `.check-*`, `EditSheet`, `ActionStatus`, `DefaultAvatar`, `RemoteImage`, `.form-error-inline`, `.visually-hidden`.
- `CopyButton`에 아이콘 모양(`icon`)과 결과 콜백(`onResult: (result: 'copied' | 'failed') => void`)을 더합니다.
  - `onResult`를 넘기면 `.copy-feedback`을 **그리지 않고**, 결과 문장과 유지 시간은 부모가 맡습니다. 지금 구조는 상태를 안에 두고 2초 뒤 지워서 막대 아래 문장·4초·`다음 입력까지 유지`를 만들 수 없습니다. 숨겨진 `.copy-feedback`을 남기면 두 번 낭독되고 E2E의 `getByText('복사했어요.')`가 두 요소에 걸립니다.
  - 아이콘의 체크 표시 4초만 `CopyButton` 안에서 유지합니다. `firstRunGuide.recordCopy`용 `onCopied`는 그대로입니다.
  - 막대의 복사 아이콘과 넓은 화면 메시지의 `새 주소 복사`가 `onResult`를 씁니다. 메시지는 `.address-bar` 안에 있어 글자 버튼을 그대로 두면 `.copy-feedback`이 지금 규칙으로 숨겨집니다.
  - `onResult`를 넘기지 않으면 지금 글자 버튼 그대로이고 `FirstRunGuide`·`SignInLink`는 바뀌지 않습니다. `.copy-control > button` 구조와 `aria-label`을 유지합니다.
- 아이콘은 인라인 SVG 선 아이콘(24 viewBox, 20px, stroke 1.8, `aria-hidden`).

## 구현 제약

- 막대 높이 60px를 유지합니다(`.preview-screen` 184px 계산).
- 새 API·공유 계약 변경 없음. `GET /api/me/short-link/availability`, `PUT /api/me/short-link/slug` 그대로.
- `복사`의 값은 `state.shortLink.url`만.
- `firstRunGuide.recordCopy`를 모든 복사 경로에 유지합니다(`새 주소 복사` 포함).
- 메시지는 `.manager-stage`(sticky) 안에서 겹치므로 무대에 `overflow: hidden`을 걸면 잘립니다.
- 1024px 경계를 넘어도 `children`이 다시 마운트되지 않는 `ManagerShell` 구조를 유지합니다.
- 입력란 14px는 넓은 화면 기준입니다. 시트 입력은 16px(iOS 초점 확대 방지).
- 강조색 버튼은 대화상자의 `이 주소로 바꾸기`뿐입니다. 막대의 `변경`은 보조 버튼입니다.

## 검증

- **직접 본 것**: 사용자 스크린샷 1장(1782×1175, `주소 설정` 메뉴, 잠기지 않은 자동 발급 주소 상태)과 위 경로의 코드(`889b878` 기준).
- **실행한 검사**(2026-11-10): `pnpm docs:check` 통과, `pnpm design:check` 통과. `pnpm design:check --require-lint`는 실패(`od lint: 건너뜀 — 로컬 OpenDesign이 없습니다`)이고 예외 절차는 [대상](#대상)에 있습니다. 이 폴더에는 HTML 산출물이 없습니다. 이 검사들은 문서 링크·형식과 기존 산출물만 보며 설계 자체를 검증하지 않습니다.
- **구현 화면 확인(2026-11-10, ego-lite Chromium, 합성 계정).** 항목별 결과와 측정값은 [0234 진행 기록](../../docs/work/orchestrator/0234-address-bar-inline.md#진행-기록)에 있습니다.
  - 390·320px 두 번 탭 방어: 입력 단계 `주소 바꾸기`와 확인 단계 `뒤로`가 같은 높이(390×844 y 788~832, 320×640 y 584~628)이고 CDP 터치 두 번에 `PUT` 0회였습니다. 하드웨어 키보드 없는 에뮬레이션이라 **모바일 키보드가 닫히는 순간의 위치는 미확인**입니다.
  - 막대 `변경` 더블클릭: 대화상자가 열린 뒤 둘째 클릭이 배경에 떨어져 바로 닫힙니다(추정대로). `PUT`은 0회이고 입력값이 남아 저장 위험은 없습니다. 깜빡여 보이는 어색함만 남습니다.
  - 폭 계산: [폭 계산](#폭-계산)을 실측값으로 바꿨습니다.
  - 메시지·`.device-chip`: [메시지 자리](#메시지-자리) 실측. 메시지(`z-index: 5`)가 칩(`3`) 위를 덮습니다.
  - 프로필 패널·메시지의 `--ds-color-surface-raised` 면은 1280×800 스크린샷에서 바탕과 구분됩니다(그림자·테두리 포함).
  - 390·320px의 `NarrowBar` 두 줄 배치: [1023px 이하](#1023px-이하) 표대로 확인했습니다.
- **미확인**(이 기기·도구로 확인할 수 없음)
  - 시트의 실제 모바일 키보드 동작, 키보드가 닫히는 순간 버튼 줄 위치
