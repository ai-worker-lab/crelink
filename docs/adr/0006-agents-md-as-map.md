# ADR 0006: 루트 AGENTS.md를 지도로 두고 공통 정책을 docs로 이동

- 날짜: 2026-10-01
- 상태: 승인
- 범위: 저장소 전체 (루트 `AGENTS.md`, 영역 `AGENTS.md`, `docs/`)

## 배경

- 루트 `AGENTS.md`는 언어·기준 정보·문서 배치·ADR·진입점·변경 기록 정책의 단일 원본이었습니다. 79줄이지만 긴 정책 문단으로 약 11KB였고, 에이전트 도구가 매 세션 컨텍스트에 그대로 넣습니다.
- 매번 주입되는 지시가 길면 작업·코드·관련 문서가 쓸 컨텍스트가 줄고, 모든 규칙이 같은 무게로 보여 중요한 제약을 놓치기 쉽습니다. OpenAI [Harness engineering](https://openai.com/index/harness-engineering/)은 같은 문제를 겪고 `AGENTS.md`를 약 100줄 목차로 두고 세부는 `docs/`에서 필요할 때 읽게 했습니다(점진적 공개).
- 정책을 옮기면 에이전트가 필요한 문서를 찾아 읽어야 하므로, 지도가 정확하고 링크가 깨지지 않아야 합니다.

## 결정

1. 공통 정책 원문은 [저장소 공통 정책](../development/repository-policy.md)에 둡니다. 내용은 그대로 옮기고, 지도화 원칙과 반복 규칙을 검사로 옮기는 원칙만 추가합니다.
2. 루트 `AGENTS.md`는 저장소 소개, 핵심 명령, 반드시 지킬 규칙, 문서 지도만 담습니다. 크기 예산(100줄·3500자)과 영역 `AGENTS.md` 예산(40줄)은 `pnpm docs:check`(`scripts/docs-check.mjs`)가 강제합니다.
3. 영역 `AGENTS.md`와 다른 문서는 정책을 루트 `AGENTS.md`가 아니라 공통 정책 문서의 해당 절로 링크합니다. 링크·anchor·고아 문서도 `pnpm docs:check`가 검사합니다.

## 결과와 트레이드오프

- 매 세션 고정 컨텍스트가 줄고, 핵심 규칙이 눈에 띕니다. 세부 정책은 해당 작업에서만 읽습니다.
- 에이전트가 지도를 따라가지 않으면 세부 정책을 놓칠 수 있습니다. 그래서 자주 어기는 규칙은 문서보다 검사로 옮기는 것을 원칙으로 합니다.
- 정책 원본이 두 파일(지도와 정책 문서)로 보일 수 있으므로, 지도에는 규칙 요약만 두고 원문은 정책 문서 한 곳에만 둡니다.
