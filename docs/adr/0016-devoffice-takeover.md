# ADR 0016: 크리링 운영을 개발실로 이관하고 AI 운영자 자율 실행을 정지

- 날짜: 2026-11-09
- 상태: 승인 (2026-11-09 사용자 결정: "개발실은 크리링 프로젝트를 인수인계 받아서 서비스를 이어나가야 한다", "실제 운영도 개발실에서 맡아서 운영하여야 한다.", 2026-11-10 사용자 결정: "머지도 너가 해. 진짜 바이브 코딩이야. 나는 사용자의 입장에서 기능 등 요구사항만 전달할꺼야")
- 범위: 저장소 작업, main 머지와 운영 배포, 운영 감시와 장애 대응, CI 실행 위치
- 관계: [ADR 0015](0015-ai-operator.md)의 AI 운영자 자율 실행을 정지합니다. [ADR 0002](0002-work-items-in-repository.md)는 유지합니다.

## 배경

- ADR 0015의 AI 운영자는 운영자 Mac의 20분 자동화로 돌았습니다. 그 Mac을 초기화해 자동화와 토큰 파일이 사라졌고, 마지막 토큰 사용은 2026-10-12입니다. 토큰은 2026-11-09에 폐기했습니다.
- 운영자 age 키도 함께 사라져 새 키로 교체했습니다([런북 4-5](../../infra/docs/prod-runbook.md#4-5-회전)).
- 사용자는 역할별 AI 에이전트 팀(개발실: CTO, 리서치, 풀스택 개발, 디자인, QA, 운영)에 프로젝트를 맡기기로 했습니다. 메인 세션이 조정하고 역할은 필요할 때만 실행합니다.

## 결정

1. **권한:** 사용자는 요구사항을 전달하고, 구현·병합·배포는 개발실이 맡습니다. 사용자 승인이 필요한 일은 지출·결제, 데이터 파괴(사용자 데이터 삭제, 되돌릴 수 없는 migration, 운영 DB 직접 쓰기), 외부 게시·발송, 자격 증명 변경입니다.
   - **병합 조건:** `CI 통과`, 그리고 동작이 바뀌는 변경은 독립 QA 합격. 병합 뒤 Deploy 결과와 운영 주소를 확인합니다.
2. **장애 예외:** 운영 장애가 확인되면 직전 릴리스로의 롤백은 사전 승인된 것으로 보고 실행한 뒤 바로 보고합니다. DB 마이그레이션은 되돌리지 않습니다.
3. **범위:** 유지·개발과 운영입니다. 성장(마케팅·이벤트)은 안정화 후 다시 정합니다.
4. **작업 체계:** work item, `.omp/agents/*.md`의 이름과 `owns`, `pnpm work:*`, `pnpm verify`를 그대로 씁니다. `pnpm work:run`과 20분 자동화는 쓰지 않습니다.
5. **CI:** 로컬 기기에서 변경 영향에 맞는 `pnpm ci:local` profile을 성공시켜 clean SHA의 receipt를 만들고 push합니다. 머지 전 동일 SHA/base·환경·범위 옵션의 `--report`는 receipt 대조·`CI 통과` 등록만 하며 검사 재실행은 0회입니다(2026-11-11 사용자 승인 보강). runner·lock·공통 infra 변경은 full, receipt 없음·불일치·dirty·필수 실패/누락/중단은 거부하며 다시 검증합니다. 실행 범위·명령·예외의 원본은 [검증 루프](../development/verification.md#로컬-ci)와 해당 registry입니다. GitHub Actions 자동 실행은 CD만 남깁니다(2026-11-10 전환, 0237). `ci.yml`은 실제 영향에 로컬 미포함 E2E·WebKit·Firefox·amd64 검증이 필요할 때만 수동 실행하며, 단순 관리 옵션 변경으로 무조건 실행하지 않습니다. 사전 선언된 외부 live 관측 실패만 비차단이고 내부 필수 실패는 유지합니다.
6. **브라우저 검증:** Playwright에서 ego-lite로 옮깁니다. 첫 시범은 [0206](https://github.com/ai-worker-lab/crelink/tree/work/0206-ego-analytics-responsive)입니다.
7. **운영 감시:** Sentry와 Discord를 씁니다. Jira와 Confluence는 보류합니다.

## 이유

- 사용자는 요구사항에 집중하고 구현과 배포를 맡기기로 했습니다. 사람 확인이 빠지므로 병합 전 검증과 병합 뒤 확인이 유일한 관문입니다.
- `owns`를 바꾸면 티켓 165개의 역할이 깨지고 `work:check`가 실패합니다. 역할 이름을 라벨로 유지하고 개발실 담당자를 배정합니다.
- 상시 실행은 토큰 비용이 큽니다. 감시는 LLM 없는 점검이 상태 변화만 알리고, 알림이 오면 역할을 호출합니다.
- Jira·Confluence는 비용이 아니라 상태 원본이 둘로 갈리는 문제 때문에 보류했습니다. 협업자가 늘면 ADR 0002와 함께 다시 검토합니다.

## 버린 대안

- AI 운영자 복구: 사용자가 팀 운영으로 전환했습니다.
- `.omp/agents` 역할을 개발실 이름으로 교체: 효용보다 깨지는 범위가 큽니다.
- CI의 Playwright 유지: 권고했으나 사용자가 로컬 CI를 택했습니다.

## 결과와 트레이드오프

- `CI 통과`가 로컬에서 기록되면 신뢰 기반이 됩니다. 쓰기 권한자는 검증 없이도 기록할 수 있습니다.
- ego-lite는 Chromium 기반이라 WebKit·Firefox 자동 검사와 독립 컨텍스트 병렬 실행을 잃습니다.
- 필요 승인 수는 0이고 사람 검토가 없습니다. 잘못된 변경은 바로 운영에 나갈 수 있어 CI, QA, 롤백에 의존합니다.
- 서버 안의 점검은 서버 전체 장애를 알리지 못해 외부 감시가 필요합니다.
