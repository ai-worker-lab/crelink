# ADR 0015: AI 운영자에게 운영·개발·배포 권한 위임

- 날짜: 2026-10-10
- 상태: 승인 (2026-10-10 사용자 결정: "모든 권한을 맡긴다. 운영부터 추가 기능 등 기획부터 개발까지 모두 ai 전용 계정을 만들자. 실행할때마다 기록을 남기자." 이 ADR의 세부 선택은 같은 위임에 따른 AI 승인)
- 범위: 크리링 운영(운영자 API·화면, 운영 데이터 쓰기), 저장소 작업(work item·기획·설계·개발·PR·main 머지=운영 배포), 실행 호스트(운영자 Mac의 Orca 자동화), API 인증(`apps/api`), 웹 토큰 경로(`apps/web`), 저장소 정책([저장소 공통 정책](../development/repository-policy.md), 루트 `AGENTS.md`)
- 관계: 저장소 공통 정책의 "배포·데이터 파괴·외부 공개는 명시적 요청 없이 하지 않습니다", "main 머지 전에 알림", "제품 방향·우선순위·요구 확정은 사용자 결정", [검증 루프](../development/verification.md#운영-확인)의 "운영 확인 전 사용자에게 알림"에 AI 운영자 예외를 둡니다. 다른 정책은 그대로입니다.

## 배경

- 크리링의 1차 목표는 사이트 보강과 실사용자 100명 모집입니다([PRD](../product/crelink.md) `목표`). 사용자는 이 일을 AI에게 맡기고, 30분마다 실행되는 AI 운영자가 운영·기획·개발·배포를 모두 하기로 했습니다.
- 지금 정책은 배포·외부 공개·제품 결정마다 사람 승인을 요구합니다. 운영자 API는 Google 로그인 쿠키만 받고, 운영 쓰기의 행위자를 기록하지 않습니다.
- 사람 확인 없이 운영 쓰기를 하려면 누가(사람·AI) 무엇을 했는지 남는 기록, 즉시 멈출 수단, 자격 증명 폐기 수단이 필요합니다.

## 결정

1. **권한 위임**: AI 운영자는 [AI 운영자 헌장](../ops/ai-operator.md)의 범위 안에서 사람 승인 없이 운영 쓰기, 기획(PRD·work item), 설계 승인, 개발, PR, CI 통과 뒤 main 머지(=운영 배포), 배포 결과 확인과 롤백을 합니다. 사람 승인 대신 근거를 work item `진행 기록`과 실행 기록에 남깁니다("사용자 위임(2026-10-10)에 따른 AI 승인").
2. **예외 없는 규칙**: 법·약관(정보통신망법 제50조 광고성 정보 전송 동의, 플랫폼 자동화·스팸 금지, 표시광고법 추천·보증 표시), 개인정보 처리방침 범위, 비밀값 노출 금지, 사용자 데이터 파기 금지, 운영 방문·클릭 통계 오염 금지는 위임 범위 밖입니다. 이런 일이 필요하면 하지 않고 실행 기록에 사람 결정 필요로 남깁니다.
3. **전용 계정**: AI는 사람과 구별되는 크리링 계정(`users.kind='ai'`, 운영자 권한)으로 일합니다. Google 로그인 없이 API 토큰(Bearer)만 쓰고, 토큰은 DB에 해시만, 원문은 실행 호스트의 권한 600 파일에만 둡니다. 발급은 운영 서버 API 컨테이너 안 CLI로만 합니다.
4. **기록**: 모든 운영자 쓰기는 행위자·행동·대상·전후 값·실행 id를 남기고, AI 실행은 시작·끝·상태·요약·한 일·다음 할 일·관련 PR을 남깁니다. 사람에게 알리는 기본 방법은 운영자 화면의 실행 기록입니다.
5. **멈춤**: 사람 운영자만 켜고 끄는 멈춤 스위치가 켜지면 실행은 기록만 남기고 아무것도 하지 않으며, 진행 중 실행의 AI 쓰기도 즉시 거절됩니다. 그 밖의 되돌림 수단은 토큰 폐기와 Orca 자동화 끄기입니다.
6. **GitHub 신원**: AI 전용 GitHub 계정(machine user)이 생기기 전까지 실행 호스트의 기존 `gh` 자격으로 커밋·PR하고, 커밋 트레일러 `AI-Operator-Run: <실행 id>`로 구별합니다.

## 검토한 대안

- **사람 승인 유지(AI는 제안만)**: 가장 안전하지만 사용자가 명시적으로 모든 권한 위임을 결정했고, 30분 주기 실행의 의미가 없어집니다.
- **사람 운영자 세션 쿠키를 AI가 재사용**: 구현이 가장 적지만 사람과 AI 행동이 구별되지 않고, 세션 만료(30일)마다 사람이 로그인해야 하며 폐기가 사람 로그아웃과 섞입니다.
- **운영 API를 인터넷에 직접 공개해 토큰으로 호출**: 경로가 짧지만 API 비공개 원칙([운영 배포 설계](../specs/crelink-prod-deploy.md))과 Caddy 공개 정책을 바꿔야 합니다. 웹의 토큰 전용 경로를 지나게 했습니다.
- **HTTP로 토큰 발급(운영자 화면 버튼)**: 편하지만 사람 세션이 탈취되면 AI 권한 토큰도 만들 수 있습니다. 서버 접속 권한이 있는 사람만 CLI로 발급합니다.

## 결과와 트레이드오프

- 사람 확인 없는 운영 쓰기와 배포가 생깁니다. 잘못된 행동은 기록으로 찾고, 멈춤·토큰 폐기·자동화 끄기·Git 되돌리기·운영 롤백으로 복구합니다. 데이터 파기 API가 없어 되돌릴 수 없는 쓰기는 제한됩니다.
- AI 커밋이 사람 `gh` 자격으로 남는 동안은 GitHub 화면에서 행위자를 트레일러로만 구별합니다.
- 실행 비용(모델 사용량)이 30분마다 생깁니다. 헌장의 비용·행동 상한과 할 일이 없을 때 짧게 끝내는 규칙으로 줄입니다.
- 구현 세부는 [AI 운영자 기술 설계](../specs/crelink-ai-operator.md)가 기준입니다.
