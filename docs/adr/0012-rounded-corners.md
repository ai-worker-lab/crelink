# ADR 0012: 계단형 모서리 대신 둥근 모서리

- 날짜: 2026-10-07
- 상태: 승인
- 범위: `packages/design-tokens`, `design/`, `apps/web`, `apps/app` (여러 영역)
- 대체: [ADR 0001](0001-design-tokens.md) 결정 6(시작 모서리 스타일)

## 배경

- ADR 0001 결정 6은 뼈대의 시작 컴포넌트가 계단형(픽셀) 모서리를 쓰고 서비스 디자인에서 바꿀 수 있다고 정했습니다. 웹은 `clip-path` 다각형, 앱은 `PixelFrame`으로 그렸습니다.
- 2026-10-07 사용자가 크리링 디자인 방향을 스튜디오 라이트(밝은 바탕, 흰 카드, 둥근 모서리, 알약형 버튼)로 확정했습니다. 규칙은 [디자인 시스템](../../design/system/DESIGN.md)에 있습니다.
- `clip-path`는 바깥 초점 링과 그림자를 잘라 내어, 초점 링을 요소 안쪽에 그려야 했고 카드 그림자를 쓸 수 없었습니다.

## 결정

1. 모서리는 `border-radius`(웹)와 `borderRadius`(앱)로만 그리고, 값은 `corner` 토큰을 씁니다: `corner.sm`(배지·작은 칩), `corner.md`(입력·내부 요소), `corner.lg`(카드·링크 카드·하단 시트), `corner.full`(알약형 버튼·스위치). 프로필 사진은 원형입니다.
2. 웹의 계단 다각형(`--notch-md`)과 앱의 `PixelFrame`을 없앱니다.
3. 초점 링은 요소 바깥에 그립니다(3px 실선, 간격 2px, 본문 글자색).

## 결과와 트레이드오프

- 초점 링과 카드 그림자를 잘림 없이 쓸 수 있고, 웹·앱 모두 기본 스타일 속성만으로 모서리를 그려 코드가 줄어듭니다.
- 앱은 `PixelFrame`의 세 조각 그리기가 필요 없어지고, 버튼·카드는 한 `View`의 배경·테두리·모서리로 그립니다.
- 다른 모서리 형태가 필요해지면 이 ADR을 대체하는 새 ADR로 정합니다.
