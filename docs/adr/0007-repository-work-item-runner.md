# ADR 0007: 저장소 work item을 제어 평면으로 쓰는 에이전트 실행기

- 날짜: 2026-10-01
- 상태: 승인
- 범위: 저장소 전체 (work item 진행, 에이전트 실행, `scripts/runner.mjs`, `WORKFLOW.md`)

## 배경

- work item은 `docs/work/`의 파일이며 상태의 원본은 각 파일의 `상태` 줄입니다([ADR 0002](0002-work-items-in-repository.md)). 지금까지는 사람이 티켓을 골라 에이전트에 위임했습니다.
- [OpenAI Symphony](https://github.com/openai/symphony)는 이슈 트래커를 제어 평면으로 두고, 이슈마다 격리 작업공간과 코딩 에이전트를 띄우며, 정책과 프롬프트를 저장소의 `WORKFLOW.md`로 관리합니다. 고정된 상태 전이 대신 목표와 인계 상태를 프롬프트로 줍니다.
- 에이전트 런타임(OMP, Codex, Claude Code)은 바뀔 수 있고, 여러 티켓을 병렬로 진행하면 누가 무엇을 잡았는지 드러나야 합니다.

## 결정

1. 외부 트래커 없이 저장소 work item을 실행기의 제어 평면으로 씁니다. 착수 가능 조건(에픽 아님, 하위 항목 없음, `준비`, 자신과 상위의 `선행`이 모두 `완료`, 점유 없음)은 `scripts/lib/work-items.mjs`의 한 함수가 계산하고 `pnpm work:next`와 실행기가 함께 씁니다.
2. 착수 점유는 `work/NNNN-<slug>` 브랜치의 존재(로컬 또는 원격)입니다. 점유를 기록하는 별도 파일이나 상태 사본을 두지 않습니다.
3. 실행 정책은 루트 `WORKFLOW.md`의 YAML front matter, 에이전트 지시는 그 본문 템플릿으로 저장소에 둡니다. 실행기는 tick마다 다시 읽고, 잘못된 설정이면 마지막 정상 설정을 유지합니다.
4. 실행기는 티켓마다 git worktree를 만들고 `agent.command`(셸 명령)를 그 worktree에서 실행합니다. 런타임은 명령과 환경변수(`WORK_ITEM_ID`, `WORK_PROMPT_FILE` 등) 계약으로만 연결해 특정 에이전트에 묶지 않습니다.
5. 에이전트가 끝나면 실행기는 worktree 안의 work item 상태만 보고 판단합니다. `준비`·`진행`이면 지수 backoff로 재시도하고, 그 밖이면 인계로 끝냅니다. 기준 checkout에서 `보류/종료`가 되거나 삭제되면 실행 중인 에이전트를 멈춥니다.
6. 실행기 상태(이벤트, 로그, 프롬프트, 주기 작업 시각)는 실행기를 띄운 checkout의 `.local/runner/`에만 두며 재시작 복구는 브랜치와 worktree에서 다시 계산합니다.

## 결과와 트레이드오프

- 별도 서비스나 데이터베이스 없이 저장소와 git만으로 점유·진행·복구가 드러납니다. 런타임을 바꿀 때는 `agent.command`만 바꿉니다.
- work item 상태 변경은 작업 브랜치의 커밋이므로, 기준 브랜치에서 보이는 상태는 병합 시점에야 바뀝니다. 진행 중 여부는 `work/*` 브랜치와 `pnpm work:next --all`로 봅니다.
- 병렬 브랜치에서 새 work item을 만들면 번호가 겹칠 수 있습니다. 병합 후 `pnpm work:check`가 중복을 잡고 병합하는 쪽이 번호를 다시 매깁니다.
- 실행기는 사람 확인 없이 에이전트 명령을 실행합니다. 기본 동시 실행 1개, 원격 push는 설정(`workspace.push`)으로만 켜고, 배포·데이터 파괴·외부 공개·force push는 프롬프트에서 금지합니다. 이 경계는 프롬프트와 런타임 권한에 의존하므로 실행 환경 자체의 권한(자격 증명, 네트워크)도 함께 제한해야 합니다.
- 재시도 횟수는 메모리에만 있어 실행기를 다시 시작하면 active 상태로 남은 항목을 처음 시도부터 다시 진행합니다.
