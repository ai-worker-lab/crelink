# ADR 0009: work item을 역할별 폴더에 둠

- 날짜: 2026-10-02
- 상태: 승인
- 범위: 저장소 전체 (ALM 작업 관리)

## 배경

- [ADR 0003](0003-work-item-hierarchy.md) 결정 4는 "계층은 폴더가 아니라 필드"로 정해 모든 work item을 `docs/work/` 한 폴더에 두었습니다. 상위를 바꿔도 경로와 링크가 그대로라는 장점이 있었습니다.
- 항목이 늘면서 사용자가 "work가 역할별로 쪼개져 있지 않아 구분이 어렵다"고 판단했습니다. 티켓은 한 역할(`.omp/agents`의 agent)이 맡는 단위인데, 한 폴더에서는 파일 이름만으로 어느 역할의 일인지 보이지 않습니다.
- 에픽 없는 독립 티켓(결함·유지보수·운영·제품 결정, 여러 영역을 바꾸는 `orchestrator` 티켓)이 계속 있습니다.

## 결정

1. 에픽은 `docs/work/epics/NNNN-<slug>.md`, 티켓·하위 티켓은 `docs/work/<역할>/NNNN-<slug>.md`에 둡니다. 폴더 이름은 `역할` 필드 값이자 `.omp/agents`의 agent name입니다. 루트에는 `README.md`와 `TEMPLATE.md`만 둡니다.
2. 폴더는 역할 구분용입니다. 계층은 여전히 `상위`, 순서는 `선행` 필드로 표현하며, 하위 티켓도 상위 티켓 아래가 아니라 자기 역할 폴더에 둡니다. ADR 0003의 나머지 결정(3단계, "티켓" 용어, 한 티켓 한 역할, 독립 티켓, 검사 명령)은 그대로입니다.
3. 번호는 폴더와 관계없이 저장소 전체에서 하나인 일련번호입니다. 파일 이름, 첫 줄 `# NNNN 제목`, 브랜치 `work/NNNN-<slug>`는 바뀌지 않습니다.
4. 폴더 배치는 `pnpm work:check`가 검사하고, 역할·단계를 바꿔 폴더가 달라지면 `pnpm work:place`가 파일을 옮기며 저장소 Markdown의 상대 링크를 함께 고칩니다. 세부 규칙은 [작업 관리](../work/README.md)가 기준입니다.

## 검토한 대안

- **에픽별 폴더(`docs/work/<에픽>/`)**: 에픽 하나의 진행을 한곳에서 보기 좋지만, 에픽 없는 독립 티켓을 둘 곳이 따로 필요하고 상위를 바꿀 때마다 파일이 옮겨집니다. 사용자의 목적은 역할별 구분이라 탈락했습니다.
- **한 폴더에 역할을 이름에 넣기(`NNNN-<역할>-<slug>.md`)**: 파일을 옮기지 않아도 되지만 역할을 바꾸면 이름과 브랜치 slug가 함께 바뀌고, 폴더 단위로 한 역할의 일을 모아 볼 수 없습니다. 역할별 구분이라는 목적을 이름 규칙에 맡기는 셈이라 탈락했습니다.
- **현재 유지(한 폴더 + `역할` 필드)**: `pnpm work`·`work:next`가 역할을 보여 주지만 파일 탐색과 위임 때 구분이 어렵다는 문제가 남습니다.

## 결과와 트레이드오프

- 역할 agent와 사람이 한 역할의 티켓을 폴더 하나에서 찾습니다. 에픽은 `epics/`에 모여 통합 책임 위치가 드러납니다.
- 역할이나 단계를 바꾸면 파일이 옮겨지고 링크 경로가 바뀝니다. `pnpm work:place`가 링크를 고치지만, 코드 표기나 문장 속 옛 경로(변경 기록의 근거 등)는 지난 기록으로 남기고 위치만 알려 줍니다.
- 번호를 정할 때 모든 폴더를 봐야 합니다. `pnpm work`가 전체 번호를 보여 주고, 번호 중복은 폴더를 넘어 `pnpm work:check`가 잡습니다.
- 이 도구를 이식해 쓰는 저장소는 같은 명령으로 기존 work item을 옮깁니다([기존 저장소에 하네스 적용](../development/adopting-harness.md)).
