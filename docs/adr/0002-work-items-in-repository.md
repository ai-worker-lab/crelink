# ADR 0002: work item을 저장소 문서로 관리

- 날짜: 2026-10-01
- 상태: 승인
- 범위: 저장소 전체 (ALM 작업 관리 도구)

## 배경

- 초기 골격은 GitHub Issues를 work item 도구로 쓰는 어댑터(Issue Forms, 상태 라벨)를 함께 가져왔습니다.
- 사용자는 work item을 GitHub Issues가 아니라 저장소 문서로 관리하기로 정했습니다.
- [ALM 운영 기준](../alm/workflow.md)은 작업 관리 도구를 교체 가능한 어댑터로 두므로, 기준 본문은 바꾸지 않고 구현 방법만 바꿀 수 있습니다.

## 결정

1. work item은 `docs/work/NNNN-short-title.md` 파일 하나로 관리합니다. 형식과 진행 방법은 [작업 관리](../work/README.md)가 기준입니다.
2. 각 항목의 상태는 그 파일의 `상태` 줄에만 둡니다. 목록·보드·라벨 같은 상태 사본을 만들지 않습니다.
3. GitHub Issues 기능을 끄고 `.github/ISSUE_TEMPLATE/`와 GitHub 어댑터 문서를 삭제합니다. Pull Request 템플릿은 work item 파일 경로를 연결하도록 유지합니다.

## 결과와 트레이드오프

- work item이 코드와 같은 커밋·이력·리뷰를 거치고, 저장소만 있으면 원격 서비스 없이 읽을 수 있습니다. 도구를 바꿀 때 내보내기·이전 작업이 필요 없습니다.
- 상태 변경도 커밋이 필요합니다. 담당자 지정, 알림, 보드 화면, 댓글 토론 같은 Issues 기능은 없습니다. 1인 개발 범위에서는 필요하지 않다고 봅니다.
- 동시에 여러 브랜치에서 같은 항목을 고치면 Git 충돌로 드러납니다. 같은 항목의 상태 변경은 해당 작업 브랜치에서만 합니다.
- 협업자가 늘거나 외부 사용자의 피드백 창구가 필요해지면 이 결정을 다시 검토합니다.
