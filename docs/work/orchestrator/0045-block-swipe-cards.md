# 0045 블록 안 스와이프 카드와 쿠팡 파트너스 카드 정보 채우기 결정

- 단계: 티켓
- 역할: orchestrator
- 상태: 진행
- 종류: 제품 결정
- 우선순위: P2 (AI 제안)
- 작성일: 2026-10-07

## 목적

크리에이터가 공개 랜딩에서 쿠팡 파트너스 링크를 블록(구역) 안에서 가로로 넘기는 카드로 보여 주고 싶어 합니다. 카드에 상품 사진·이름을 어떻게 채울지 정하기 전에 쿠팡 파트너스 API로 가능한지 조사하고, 사용자가 고를 선택지와 질문을 정리합니다. 이 기능은 이후 PRD·API·웹 작업으로 나뉘므로 결정과 분해는 `orchestrator`가 맡습니다.

조사 질문: 상품 ID·쿠팡 URL·파트너스 단축 URL로 상품 정보를 얻는 공식 경로가 있는가? 없다면 크리링이 약관과 보안 위험 없이 카드 정보를 채울 방법은 무엇인가?

끝낼 조건: 공식 문서·약관·로그인 화면으로 확인할 수 있는 범위를 정리하고, 답하지 못한 것은 `미정`으로 남겨 사용자 결정으로 넘깁니다.

### 사용자 결정(2026-10-07)

1. 구조: 블록 형태로 영역을 나누고 한 블록 안에서 카드를 스와이프로 넘긴다. 블록마다 표시 종류(지금의 리스트형, 스와이프 카드형)를 고른다.
2. 내용: 링크를 전달하면 정보를 가져와 채우는 방식.
3. 대가성 문구: 쿠팡 링크가 있으면 자동 표시.
4. 한도: 카드 링크도 계정당 무료 링크 5개(PRD R13)에 포함.
5. 쿠팡 카드 자동 채움 방식은 파트너스 API 조사 후 결정(이 티켓의 조사 목적).

## 조사 결과 요약

세부와 출처는 [쿠팡 파트너스 링크 카드 정보 채우기 방식 비교](../../references/coupang-partners-card-data.md)입니다.

- 상품 ID·쿠팡 URL·파트너스 단축 URL로 상품 정보(사진·이름·가격)를 돌려주는 공식 파트너스 API는 없습니다. 상품 API는 카테고리 베스트·골드박스·쿠팡 PL·키워드 검색(최대 10개, 1분 50회)·추천뿐이고, `POST /deeplink`는 쿠팡 URL을 추적 단축 URL로 바꿀 뿐입니다(파트너스 도움말 `문서` 탭 명세, 로그인 화면에서도 같음).
- API 키는 최종 승인 회원만 발급받습니다(로그인 화면: 최종 승인 전 계정은 `생성` 비활성). 약관은 인증 키를 제3자에게 제공·공유하는 것과 API 데이터를 복제·저장·전송하는 것을 금지하고, V2 가이드는 응답 캐시를 웹 5분으로 제한합니다. 크리링이 크리에이터 키를 보관하거나 API 사진·가격을 저장해 쓰는 방식은 약관과 충돌할 가능성이 큽니다.
- 서버가 쿠팡 상품 페이지를 열면 403, 파트너스 단축 주소를 열면 클릭 추적 값이 붙은 302이고, 약관은 로봇·자동화 접근과 자동화된 클릭을 금지합니다. 서버가 쿠팡·파트너스 주소를 열지 않아야 합니다.
- 상품 링크 화면은 단축 URL과 `일반태그`(iframe, 상품명 없음)·`블로그용 태그`(생성된 배너 이미지 + `alt` 상품명, 잘릴 수 있음)를 줍니다. 붙여 넣은 코드로는 원본 상품 사진과 온전한 상품명을 확실히 얻지 못하고 가격은 없습니다.
- 쿠팡 외 링크의 OG 수집은 SSRF 방어(사설·Tailscale 대역 차단, 연결 시점 IP 검사, 리디렉션 단계 검사), 시간·크기 제한, 수집 금지 도메인(쿠팡·제휴 단축 주소), 이미지 재호스팅 여부를 설계에서 다뤄야 합니다.
- `[AI 제안]` 추천: 쿠팡 카드는 파트너스 URL 붙여 넣기 + 직접 입력(사진 업로드·이름)을 기본으로, 블로그용 태그 붙여 넣기는 링크·이름을 미리 채우는 보조로 둡니다. 파트너스 API 연동과 가격 표시는 하지 않습니다. 이 경우 결정 2("가져와 채우기")는 쿠팡 링크에서 부분적으로만 충족됩니다.

## 남은 사용자 결정 질문

1. **쿠팡 카드 채움 방식** — 선택지: (A) 파트너스 API 연동(크리에이터 키 보관), (B) HTML 코드 붙여 넣기만, (C) 파트너스 URL + 직접 입력만, (D) C 기본 + B 보조. `[AI 제안]` D. 근거: 조회 API 없음, 키 위탁·데이터 저장이 약관과 충돌, 코드만으로는 사진·이름이 확실하지 않음. D를 고르면 결정 2가 쿠팡 링크에서는 "링크·쿠팡 여부·대가성 문구 자동, 사진·이름은 크리에이터 입력(이름은 코드가 있으면 미리 채움)"으로 좁혀지는데 이를 받아들일지 함께 답해 주세요.
2. **쿠팡 카드 사진** — 선택지: (가) 크리에이터 업로드만, (나) 블로그용 태그의 쿠팡 CDN 배너 이미지를 그대로 표시, (다) 둘 다 허용하고 크리에이터가 고름. `[AI 제안]` 가. 근거: 블로그용 태그 이미지는 상품+쇼핑 버튼이 합쳐진 세로 배너일 가능성이 커 카드에 맞지 않고 `[추정]`, 재호스팅은 지식재산권 위험, 그대로 표시는 방문자 IP가 쿠팡에 전달되고 이미지가 지워지면 깨짐.
3. **가격 표시** — 선택지: (가) 표시하지 않음, (나) 크리에이터가 직접 입력해 표시. `[AI 제안]` 가. 근거: 공식 경로(API)는 5분 이내 갱신이 필요하고 저장이 금지되며, 직접 입력 가격은 낡아 사실과 다른 표시가 될 위험.
4. **일반 쿠팡 주소(`www.coupang.com/vp/products/…`) 입력** — 선택지: (가) 수익이 반영되지 않는다고 안내하고 저장 허용, (나) 저장 막고 파트너스 링크로 바꾸라고 안내. 또 대가성 문구를 (ㄱ) 파트너스 주소(`link.coupang.com`·`coupa.ng`)일 때만, (ㄴ) 쿠팡 도메인이면 모두 표시. `[AI 제안]` 가 + ㄱ. 근거: 이용 가이드상 일반 주소는 수익이 없어 경제적 이해관계가 생기지 않음 `[추정]`, 크리에이터가 제휴 없이 쿠팡 상품을 소개할 수도 있음.
5. **쿠팡 외 링크의 정보 가져오기(OG)** — 선택지: (가) 이번 스와이프 카드 범위에 넣음(서버 수집기 + SSRF 방어 설계, 이미지는 재호스팅 또는 주소 표시 중 선택), (나) 이후 버전으로 미루고 지금은 파비콘 + 직접 입력. `[AI 제안]` 가, 이미지는 기존 업로드 경로로 검증해 재호스팅하고 크리에이터가 쓸지 확인. 근거: 결정 2를 쿠팡 외 링크에서는 충족할 수 있고, 재호스팅은 기존 `thumbnail`(업로드 이미지) 계약에 맞으며 방문자 정보가 외부로 나가지 않음. 대신 수집기 보안·운영 부담이 생기므로 범위가 커짐.

참고(질문 아님): 운영정책은 파트너스에 등록되지 않은 미디어에 광고를 노출하는 것을 금지하므로, 크리에이터가 크리링 랜딩 주소를 파트너스 활동 페이지로 등록하도록 안내가 필요할 수 있습니다 `[추정]`.
