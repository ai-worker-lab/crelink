# 0148 검색엔진 소유 확인과 sitemap 제출(회사 계정 접근 필요)

- 단계: 티켓
- 역할: orchestrator
- 상태: 진행
- 종류: 운영
- 우선순위: P1
- 작성일: 2026-10-10

## 목적

0141로 운영에 `robots.txt`·`sitemap.xml`·OG가 생겼지만, 검색엔진에 사이트 소유를 확인하고 sitemap을 제출해야 홈·문서의 색인과 검색 유입을 관측할 수 있습니다. PM은 정상 접근 가능한 회사 계정에서 무료 등록·소유 확인·제출을 자율 실행합니다. 외부 홍보 승인 대기가 아니라 실제 회사 계정 로그인과 소유 확인 값 확보가 선행 조건입니다.

## 수용 기준

- [ ] PM이 정상 접근 가능한 회사 Google·네이버 계정을 선정하고 소유 확인 권한을 확인합니다. Google의 2026-10-10 사용자 선택은 아래 역사 기록으로 유지하며, 무료 등록에 별도 사람 승인을 요청하지 않습니다. 인증/접근 불가는 정확한 기술 선행 조건으로 기록합니다.
- [x] 소유 확인 방식을 정합니다. HTML 메타 태그나 확인 파일이면 값을 받아 web 티켓으로 반영합니다(확인 값은 비밀값이 아니지만 계정 정보는 저장소에 쓰지 않음). DNS TXT면 사람이 직접 등록합니다.
- [ ] 두 서비스에 `https://links.shaul.kr/sitemap.xml`을 제출하고 제출 결과(성공·오류)를 진행 기록에 남깁니다.

## 범위

- 포함: 소유 확인, sitemap 제출, 확인 태그가 필요하면 그 반영 티켓 생성.
- 제외: 유료 검색 광고·결제, 사람 개인계정 임의 사용, 플랫폼이 금지한 자동 계정 생성과 인증 우회. 플랫폼이 허용하는 무료 회사 계정 구성은 현행 헌장 범위입니다.

## 위험·복구

확인 태그를 잘못 넣어도 서비스 동작에는 영향이 없습니다. 태그를 지우면 소유 확인만 풀립니다.

- 2026-10-10: 생성(AI 운영자 실행 `e1f4ffa2-d409-4be6-b34e-a2b2b9551f53`, 직전 실행 `1827dbad-ec9c-4ace-b51a-c973adfeafd3`의 "사람 결정 필요"). 사람 계정이 있어야 해 분류 대기로 둡니다.
- 2026-10-10: 사용자 결정(대화, AI 운영자 실행 `d9c7ae80-fdbd-40be-9150-735983b583b4`): Google Search Console 소유 계정은 사용자가 정한 운영자 Google 계정입니다. 주소는 개인정보라 저장소에 쓰지 않습니다(헌장 지킬 규칙 4). 상태를 `진행`, 우선순위를 `P1`로 확정합니다(사용자 위임(2026-10-10, ADR 0015)에 따른 AI 승인).
  - 확인 방식(AI 승인): Google은 `URL 접두어` 속성 `https://links.shaul.kr/`과 `HTML 태그`, 네이버는 `HTML 태그`입니다. 두 값을 받아 루트 레이아웃 `metadata.verification`(`google`, `other['naver-site-verification']`)에 넣습니다. 이 티켓의 역할(orchestrator)이 `apps/web/**`도 가지므로 따로 web 티켓을 만들지 않습니다. DNS TXT(Google `도메인` 속성)는 Cloudflare 사람 작업이라 쓰지 않습니다.
  - 다음: 사람이 두 서비스에서 확인 값(`content`)을 받아 알려 주면 → 메타 태그 반영·배포 → 사람이 `확인` 누르기 → sitemap 제출 → 결과를 여기 남김.
- 2026-10-12: 사용자 위임 변경으로 무료 검색엔진 등록·회사 계정 선정은 PM 자율 실행입니다. 위 2026-10-10의 사람 직접 확인/계정 선정 절차는 당시 기록입니다. PM이 정상 회사 계정 접근·소유 확인 값을 확보하고 기존 선택 방식으로 확인·sitemap 제출을 수행합니다. OTP·접근 자격이 없으면 우회하지 않고 실제 필요한 접근 단계와 대안을 기록합니다. 실제 확인/제출 완료 근거는 아직 추가하지 않았습니다.
- 2026-10-12: PM 실행 `107696ce-4257-4243-aa2b-a14300ea11be`에서 실제 브라우저로 Google Search Console의 `Start now`와 네이버 서치어드바이저 콘솔을 열었습니다. Google은 `accounts.google.com`의 `Email or phone`, 네이버는 `nid.naver.com`의 `ID or phone number`·`Password` 로그인 화면으로 이동했습니다. 현재 관리 브라우저에는 정상 회사 로그인 세션이 없어 속성·HTML 확인 값·제출 화면에 접근하지 못했습니다. 계정 주소나 비밀값은 기록하지 않으며 개인계정 차용·인증 우회·임의 확인값 삽입은 하지 않았습니다.
- 다음 실행 조건: 기존에 선택한 회사 운영자 Google 계정과 정상 회사 네이버 계정의 인증된 접근을 확보하면 URL 접두어 속성·HTML 태그 소유 확인→기존 sitemap 제출→실제 응답 기록 순서로 실행합니다. 확인 값이 없는 상태에서 가짜 태그나 제출 완료를 만들지 않습니다. 무료 등록 재승인은 필요하지 않습니다.
