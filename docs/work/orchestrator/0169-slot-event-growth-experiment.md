# 0169 첫 크리링 완성 챌린지 기획과 자사 캠페인

- 단계: 티켓
- 역할: orchestrator
- 상태: 분류 대기
- 종류: 기능
- 우선순위: P1
- 작성일: 2026-10-11

## 목적

새 캠페인 후보 **첫 크리링 완성 챌린지**를 기획합니다. “목적 고르기→직접 대표 링크 등록→본인의 프로필 공유 준비”의 자발적 3단계로 첫 가치를 경험하게 하는 자사 사이트 캠페인입니다. 참여에 새 금전/경품 보상이나 외부 게시 의무를 걸지 않습니다. 기존 신청자 한정 슬롯 +5 이벤트(R24)는 별도 선택 가능한 현행 혜택으로 소개하고 조건을 변경하지 않습니다. `0168`과 같은 화면/기간에 영향을 주는지 조사하고 중복 실험을 피한 뒤 분류합니다.

## 수용 기준

- [ ] Events/Lifecycle와 Product가 참여 동기·유사 온보딩 캠페인·현재 사용자 장벽을 조사하고, 자율 3단계 챌린지/기존 이벤트 안내만 개선하는 대안의 추천 이유·측정/중단 조건을 보고합니다.
- [ ] 캠페인의 대상·참여 동선·자사 안내 소재·게시 기간을 설계하고 성장 가설을 PRD/설계로 확정합니다. 실제 시행 결정 뒤 기간을 명시하고 허위 마감·참여자 수를 만들지 않습니다. 무료 외부 게시는 현행 규칙·접근 조건을 확인한 뒤 PM이 자율 실행하며 지출/결제만 사전 사람 승인 필수입니다.
- [ ] 선택한 구현은 기존 홈/관리 화면/사용 안내 경로를 재사용하며 새 참여자 공개 명단·개인정보·DB 참여 상태를 도입하지 않습니다. 현행 슬롯 이벤트를 소개하면 기본 5개에서 +5·계정당 한 번·현재 종료 여부를 실제 상태에 맞게 설명합니다.
- [ ] 신청은 사용자의 명시적 행동이며 자동 신청·자동 보너스 부여·추가 개인정보 수집·새 보상/추첨·좋아요/팔로우 조건·외부 DM/이메일은 없습니다.
- [ ] 신청 전후에 실제 첫 링크 만들기 동선을 안내하고 기존 오류·이미 신청·이벤트 종료 상태를 보존합니다. 기존 보너스와 운영자 수동 슬롯을 혼동하거나 중복 부여하지 않습니다.
- [ ] `0164`·`0168`의 변경 화면·배포/관측 시각과 비교해 중복 영향과 측정 한계를 기록한 뒤 준비로 전환합니다. 필요하면 같은 화면 변경은 한 실험의 관측이 끝날 때까지 대기합니다.
- [ ] localhost 실제 화면/신청 상태와 기존 서버의 한 번만 부여 계약을 확인하고 CI→guard→Deploy 근거를 남깁니다. 보너스 회수는 롤백으로 사용하지 않습니다.
- [ ] 배포 전후 7일 이벤트 신청 수·실사용자 수를 기록합니다. 신청자별 활성화·재방문 집계가 없으면 미관측이며, 신청 증가만으로 실사용자 증가를 주장하지 않습니다.

## 팀별 과제

- Events/Lifecycle: 현행 혜택·조건·자발적 신청·첫 링크 연결 시나리오.
- Growth/Marketing: 자사/외부 채널용 사실 기반 안내 소재. 무료 외부 게시와 비용 없는 보상 조건은 PM이 준수/접근·제품 계약으로 판단하며 지출/결제만 사람 승인으로 분리합니다.
- Product/Web: 신청에서 실제 링크 작성으로 이어지는 UX와 대안 비교.
- API/Data: 기존 한 번 신청·보너스 합산 계약과 측정 가능 지표 검토. 집계 공백을 사실로 보고.
- SRE/Security/QA: 출시/되돌림·보상 오표시·중복 신청·개인정보·권한 검토.

전담 `crelink-pm`이 팀별 조사·보고·실제 구현/홍보를 통합합니다. 무료 회사 계정·홍보 자체를 승인 대기로 두지 않습니다. 이 과제의 현재 범위를 넘는 새 추첨·개인정보 수집은 구현에 몰래 포함하지 않으며 지출/결제/비용 약정은 사전 사람 승인, 법·약관·동의·권한은 실행 조건으로 구분합니다.
