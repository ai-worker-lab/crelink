# 0087 가입 유입 경로 기록(광고 배너 가입 전환 측정)

- 단계: 티켓
- 역할: product
- 상태: 분류 대기
- 종류: 기능
- 우선순위: P2 (AI 제안)
- 작성일: 2026-10-09

## 목적

첫 크리링 광고 배너(0086)는 가입 유도용입니다. 지금은 배너별·랜딩별 노출·클릭만 셉니다(`ad_banner_daily_stats`, PRD R20 ⑧). 클릭한 사람이 실제로 가입했는지는 알 수 없습니다. 광고 클릭 주소 `{SHORT}/a/{배너}/{랜딩}`은 저장된 URL로 302할 뿐이고, 가입 때 어디서 왔는지 기록하는 요구가 PRD에 없기 때문입니다. 그래서 배너 문구나 위치를 바꿔도 가입이 늘었는지 판단할 수 없습니다.

## 수용 기준

- [ ] PRD에 가입 유입 경로 기록 요구를 넣을지 사용자가 정합니다. 함께 정할 것: 기록 단위(배너·랜딩·외부), 보관 기간, 개인정보 처리방침 고지, 운영자 화면에서 보는 방식.
- [ ] 넣기로 하면 요구와 수용 기준을 PRD에 적고 구현 티켓으로 나눕니다(api·web, 영역이 여럿이면 orchestrator).

## 범위

- 포함: 요구 정리와 사용자 결정.
- 제외: 구현.

## 위험·복구

유입 경로를 가입 계정과 묶으면 광고 기록이 개인 단위가 됩니다. 지금 광고 기록은 개인 식별 정보 없는 합계뿐이라고 고지하고 있습니다(`apps/web/src/app/(public)/privacy/page.tsx` `크리링 광고 노출·클릭 수`). 따라서 처리방침과 R10을 다시 봐야 합니다. 법률 검토 전입니다.

- 설계: [광고 블록 기술 설계](../../specs/crelink-ad-banner.md) `노출·클릭 기록과 R7 ⑥`
