# 0235 API 테스트 Jest 워커 수 제한

- 단계: 티켓
- 역할: api
- 상태: 검증
- 종류: 유지보수
- 우선순위: P2
- 작성일: 2026-11-10

## 목적

`apps/api`의 `jest` 설정에 워커 제한이 없어 12코어 개발 기기에서 기본값 11개가 뜹니다. 여러 worktree 작업이 겹치면 워커 메모리가 쌓여 스왑과 메모리 압박을 키웁니다. 테스트 시간을 늘리지 않는 범위에서 워커 수를 제한합니다.

## 수용 기준

- [x] `apps/api` 테스트의 워커가 최대 2개만 뜹니다.
- [x] 통과 수가 변경 전과 같습니다(33개 스위트, 281개 테스트).
- [ ] 캐시 없는 실행의 워커 메모리 최댓값이 약 3 GiB 이하이고, 소요 시간이 변경 전보다 늘지 않습니다.

## 범위

- 포함: `apps/api/package.json`의 `jest.maxWorkers`, 백엔드 변경 기록.
- 제외: 다른 패키지의 테스트 설정, `ts-jest` 변환 방식, 테스트 내용, CI 설정.

## 위험·복구

운영 코드와 데이터에 영향이 없습니다. 테스트가 늘어 시간이 문제가 되면 `maxWorkers` 값을 올리거나 줄을 지웁니다.

## 연결

- `apps/api/package.json`

## 진행 기록

- 2026-11-10: 생성. MacBook Monitor 기록에서 00:22, 05:34에 `crelink-worktrees/*/apps/api`의 node 11개가 같은 부모로 실행된 것을 확인했습니다.
- 2026-11-10: `make infra-up`과 `pnpm --filter @crelink/shared build` 뒤 `jest --no-cache`로 측정했습니다. 워커 메모리는 1초 간격으로 표본을 뜬 RSS 합계의 최댓값이며, 공유 메모리가 겹칠 수 있습니다. 소요 시간은 초 단위입니다. 4개는 2회, 나머지는 1회 측정했습니다. 모든 실행에서 33개 스위트, 281개 테스트가 통과했습니다.

| 워커 | 소요 시간 | 워커 메모리 최댓값 |
| --- | --- | --- |
| 11(기본값) | 17초 | 6.75 GiB |
| 4 | 13초, 14초 | 4.41 GiB, 4.18 GiB |
| 3 | 14초 | 3.46 GiB |
| 2 | 17초 | 2.53 GiB |

- 2026-11-10: 수용 기준의 메모리와 시간을 함께 만족한 값이 2개뿐이라 `maxWorkers`를 2로 정했습니다.
- 2026-11-10: 설정 파일 값으로 `jest --no-cache`를 다시 실행했습니다. 워커 2개, 33개 스위트와 281개 테스트 통과, 워커 메모리 최댓값 2.55 GiB, 18초입니다. 메모리 기준은 충족했지만 시간은 변경 전 17초(1회)보다 1초 많아 세 번째 수용 기준은 체크하지 않고 검토에 넘깁니다. 측정 단위가 1초이고 횟수가 적어 차이가 실제인지는 확정하지 못했습니다.
- 2026-11-10: `pnpm verify` 통과(8개 단계, 실패 0, `test` 포함). `pnpm work:check`, `pnpm work:scope 0235` 통과. 코드 경로를 바꾸지 않아 `make up`과 `pnpm smoke`는 실행하지 않았습니다.
