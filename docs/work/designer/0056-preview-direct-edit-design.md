# 0056 페이지 편집 새 컨셉(미리보기 직접 편집)과 프로필 메뉴 분리 디자인

- 단계: 티켓
- 역할: designer
- 상태: 완료
- 종류: 기능
- 우선순위: P2 (AI 제안)
- 작성일: 2026-10-08

## 목적

0051·0053에서 만든 `페이지 편집` 메뉴는 공개 랜딩 순서대로 고정 카드 5개(프로필 → SNS 채널 → 외부 링크 → 포트폴리오 → 방명록)를 세로로 쌓고 옆에 실시간 미리보기를 둡니다. 사용자는 이 화면의 컨셉을 다시 정하기로 했고(2026-10-08), 세 선택지 중 **미리보기 직접 편집**을 골랐습니다: 휴대폰 미리보기를 화면 중심에 두고, 미리보기 안 구역을 누르면 옆 패널이 그 구역 편집 폼으로 바뀝니다. 함께 **프로필(사진·이름·소개)과 SNS 채널을 `페이지 편집`에서 빼 별도 메뉴**로 둡니다.

## 수용 기준

- [x] OpenDesign 시안이 1280px에서 미리보기 중심 배치를 보여 주고, 미리보기 안 구역(외부 링크·포트폴리오, 방명록 탭)을 고르면 편집 패널이 그 구역 폼으로 바뀐다. 고른 구역 표시(선택 테두리 등), 아무것도 고르지 않은 처음 상태, 키보드로 구역을 고르는 방법이 있다.
- [x] 프로필·SNS 채널을 다루는 별도 메뉴가 있고(메뉴 이름·순서·주소 제안 포함), `페이지 편집`에는 링크·포트폴리오(·방명록 켜기)만 남는다. 미리보기에서 프로필 머리를 누르면 어떻게 되는지(그 메뉴로 이동 등) 정해져 있다.
- [x] 지금 관리 화면 기능을 빠짐없이 다룬다: 외부 링크 추가·수정·삭제·끌어 정렬·숨기기·한도(R13)·차단(R14), 포트폴리오 추가·수정·삭제·순서, 프로필, SNS 채널, 방명록 켜기, 저장 안 함·저장 중·저장 실패·빈 랜딩 상태.
- [x] 1023px 이하(390px 확인)에서 미리보기 직접 편집을 어떻게 쓰는지(구역 누르면 하단 시트 등)와 320px 가로 넘침 없음이 시안과 `handoff.md`에 있다.
- [x] `handoff.md`에 지금 구현(0053)과 달라지는 점, PRD R18 변경 필요 여부, 새 API 필요 여부(기술 검토)가 있다.
- [x] 사용자가 시안을 승인한다.
- [x] `pnpm design:check --require-lint`가 통과한다.

## 범위

- 포함: 관리 화면 정보 구조(메뉴 구성 변경), `페이지 편집`·새 프로필 메뉴의 PC·휴대폰 배치와 상태, 인계 문서.
- 제외: 웹 구현(승인 뒤 web 또는 orchestrator 티켓), 구역 순서 자유 배치·새 블록 종류·꾸미기(테마)(블록 목록 컨셉은 고르지 않음), `의견 보내기` 위치(0057에서 오른쪽 아래 떠 있는 버튼으로 구현).
