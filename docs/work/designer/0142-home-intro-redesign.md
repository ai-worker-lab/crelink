# 0142 홈 소개 화면 보강 디자인

- 단계: 티켓
- 역할: designer
- 상태: 완료
- 종류: 기능
- 우선순위: P1
- 작성일: 2026-10-10

## 목적

로그인 전 홈(`apps/web/src/app/(public)/page.tsx`)은 제목 한 줄, 설명 한 줄, `구글로 시작하기` 버튼뿐입니다. 처음 온 사람이 크리링 랜딩이 어떻게 생겼는지, 무엇이 무료인지 알 수 없습니다. 커뮤니티·검색·랜딩 하단에서 들어온 사람이 홈에서 가입을 정하므로, 홈이 모집 채널 모두의 도착지입니다([조사](../../product/research/initial-user-acquisition.md#결론)).

## 수용 기준

- [x] 홈 시안에 예시 랜딩 모습, 사용 3단계(가입 → 링크 추가 → 인스타그램 프로필에 주소 넣기), 무료로 주는 것(단축 주소·주소 변경·외부 링크 5개), 가입 버튼이 있습니다.
- [x] R24 이벤트 안내 자리(0089에서 만드는 홈 안내)와 겹치지 않고 함께 놓입니다.
- [x] 로그인한 사람의 홈(지금의 `내 크리링 편집`)은 바뀌지 않거나 바뀌는 점을 인계에 적습니다.
- [x] 390px·1280px 시안과 인계 문서(`design/<기능>/handoff.md`)가 있습니다.

## 범위

- 포함: 로그인 전 홈 시안과 인계.
- 제외: 구현(web 티켓으로 나눔), 예시 랜딩에 실제 크리에이터 데이터를 쓰는 것(허락 없이 쓰지 않음).

## 위험·복구

해당 없음.

## 진행 기록

- 2026-10-10: 생성(0090 조사에서 발견, 분류 대기). 사용자 위임(2026-10-10, 에픽 0088 진행 기록)에 따라 시안 승인은 AI가 할 수 있습니다.
- 2026-10-10: 분류·착수·완료(사용자 위임(2026-10-10, ADR 0015)에 따른 AI 승인, AI 운영자 실행 `a5b8316a-a04a-44f5-b862-0060d613d60f`). 근거: 실사용자 0/100, 7일 방문 3. 가이드 글(0146)·랜딩 바닥글(0151)·모집 문안(0145)이 모두 홈으로 데려오는데 홈은 제목·설명·버튼뿐이라 우선순위 `P1` 확정.
  - 산출물: [`design/home-intro/index.html`](../../../design/home-intro/index.html)(상태 A 이벤트 없음·B 이벤트 있음 1280·390px, C 320px, 버튼 상호작용, D 로그인한 홈 그대로, E 로그인 확인 오류), [`handoff.md`](../../../design/home-intro/handoff.md), `design/system/DESIGN.md` 로그인 전 홈 소개 규칙·주요 버튼 예외 한 줄.
  - 결정: 제목·설명·첫 `구글로 시작하기`는 지금 자리 그대로, 그 아래(1024px 이상은 오른쪽)에 가상의 `예시 크리에이터` 랜딩(늘 보이는 `예시 화면` 표시·캡션, 틀 안 `aria-hidden`·`inert`) → 3단계 → 무료로 쓸 수 있어요(외부 링크 `CRELINK_LIMITS.freeVisibleLinks`, 주소 변경 `slugChangeIntervalDays`·옛 주소 `retiredSlugGraceDays`) → 마지막 `구글로 시작하기`. 이벤트 카드는 지금 자리 한 곳만. 로그인한 홈은 바꾸지 않음. 쿼리 없음(0087 이후 제안만).
  - 검증: `pnpm design:check --require-lint` 통과(새 시안 알림 없음, 기존 P2 6건만), `pnpm tokens:generate`·`pnpm design:sync` 생성물 변경 없음. 운영 화면은 열지 않음.
  - 승인: 디자인 승인(AI 승인). 구현은 [0154](../orchestrator/0154-home-intro-web.md)로 넘겼습니다(`tests/e2e/slot-event.spec.ts` 72행 `구글로 시작하기` 단언이 링크 두 개로 strict 위반이 되므로 같은 변경에서 고침).
