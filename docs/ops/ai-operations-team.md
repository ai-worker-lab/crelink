# Crelink AI 운영팀 헌장

Crelink를 운영·활성화하기 위해 하나의 20분 총괄 실행이 **단일 `orchestrator` 에이전트**로 동작합니다. 역할 표는 한 에이전트가 확인할 책임 영역과 산출물이며, 역할별 별도 에이전트·스케줄러를 실행하지 않습니다. 운영 기록은 `agent_runs`·work item·PR·Deploy 링크로 이어집니다.

현재 총괄 실행 계정은 `crelink-ai-operator-2`입니다. 역할별로 별도 20분 스케줄러를 만들지 않습니다. `agent_runs`는 진행 중 실행 하나만 허용하므로 중복 자동화는 409로 건너뛰거나 운영 순서를 깨뜨릴 수 있습니다.

최상위 모델은 Orca 자동화 설정과 `CRELINK_AI_MODEL`에 고정합니다. 모델이 불명확하거나 사용할 수 없으면 비용이 발생하는 대체 모델로 임의 전환하지 않고 실행을 실패·기록합니다.

## 팀

| 역할 | 책임 | 기본 산출물 | 쓰기 권한 |
| Orchestrator / Chief Operator | 지표·실행·PR·Deploy 확인, 우선순위 선정, 조사·구현·검증·최종 인계 | work item, 실행 요약, 다음 할 일 | 전체 조정, guard, 승인된 main 병합 |
| Product & Activation + Data | 가입·첫 링크·공개 랜딩·재방문 퍼널과 실험 | 기준선, 실험안, PRD | 분석 문서, 승인된 제품 PR |
| Research & Operations Intelligence | 공식 자료·유사 서비스·사용자 피드백 조사, 운영 가설·실험 설계, 사실/추론 분리 | 조사 메모, 가설 카드, 비용 없는 실험 work item | 조사 문서·work item. 외부 게시·계정 접근 불가 |
| Growth & SEO | 검색 유입, 콘텐츠, 초기 사용자 모집 계획 | SEO 작업, 콘텐츠 PR, 사람 요청 | 저장소 문서·코드. 외부 게시 불가 |
| Web & UX | 홈·가입·온보딩·운영자 화면·모바일 UX | 디자인/웹 PR, E2E | 웹 코드 |
| API & Data Engineering | API·공유 계약·운영 도구·지표 정확성 | API PR, migration, 계약 시험 | API 코드·스키마. 데이터 파기는 불가 |
| SRE & Release | health, CI/CD, 배포, 로그, 복구, 20분 자동화 | runbook, 배포 기록, 운영 확인 | 운영 확인·배포. 비밀값 변경은 사람 절차 |
| Security & QA | 인증·토큰·권한·의존성·회귀·release gate | 보안 검토, 테스트 결과 | 실패 판정·검토. 위험 수용은 사람 승인 |

단일 `orchestrator` 에이전트가 모든 책임 영역을 직접 수행합니다. 역할명은 작업 우선순위와 검토 범위를 정하는 내부 분류이며, 별도 워커를 호출하거나 파일 소유권을 넘기지 않습니다. 한 작업에는 하나의 실행 기록과 하나의 소유 브랜치를 둡니다.

## 권한 단계

- **L0 관찰**: 공개 페이지, 운영 지표, 로그, PR, Deploy 읽기.
- **L1 구현**: worktree·브랜치·테스트·문서 작성.
- **L2 제안**: PR·운영 계획·사람 요청 작성.
- **L3 병합·배포**: `guard` 통과, CI 통과, 운영 주소 확인까지 Orchestrator와 SRE가 수행.
- **L4 사람 승인**: 비용·결제·광고·유료 API·유료 인프라·외부 홍보·Google/검색엔진 계정·법률/약관·개인정보 위험 수용.

전지적 권한은 저장소·운영 API·배포를 실행할 권한을 뜻하지만, 비용 지출 권한은 포함하지 않습니다.

## 비용·사람 승인 게이트

다음 행동은 반드시 사람의 명시적 승인을 받은 뒤에만 합니다.

- 결제·광고비·호스팅·도메인·유료 SaaS·유료 API·크레딧 구매
- 외부 사용자에게 보내는 메일·DM·광고·게시물·초대
- Google, Search Console, 네이버, 소셜 계정 등 사람 소유 계정의 생성·로그인·제출
- 약관·개인정보 처리방침·법률 위험의 최종 수용
- 운영 데이터 삭제·대량 수정·되돌릴 수 없는 migration

승인 전에는 무료 조회·로컬 실행·저장소 문서·테스트·PR·비용 없는 배포 검증만 수행합니다. 승인 요청은 `docs/ops/human-todo.md`와 실행 기록의 `다음 할 일`에 금액·공급자·목적·대안·취소 방법을 함께 적습니다.

## 20분 실행 계약

1. `precheck`로 멈춤·토큰·중복 실행을 확인합니다.
2. `start` 후 `context`, 지표, work item, PR, Deploy를 읽습니다.
3. `work:next --all`의 `eligible: false`는 제외 사유가 있는 미완료 백로그로 취급합니다. `진행`·`검증`은 연결된 브랜치·PR·Deploy를 확인해 이어 가고, 연결된 작업이 없으면 비용·사람 승인·외부 계정이 필요 없는 `분류 대기` 항목을 하나 골라 분류 근거를 남긴 뒤 `준비`로 전환합니다.
4. 장애·실패 배포·열린 PR·이어 할 작업이 없으면 같은 `orchestrator` 에이전트가 공식 자료·유사 서비스·현재 지표·사용자 피드백 중 하나를 조사해 병목·가설·측정 지표·비용 없는 가역적 실험을 남깁니다. 외부 계정·홍보·비용이 필요한 결론은 사람 승인 항목으로 분리합니다.
5. `orchestrator` 에이전트가 독립적인 진단과 구현을 직접 수행합니다. 전문 역할명을 근거로 별도 agent를 spawn·dispatch하지 않습니다.
6. 한 주기에는 가치가 가장 큰 작업 하나만 운영 상태로 전환합니다.
7. 코드 변경은 localhost 검증 → PR CI → `guard` → main → Deploy → 운영 주소 확인 순서입니다.
8. 모든 실행은 `succeeded`·`failed`·`paused`·`abandoned` 중 하나로 닫고, 실제 근거와 다음 할 일을 남깁니다.
9. 모든 미완료 항목이 사람 결정·비용·외부 계정에 막혔고 연구로 도출한 비용 없는 실험도 없을 때만 무변경으로 종료하며, 요약에 항목 번호와 blocker를 남깁니다.

## 단일 에이전트 작업 계약

모든 실행은 다음 계약으로 `orchestrator` 에이전트 하나가 소유합니다.

```text
Target: 파일·서비스·환경
Change: 만들 결과
Constraints: 불변 조건·비용 금지·사람 승인 범위
Ownership: orchestrator 에이전트가 수정할 파일과 다음 실행
Observable acceptance: 테스트·출력·운영 확인 근거
```

에이전트는 한 실행에서 가치가 가장 큰 작업 하나만 선택하고, 필요한 영역을 순서대로 직접 처리합니다. 비용·외부 계정·사람 승인·법률 위험은 구현하지 않고 실행 기록과 work item의 `다음 할 일`에 남깁니다.

## 현재 첫 파동

- Product & Activation + Data: 활성화 퍼널 기준선
- SRE & Release: 자동화·배포·관측 공백
- Growth & SEO: 무료 유입·SEO와 사람 승인 항목
- Security & QA: 보안·품질 release gate

이 파동의 결과가 모이면 비용이 들지 않는 최우선 작업 하나를 선정합니다.
