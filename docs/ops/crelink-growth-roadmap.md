# Crelink 팀별 성장 로드맵

## 목적과 근거

신규 사용자에게 **협업 문의용 프로필을 직접 완성하는 가치**, 기존 사용자에게 **새 대표 작업을 반영해 프로필을 다시 쓸 가치**를 제공하는 실행 계획입니다. 아래 기능·콘텐츠·캠페인은 구현 완료나 수요 검증 결과가 아니라, 근거와 실행조건에 따라 PM이 선택할 후보입니다. 유지보수·배포 점검·보안 검사는 선택한 성장 과제의 출시 조건이며 그 자체를 성장 성과로 포장하지 않습니다.

- 운영 책임·권한·20분 실행 원본: [AI 운영팀 헌장](ai-operations-team.md).
- 초기 선택과 조사 근거: [팀별 그로스 조사](../product/research/crelink-growth-team-research.md), 확인일 **2026-10-11**. 그 문서의 `2026-10-11T12:42:52.351Z` 관측 **실사용자 0 / 100**은 과거 기준선이며 현재값이나 성장 예측이 아닙니다. 이 로드맵에서 운영 지표를 새로 조회하지 않았습니다.
- 제품 범위·실사용자 정의·보상 조건 원본: [Crelink PRD](../product/crelink.md)의 `목표`·R23·R24. 100명 목표에는 확정 기한이 없습니다.
- 초단기 첫 선택: [0168 협업 문의용 크리에이터 시작 키트](../work/orchestrator/0168-creator-starter-kit.md). 다음 후보: [0169 첫 크리링 완성 챌린지](../work/orchestrator/0169-slot-event-growth-experiment.md).
- 외부 채널·실행 문안·측정 한계 원본: [모집 실행 문안](../product/acquisition-playbook.md). `0153`의 과거 승인 요청·실행 기록은 보존하되 무료 홍보의 재승인 요청으로 재사용하지 않고 PM 실행안에 연결합니다.
- **2026-10-12 권한 변경:** 무료 외부 홍보는 PM 자율 실행, 사전 사람 승인은 실제 지출·결제·유료 구독/크레딧·비용 발생 약정에만 필요합니다. 현재 권한 원본은 [운영 헌장](ai-operator.md)입니다. 이는 권한 이관이며 플랫폼 재조사·외부 게시·현재 지표 조회를 수행했다는 기록이 아닙니다.

## 실행 계약과 우선순위

### 기간은 착수 이후 목표 구간

| 기간 | 목표 구간 | 단계 산출물과 진입 판단 |
| --- | --- | --- |
| 초단기 | 0~48시간 | `0168` 범위·설계·자사 가이드·구현/검증 근거를 준비하고, 출시 가능 여부를 판정합니다. `0169`는 동기·대안·중복 영향 조사까지 연결합니다. 시간 도달만으로 출시하지 않습니다. |
| 단기 | 3~7일 | 실제 배포가 있으면 그 배포 기준의 관측을 시작하고 타깃 콘텐츠·규칙과 접근 조건을 충족한 무료 채널 하나를 PM이 준비/실행합니다. `0169`는 선행 실험과의 충돌 해소 후 선택합니다. |
| 중기 | 2~4주 | 실제 피드백·관측 공백을 정리하고, 차별화 기능·재방문 캠페인 중 근거가 있는 후보 하나를 설계/출시합니다. 표본 부족이면 연구·모집 경로를 재설계합니다. |
| 장기 | 2~3개월 | 관측된 사용자 가치가 있는 타깃/자산을 확장하거나, 근거가 없으면 타깃·가설을 전환합니다. 100명 도달이나 특정 전환율을 약속하지 않습니다. |

구간은 달력 납기·8팀 동시 착수 약속이 아닙니다. 선행 작업·관측·접근 조건 또는 비용 승인이 늦어지면 다음 구간도 재계획합니다. 배포 후 7일 점검은 실제 배포 시각부터 계산하므로 단기 구간 안에 억지로 완료하지 않습니다.

- **P0 — 조건부 차단/필수 선행**: 실제 장애·보안 위험·데이터 오염·출시 차단, 또는 선택한 단계에 꼭 필요한 선행 조건만 해당합니다. 표의 P0는 발동 조건을 포함합니다. 조건이 없으면 **해당 없음**으로 기록하고 정상 성장 P1을 진행합니다. P0라는 표기만으로 비용 승인·안전/접근 조건을 우회하거나 전문 워커에게 운영 쓰기를 허용하지 않습니다.
- **P1 — 정상 성장 선택**: 신규 기능·타깃별 콘텐츠·새 캠페인·재방문 가치에 직접 연결된 기본 후보입니다. 첫 선택은 `0168`; `0169`는 추천 근거와 중복 영향 확인 후 다음 후보입니다.
- **P2 — 후속/탐색**: 당장 구현하지 않아도 되는 대안·자료·확장 연구입니다. P1 측정 대기 중 비용 없는 조사/소재 준비는 가능하지만, 같은 화면을 다시 바꾸어 관측을 흐리지 않습니다.

### 담당 책임과 한 cycle의 첫 선택

8팀은 [헌장](ai-operations-team.md)의 **실제 프로젝트 실행팀**입니다. 중앙 `orchestrator`는 회사/포트폴리오 우선순위·비용 승인·충돌을 조정하고 `crelink-pm`이 기존 20분 스케줄·한 실행 기록에서 **성장 과제 하나**를 선택·감독합니다. Product=`product`(+`designer`), Research=`crelink-research`, Growth=`crelink-growth`, Events=`crelink-events`, Web=`web`(+`designer`), API=`api`, SRE=`infra`, QA=`crelink-qa`를 필요할 때 Orca provider `omp`·명시 모델 `openai-codex/gpt-6.1-sol`로 호출하며 Task가 해당 역할 파일을 읽게 합니다. 상시 8워커·팀별 스케줄러는 없고 활성 전문 워커는 최대 2명, 수정 경로 비중첩·실제 선행 조건을 지킵니다. 운영 자격·쓰기·병합/배포·외부 게시/발송·서버 `start`/`finish`는 PM만 소유합니다. 전문 워커는 조사·문안·로컬 검증과 실행 인계를 맡고 운영 credentials를 전달받지 않습니다. 실제 장애/보안 예외면 성장 과제를 중단/재계획합니다.

1. 멈춤·토큰·중복 실행, 현재 티켓/PR/Deploy, 선택 후보의 최신 근거를 읽습니다.
2. 조건부 P0 발동 여부를 판단합니다. 장애가 없으면 `0168`의 다음 미완료 수용 기준을 우선 선택합니다. 완료/비용 승인/접근 조건/측정 대기이면 `0169` 또는 타깃 자산의 안전한 다음 행동을 비교합니다.
3. 대상·사용자 가치·근거·반증 조건·안전/접근 조건·비용 승인 필요 여부·되돌림을 적고 15분 안에 검증/인계 가능한 작은 Task와 관측 가능한 수용 기준으로 나눕니다. 후반에는 새 착수를 멈추고 결과·질문·settlement를 처리합니다. 시계에 맞추려고 live/검증 불가 워커를 삭제하지 않으며 미정산 소유권·ID·blocker를 다음 실행으로 넘깁니다. 여러 기간/팀의 P1을 한꺼번에 운영 상태로 전환하지 않습니다.
4. 초기 PM은 `0168`·`0169`의 미완료 수용 기준을 인계받습니다. 조사는 필수 선행이지 이미 조사된 구현의 대체가 아닙니다. 실제 산출물·실행 역할/Task/Dispatch·검증 여부·분모·다음 관측일·blocker를 티켓/실행 기록에 남기며 출시를 미리 주장하지 않습니다. 심층 조사 순환은 기존 연구/구현 진행을 막지 않으며 정상 실행 8회 안에 모든 팀의 새 근거를 확인하는 계약을 따릅니다.

**상태 원본은 work item의 `상태` 줄**입니다. 아래 96개 우선순위 셀은 계획이며 96개 새 티켓이 아닙니다. `0168`·`0169`와 기존 관련 티켓에 산출물을 연결하고, 실제로 선택한 별도 기능만 기존 분류 절차로 등록합니다. 이 문서에 경쟁 상태표·완료 체크박스를 만들지 않습니다.

### 승인과 중단의 공통 경계

- 저장소 조사·localhost 구현/시험·자사 콘텐츠 PR은 기존 권한 안에서 진행합니다. 출시에는 localhost → PR CI → guard → main → Deploy → 운영 주소 확인 근거가 필요합니다. main 병합은 운영 배포입니다.
- **사전 사람 승인 경계는 실제 지출·결제·유료 광고/API/인프라·구독/크레딧·비용 발생 약정뿐**입니다. 무료 외부 게시·모집·설문·합법적이고 수신 동의된 개별 DM/이메일·회사 계정/채널·검색엔진 등록은 PM이 자율 결정·실행합니다. 플랫폼이 허용하는 무료 회사 계정 구성도 포함하며 접근 불가는 비용 승인 대기가 아닌 인증/접근 blocker입니다. 기존 R24 비금전 보너스 운영은 그대로 진행하고, 비용 없는 새 슬롯/이벤트 조건은 PRD·제품 결정 절차로 확정합니다.
- 법·약관·수신 동의·개인정보·저작권·사칭/스팸 금지·인증/멈춤 통제·운영 데이터 파괴 금지는 실행조건/금지이며 사람 승인으로 우회할 수 없습니다. 사람 개인계정 사칭·비밀값 전달/공개·CAPTCHA/OTP 우회를 금지합니다. 플랫폼 허용 여부가 불명확하면 그 경로만 fail closed하고 규칙 조사·합법적인 무료 대체 경로를 계속합니다.
- 비용 요청에는 대상·완성 문안/화면·채널/횟수·금액/공급자·목적·대안·측정법·철회 방법을 포함합니다. 무료 실행안에는 실제 채널 규칙/확인 근거·접근/동의·비용 상태(미확인과 0 구분)·관측/철회 방법을 남기며 PM이 guard와 근거를 확인한 뒤 실행합니다. 결과 원본은 확인 가능한 공개 URL·실행 시각·제출/공개 구분·철회/관측 기록이고 준비를 실행으로 보고하지 않습니다.
- 가입/편집 차단·권한 누출·지표 오염·잘못된 슬롯 부여·가상 예시 오인·보상 사실 불일치가 있으면 관련 변경을 멈추고 복구/롤백 근거를 남깁니다. R24의 이미 부여한 보너스를 회수하는 것을 롤백으로 삼지 않습니다.
- 한 운영자의 실행 용량을 넘거나 CI/localhost 부하가 관측되면 새 착수를 멈추고 작업 범위/순서를 줄입니다. 표본 부족·분모 부재·비용 승인/접근 지연은 장애가 아니며, 원인에 맞춰 조사·타깃·모집·관측 구간을 재계획합니다.

## 팀별 4기간 × P0/P1/P2

각 셀의 `→` 뒤는 실제로 남길 산출물이며, `완료`는 그 셀의 완료 조건입니다. 해당 조건을 확인하지 않은 항목은 완료·출시·성과로 보고하지 않습니다. 마지막 열의 KPI는 **관측할 값/정의**이며 근거 없는 수치 목표가 아닙니다.

### 1. Product/Activation

| --- | --- | --- | --- | --- |

- **중단/재계획:** 원격 대상·cleanup 범위 불명·분류 누락이면 mutation 전에 중단. 시험 부족이면 출시를 보류하며 가상 persona로 실제 사용자 모집을 대체하지 않습니다.

## 가상 persona QA와 실사용자 관측의 분리

### 시험 경계

가상 persona는 정상 사용·edge·모의 상황을 재현하는 **QA 도구**입니다. 합성 사용자의 완성/재방문/신청은 **사용자 수요 검증·실제 전환·모집 성과의 증거가 아닙니다**. 가상 예시는 실제 고객·후기·성과로 공개하지 않습니다.

| 분류 | 시나리오와 실제 확인 대상 | 결과의 의미 |
| --- | --- | --- |
| 정상 | 신규 크리에이터의 직접 링크 저장·프로필 열람, 기존 크리에이터의 편집 보존, 비회원 공개 열람 | 기능/계약이 동작하는지 확인. 제품을 실제로 원한다는 뜻은 아님. |
| edge | 잘못된 URL·슬롯 한도·다른 계정 권한·이벤트 종료/이미 신청·저장 실패·빈 상태 | 거부/오류 안내·데이터/슬롯 보존·노출 범위를 확인. 실제 발생 빈도는 별도 관측. |
| 모의 | 용도별 작성 흐름, 캠페인 신청 후 첫 링크 작성, 돌아와 대표 작업을 바꾸는 합성 흐름 | 연속 흐름의 결합/회귀 확인. 실제 이용 동기·참여 의사·재방문율은 검증하지 않음. |

- localhost **실제 API/DB**를 사용하며, 원격 URL/DB에서는 생성·수정·cleanup 이전에 fail closed합니다. 실제 사용자 생성·운영 쓰기·외부 발송·Google 계정/자격 증명 우회는 하지 않습니다.
- 시험 계정은 run별 고유값·`.test` 이메일과 기존 fixture/cleanup을 재사용하고 **`SeedOptions.metricsExcluded=true`가 기본이며 `users.metrics_excluded_at`을 생성 시 설정**합니다. `metricsExcluded: false`를 명시하는 경우는 localhost 지표 대조군 시뮬레이션에만 한정합니다. 이 대조군도 실제 사용자가 아니며 운영 지표/성과에 포함하지 않습니다. 실행법·계정 관리·시나리오의 원본은 [가상 사용자 테스트](../development/user-simulation.md)입니다.
- 실제 사용자 분류는 [PRD의 실사용자 정의](../product/crelink.md#목표)가 원본입니다. 운영자·AI·시험·정지 계정과 내용 없는 랜딩은 정의대로 제외합니다. 운영용 분류 schema/API를 이 계획으로 변경하지 않습니다.
- 시험 기록에는 실행 환경·run 식별값·분류·예상/실제 결과·실패·cleanup/잔여 데이터 여부를 남깁니다. 비밀값·실사용자 식별정보는 넣지 않습니다. 안전한 cleanup을 완료하지 못하면 잔여 범위/이유를 기록하고 운영 데이터 삭제로 해결하지 않습니다.

### 성장 관측과 재계획

1. 실제 출시가 있을 때만 배포 기준 시각·7일 뒤 점검일·안전 지표·중단/되돌림을 연결 티켓에 기록합니다. 실행하지 않은 시험/출시/관측은 미수행으로 남깁니다.
2. 기존 집계의 가입·첫 보이는 링크 생성자·이벤트 신청·실사용자 상태값을 각 정의대로 보고합니다. 홈/페이지/채널/참여자별 분모가 없으면 **미관측**으로 기록하고 0·전환율·인과 효과로 채우지 않습니다.
3. 초기 조사/`0168`의 기존 기준을 따라 첫 7일 지표 대상 가입자가 **5명 미만이면 표본 부족**입니다. 이는 통계적 유의성 기준/목표 전환율이 아니며, 5명 이상도 성공이나 원인 효과를 증명하지 않습니다.
4. 표본 부족이면 관측 구간·타깃·자사 자산·조건을 충족한 무료 모집 경로를 재계획합니다. 비용 승인 대기이면 비용 없는 대안, 접근/규칙 불명이면 해당 경로만 멈추고 규칙 조사/합법적 대체 모집, 실행 부하이면 범위 축소/순차 실행, 실제 안전 실패이면 중단/복구로 전환합니다. 모두 같은 사유로 장애/P0 처리하지 않습니다.
5. 유지·확장·보류·가설 전환 결정은 실제 근거/정보 공백과 함께 티켓에 남깁니다. 목표 전환율·검색량·성장 예측을 수치 근거 없이 만들지 않고, 다음 기간에 들어갔다는 이유만으로 성과를 선언하지 않습니다.
