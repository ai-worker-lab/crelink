# 가상 사용자·실사용자 분리와 시나리오 테스트

## 목적과 경계

가상 사용자로 정상 흐름·엣지 케이스·모의 상황을 반복 재현합니다. **가상 사용자 수·완료율·선호·재방문은 실제 모집·수요·성장 성과가 아닙니다.** [팀별 성장 로드맵](../ops/crelink-growth-roadmap.md)의 QA와 실제 사용자 리서치는 별개입니다.

- 원본: [`fixtures.ts`](../../tests/e2e/fixtures.ts), [`personas.spec.ts`](../../tests/e2e/personas.spec.ts), [`e2e-local.mjs`](../../scripts/lib/e2e-local.mjs), [기존 E2E 계약](../../tests/e2e/README.md).
- localhost의 실제 웹·API·PostgreSQL을 사용합니다. 운영 서버나 Supabase에 계정을 만들거나 Google 계정을 자동 등록하지 않습니다. fixture의 Google 신원/세션은 로컬 가입 결과를 재현하며 실제 OAuth 시험을 대체하지 않습니다.
- 웹·API·단축 URL은 HTTP(S), DB는 postgres(ql), 네 대상 모두 `localhost`·`127.0.0.1`·`::1`만 허용합니다. runner와 직접 Playwright fixture 모두 네트워크/DB 연결·stale cleanup 전에 검사합니다. 원격 대상 허용 옵션은 없습니다. localhost라는 이유로 운영 DB 터널/포트포워딩을 연결해서는 안 됩니다.
- 사용자별 `.test` 이메일은 가상 주소와 cleanup 소유권 표식이고, `metrics_excluded_at`은 지표 포함 여부입니다. 두 목적을 혼동하지 않습니다. 이메일 이름만 보고 지표가 자동 제외된다고 가정하지 않습니다.

## 분류와 관리

| 분류 | 생성·식별 | 지표·관리 |
| --- | --- | --- |
| 실제 고객 | 기존 Google 가입 경로, 사람이 실제 사용하는 계정 | [실사용자 정의](../product/crelink.md#목표)에 따라 집계. 임의 가상 계정을 실제 고객으로 보고하지 않음 |
| 가상 테스트 크리에이터 | `data.user()`·run별 이메일 `@e2e.crelink.test`, 시나리오 이름 `[SIM]` | **기본 `metricsExcluded: true`**. 생성 시 `users.metrics_excluded_at=now()`; 성장 대상에서 제외. 종료 시 이 실행 소유 행 정리 |
| 가상 지표 포함 대조군 | `data.user({ metricsExcluded: false })`, `.test` 주소·`[SIM 대조군]` 이름 | localhost에서만 실제 고객 집계 경로를 시험하기 위해 일시적으로 timestamp NULL. 실제 고객이 아니며 운영 성과에 포함하지 않음. 종료 시 정리 |
| 가상 사람 운영자 | `data.user({ role: 'operator' })` | 권한/관리 시나리오용 로컬 세션. 크리에이터 실사용자 집계 대상이 아님 |
| 가상 AI 운영자 | 기존 `data.aiAccount()` | `kind='ai'`, 기존 토큰·권한·실행 기록 시나리오. 실제 운영 토큰/실행을 사용하지 않음 |
| 익명 방문자 | `data.session()` | 사용자 행/가짜 가입을 만들지 않고 공개 열람/클릭을 재현 |

사람 운영자 화면 `/admin/creators/{id}`의 **지표 제외** 상태와 `지표에서 빼기`·`지표에 다시 넣기`가 기존 관리 계약입니다. 변경은 사람 운영자만 가능하며 행동 기록을 남깁니다. AI는 이 제어를 우회하지 않습니다. 운영의 기존 본인/지인 시험 계정은 사람이 표시해야 하며, 이 로컬 fixture 변경이 기존 운영 계정을 자동 재분류하지 않습니다.

기본 제외는 `realUsers`·가입·첫 보이는 링크 생성자·방문·링크 클릭의 성장 대상 필터에 적용됩니다. **전체 크리에이터 수에는 제외 계정도 들어가며 `creators.excluded`로 구분됩니다. 광고 집계는 현행 계약상 전체 집계**입니다([지표 구현](../../apps/api/src/ai-operator/metrics.service.ts)). 이를 모두 실제 고객 성과로 부르지 않습니다. 이번 변경은 운영 API/schema/광고 지표 정의를 바꾸지 않습니다. 로컬 테스트 결과는 운영 지표에 합산하지 않습니다.

## 가상 인물과 실행 시나리오

| ID | 가상 인물/상황 | 실제 시험·기대 결과 |
| --- | --- | --- |
| SIM-01 | 협업을 시작하는 지민, 익명 모바일 방문자, 운영 담당 민서 | UI에서 직접 첫 링크 저장→새로고침 후 보존→390px 공개 프로필→단축 방문·클릭 행 생성. 테스트 계정은 성장 집계 기준선에 변화 없음. 운영 상세에서 제외 상태 확인 |
| SIM-02 | 대표 작업을 공개하는 서윤(로컬 지표 포함 대조군), 지표 담당 민서 | 숨김 링크는 실사용자/첫 링크 집계 제외→공개하면 각각 1 증가→사람 운영자가 제외하면 기준선 복구→재포함하면 포함 집계 복구→다시 제외. 가입 지표와 활성화를 혼동하지 않음 |
| SIM-03 | 원작자 하린, 다른 사용자 도윤, 익명 사용자 | 다른 사람의 링크 수정 404·익명 쓰기 401·크리에이터의 지표 조회 403·위험 URL 400. 원작자의 링크 값과 개수 보존 |
| SIM-04 | 저장 후 다시 접속하는 유진 | 정상 세션 저장→세션 만료 재현→재시도 401. 마지막 성공 저장값 보존, 만료 뒤 쓰기 없음 |

페르소나별 시험은 기능/권한/분류의 확인입니다. 위 이름은 실제 고객·인터뷰 대상이 아닙니다. 미구현 키트/챌린지 기능을 시험 완료로 보고하지 않습니다.

### 기존 시나리오를 재사용하는 엣지 케이스

중복 테스트 대신 [기존 E2E 시나리오 목록](../../tests/e2e/README.md#시나리오)을 연결합니다.

- `creator.spec.ts`: 빈 계정, 링크 추가·숨기기(숨김 해제 한도 없음), 숨김 포함 50개 한도와 51번째 거부, 기존 편집/취소/정렬, 주소 변경 제한, 390px 편집.
- `ad-banner.spec.ts`: 광고 블록 플랫폼·크리에이터 스위치(둘 다 기본 꺼짐) 조합별 공개 랜딩 노출과 편집 화면 표시, 배너 슬롯 부여 계정 영향 없음.
- `guestbook.spec.ts`: 익명/작성자/소유자/다른 사람의 공개·비밀·숨김·삭제 권한.
- `notices.spec.ts`: 빈 프로필·없는 주소·정지 계정의 공개 안내.
- `ai-operator.spec.ts`: 토큰·실행·멈춤·사람 전용 권한 거부·감사 기록과 제외 관리.

## 실행

```sh
make up
pnpm e2e personas --project=personas --no-deps  # 네 모의 시나리오만
pnpm e2e                                      # 기존 정상/edge + 모의 시나리오 전체
node --test scripts/lib/e2e-local.test.mjs      # 원격/혼합 대상의 실행 전 거부

# Inspector에서 현재 시나리오를 단계별로 조작·검토
pnpm e2e personas --project=personas --no-deps --debug
```

주소/DB는 checkout의 `.local/instance.env`를 사용합니다([로컬 환경](local-environment.md)). 명령 전 네 값을 외부 환경변수로 덮으면 덮은 값 전체를 검사합니다. 비밀값이 있는 DB 연결 문자열을 공유 로그/문서에 출력하지 않습니다.

`playwright.config.ts`의 실행 순서는 `main → ad-banner → personas`입니다. 지표 포함 대조군을 다른 시나리오와 병렬 실행하지 않도록 `personas`는 별도 프로젝트/워커 하나로 마지막에 실행합니다. `--no-deps`는 페르소나만 로컬에서 재현할 때 사용하며 전체 회귀 통과를 뜻하지 않습니다. 같은 DB에 다른 검증 프로세스를 동시에 띄우지 않습니다.

## 결과와 수명

- 시나리오는 run별 임의 이메일·URL·ID를 생성합니다. 사용자의 실제 개인정보·운영 토큰·외부 대상은 복사하지 않습니다.
- CLI에 시나리오별 결과가 표시되며 `.local/e2e/test-results/`에 실패 trace와 SIM-01 관리/모바일 화면 첨부가 남습니다. 실제 요청/DB 기대 결과를 검증하고 실패 원인을 보고합니다.
- 종료 시 fixture는 만든 사용자·세션·링크·관련 감사/업로드 등 **이 실행 소유 행**을 정리합니다. 익명 방문자는 계정을 만들지 않습니다. 강제 종료 잔여 데이터는 다음 실행의 기존 stale cleanup이 `.test` 소유 표식과 1시간 경과 조건으로 처리합니다. 알 수 없는 사용자·운영 데이터를 일괄 삭제하지 않습니다.
- Inspector를 종료하면 시험 계정은 사라집니다. 가상 계정을 운영에 상시 배치하지 않습니다. 수동 검토는 Inspector의 살아 있는 세션과 로컬 `/admin`에서 수행합니다.
- 실행 기록에는 명령·환경(비밀값 제외)·시나리오 결과·실패·잔여 데이터 여부를 남깁니다. 시험 통과와 사용자 리서치/운영 성장 관측은 별도 보고합니다.
