# 저장소 공통 정책

언어, 기준 정보, 문서 배치, ADR, 진입점, 변경 기록에 관한 저장소 전체 정책의 원본입니다. 루트 [AGENTS.md](../../AGENTS.md)는 이 문서를 가리키는 지도이며, 영역별 `AGENTS.md`는 담당 영역의 추가 규칙만 정의하고 이 정책을 복사하거나 재정의하지 않습니다. 이 위치로 옮긴 결정은 [ADR 0006](../adr/0006-agents-md-as-map.md)입니다.

## 언어

- 제품과 저장소의 주 언어는 한국어입니다. 문서, 변경 기록, ADR, 사용자에게 보이는 문구, 작업 설명과 보고는 한국어로 작성합니다.
- 코드 식별자, 패키지·명령·파일 이름, 설정 키, API 경로처럼 기술적으로 고정된 값은 원래 표기를 유지합니다.
- 다국어(i18n)는 추후 지원 예정이지만 현재 고려 대상이 아닙니다. 다국어 구조, 번역 파일, 로케일 전환을 미리 추가하지 않습니다. 도입 시점에 ADR로 결정합니다.
- OpenDesign이 생성하거나 관리하는 내부 파일(예: `design/.od-skills/`)은 도구 형식을 유지하며 번역 대상에서 제외합니다.

## 기준 정보와 최신성

- 각 사실은 권위 있는 한 곳에만 둡니다. 현재 구현 사실은 코드, 패키지 manifest, workspace 설정, 환경변수 예시, migration, CI·배포 설정 같은 실행 가능한 원본을 우선합니다. 문서는 의도, 사용법, 제약, 결정을 설명하며 이러한 사실의 경쟁 사본이 되어서는 안 됩니다.
- 문서에 적은 동작마다 근거(관련 소스 경로나 설정 키 등)를 밝힙니다. 현재 소스나 명시적 제품 결정과 연결할 수 없는 내용은 삭제하거나, 현재 동작이 아닌 제안임을 분명히 표시합니다.
- 코드·설정·디자인을 바꾸는 변경에서 영향을 받는 문서도 함께 갱신합니다. 동작이 제거·변경되면 오래된 안내와 링크를 고치거나 삭제합니다. 모순되는 기존 안내를 남긴 채 새 섹션을 덧붙이지 않습니다.
- 하위 시스템을 변경하기 전에 관련 문서와 코드를 읽습니다. 작업을 마칠 때 영향받는 모든 문서와 링크가 결과 구현과 일치하는지 확인합니다. 문서를 바꾸지 않았다면 기존 문서가 여전히 정확하기 때문이어야 합니다.
- 문서가 최신처럼 보이도록 자동 생성 시각, 중복 상태 요약, 구현 이력을 추가하지 않습니다. 이력은 지속적인 결정이나 필요한 운영 맥락을 설명할 때만 기록합니다.
- 문서는 현재 제품을 설명하거나, 제안·폐기 예정 안내·과거 결정임을 명시할 때만 유효합니다. 목적이 끝난 문서는 삭제하고, ADR은 기록으로 보존하되 대체된 결정은 대체됨으로 표시합니다.
- 반복해서 지적되는 규칙은 문서에만 두지 않고 검사(`pnpm docs:check`, ESLint, `pnpm work:check`, `pnpm work:scope`)로 옮깁니다. 검사 오류 메시지에는 해결 방법을 적습니다.

## 배치와 범위

문서는 결정이나 동작을 포괄하는 가장 좁은 위치에 둡니다.

- `docs/`: 제품 전체 요구사항, 여러 영역에 걸친 사용자 흐름, 저장소 아키텍처, 공통 개발·배포 가이드.
- `docs/references/`: 외부 프로젝트·기술·라이선스의 비교와 배경 자료. 출처와 확인일을 표시하고, 저장소의 현재 설정·아키텍처 결정과 구분합니다.
- `docs/adr/`: 여러 영역이나 저장소 전체에 영향을 주는 결정.
- `apps/api/docs/`: 백엔드 전용 개발·아키텍처·운영·배포 가이드. 백엔드 전용 결정은 `apps/api/docs/adr/`.
- `apps/app/docs/`: 모바일 앱 전용 가이드. 앱 전용 결정은 `apps/app/docs/adr/`.
- `apps/web/docs/`: 브라우저 웹 전용 가이드. 웹 전용 결정은 `apps/web/docs/adr/`.
- `design/docs/`: 디자인 원칙과 디자인 작업 가이드. 디자인 전용 결정은 `design/docs/adr/`. OpenDesign 산출물은 `design/`에 유지하며, Markdown을 명시적으로 기준 원본으로 정하고 산출물이 그 문서를 참조하는 경우가 아니면 내용을 Markdown으로 중복 작성하지 않습니다.
- `packages/<name>/docs/`: 패키지 전용 사용법과 설계 가이드. 패키지 전용 결정은 해당 `adr/` 하위 폴더.
- `infra/`: 환경별 실행 설정. 인프라 전용 상세 가이드는 `infra/docs/`, 전용 결정은 `infra/docs/adr/`에 둡니다. 환경 전체에 걸친 사용법·비밀값 관리 안내는 루트 `docs/`에서 연결합니다.

범위별 `docs/`와 `adr/` 폴더는 첫 문서가 생길 때 만듭니다. 범위는 작성자나 구현 위치가 아니라 영향 범위로 정합니다. 예를 들어 데이터베이스 인덱스 결정은 백엔드 범위이고, 앱과 API가 공유하는 API 오류 형식 계약은 여러 영역에 걸치므로 루트 `docs/adr/`에 둡니다.

기준 문서는 하나만 둡니다. 다른 위치에서는 복사하지 않고 링크합니다. 결정의 영향 범위가 넓어지면 기준 문서를 더 넓은 범위로 옮기고 링크를 갱신하며, 남겨둔 ADR 이력은 표시하거나 연결해 현재 내용이 두 가지로 경쟁하지 않게 합니다.

## ADR

- 파일명은 `NNNN-short-title.md` 형식을 사용하고, 각 범위의 `adr/` 폴더 안에서 독립적으로 번호를 매깁니다.
- 날짜, 상태, 배경, 결정, 결과·트레이드오프를 포함하고 범위를 명시합니다.
- ADR은 지속적인 결정을 기록합니다. 진행 일지나 현재 구현 문서를 대신하지 않습니다. 근거로는 현재 기준 문서를 링크하고 work item(`docs/work/<역할 또는 epics>/NNNN-*.md`)에는 링크하지 않습니다. work item은 진행 기록이라 저장소를 옮기거나 정리하면 링크가 끊깁니다(`pnpm docs:check`가 검사).
- 바뀐 결정을 숨기려고 승인된 ADR을 다시 쓰지 않습니다. 이전 ADR을 연결하는 새 ADR을 만들고, 이전 ADR에는 새 ADR 링크와 함께 `대체됨` 상태를 표시합니다. 구현 문서는 대체된 ADR의 대안을 누적하지 않고 현재 상태를 설명합니다.

## 진입점과 유지

- 루트 `README.md`에는 저장소 소개와 빠른 실행 명령만 두고, 상세 안내는 해당 범위의 문서에 두어 링크합니다.
- 루트 `AGENTS.md`는 매 세션 에이전트 컨텍스트에 들어가는 지도입니다. 저장소 소개, 핵심 명령, 반드시 지킬 규칙, 문서 위치만 두고 세부 정책·절차는 이 문서와 범위별 문서로 링크합니다. 크기 예산은 `pnpm docs:check`가 검사합니다.
- `docs/README.md`는 탐색용 색인이며 두 번째 정책 원본이 아닙니다. 정책은 이 문서에 두고 규칙은 이 문서로 링크합니다.
- 문서를 추가하거나 옮길 때 같은 변경에서 참조 링크와 관련 색인을 갱신합니다. 연결되지 않은 문서나 중복된 현재 가이드를 남기지 않습니다.
- 의미 있는 요구·결함·운영 변경은 [ALM 운영 기준](../alm/workflow.md)에 따라 목적·수용 기준·검증·실제 배포를 연결합니다. 작업 추적 도구별 설정은 기준 절차와 분리합니다.
- 환경·비밀값 변경은 [환경과 비밀값 관리](environment-secrets.md)의 소유권과 주입 범위를 함께 확인합니다. 실제 비밀값을 문서·소스·변경 기록에 넣지 않습니다.

## 변경 기록

- `CHANGELOGS.md`는 내부 참고용 전체 변경 기록입니다. 공개·배포 여부와 관계없이 저장소의 모든 변경을 기록합니다. 커밋 전 작업도 기록할 수 있으며, 커밋 뒤에는 해당 커밋을 연결합니다.
- 영역별 변경은 해당 영역의 로그에 기록합니다: `infra/CHANGELOGS.md`, `apps/api/CHANGELOGS.md`, `apps/web/CHANGELOGS.md`, `apps/app/CHANGELOGS.md`. 전용 로그가 없는 `design/`, `packages/`, `docs/`, `.github/`, 루트 설정·정책 변경은 루트 `CHANGELOGS.md`에 기록합니다. 여러 영역에 걸친 작업은 루트 로그에 한 줄로 요약하고, 세부 내용은 영역 로그에 둡니다.
- 변경 기록 항목은 날짜별 제목(`## YYYY-MM-DD`, 최신순) 아래에 둡니다. 각 항목에 무엇이 바뀌었는지와 근거(커밋, work item, 관련 경로 중 해당하는 것)를 적고, 공개 릴리스에 포함된 경우 해당 `RELEASES.md` 버전을 표시합니다.
- 루트 `RELEASES.md`는 공개용 릴리스 노트입니다. 사용자에게 실제로 공개한 릴리스만 기록하며, 버전·날짜·Git tag·대상(웹·앱·API 등)과 사용자 관점의 변경 내용을 적습니다. 내부 구현 세부·미공개 계획·비밀값은 넣지 않습니다. GitHub Releases를 사용할 경우 설명은 같은 tag의 `RELEASES.md` 항목을 원본으로 합니다.
- 환경별 배포 시각·결과·복구 정보는 운영 work item이나 배포 플랫폼에 기록합니다. 코드, 설정, 설치 안내, 현재 아키텍처는 실행 가능한 원본이나 범위별 기준 문서에 두고, 변경 기록에는 무엇이 바뀌었는지만 적습니다.
