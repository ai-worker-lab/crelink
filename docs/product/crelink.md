| R12 | 크리에이터 랜딩페이지에는 프로필 사진, 이름(닉네임)·소개글, SNS 채널 아이콘, 포트폴리오·협업 이력, 외부 링크를 모두 올릴 수 있다. 모든 항목은 선택이며 아무것도 올리지 않아도 된다. 포트폴리오는 이번 버전에서 크리에이터가 직접 입력하고, 이후 캠페인 기능이 생기면 캠페인 이력이 자동으로 더해진다. SNS 채널 아이콘은 크리에이터가 계정 주소를 직접 입력해 붙인다. | [사용자 확정] | [AI 제안] ① 크리에이터가 각 항목을 넣고 고치고 지울 수 있다. ② 비어 있는 항목은 방문자 화면에 자리만 남지 않고 보이지 않는다. ③ 모든 항목이 비어 있어도 랜딩페이지가 열린다(R3 ④). ④ 포트폴리오 항목은 크리에이터가 직접 등록한다(항목 구성 미정). ⑤ SNS 계정 주소를 넣으면 해당 SNS 아이콘이 붙고, 누르면 그 주소로 이동한다. 본인 계정 여부는 확인하지 않는다. |
| R13 | 외부 링크 개수는 계정당 제한한다. 무료는 5개이며, 그 이상은 유료로 슬롯을 구매해 늘린다. 숨긴 링크는 한도에 포함하지 않는다. 이번 버전에서 슬롯은 결제 없이 운영자가 수동으로 부여한다. | [사용자 확정] | [AI 제안] ① 무료 계정은 보이는 외부 링크를 5개까지 둘 수 있다. ② 한도에 도달하면 추가·다시 보이기 대신 한도 안내가 보인다. ③ 운영자가 계정에 슬롯을 부여하면 그 수만큼 한도가 늘어난다. |
| R14 | 위험한 외부 링크는 저장 시 자동 검사로 막고, 운영자가 사후에 차단할 수 있다. MVP의 자동 검사는 크리링 자체 차단 목록(운영자가 등록한 도메인)으로 한다. | [사용자 확정] | [AI 제안] ① 외부 링크를 저장할 때 크리링 차단 목록과 대조해 걸리면 저장되지 않고 이유가 안내된다. ② 운영자가 특정 링크를 차단하면 방문자 화면에서 사라지거나 경고 화면을 거친다. ③ 차단된 링크는 크리에이터 편집 화면에 차단 상태로 표시된다. |
| R15 | 로그인은 구글 소셜 로그인을 기준으로 한다. 크리링 고유 사용자(user)와 소셜 provider 계정은 별도로 구분하며, 한 사용자는 여러 provider에 연동될 수 있다. MVP는 구글 로그인만 제공하고 여러 provider 연동 기능은 MVP가 아니지만, 그 구조는 미리 갖춘다. | [사용자 확정] | [AI 제안] ① 구글 계정으로 가입·로그인할 수 있다. ② 처음 로그인하면 크리링 사용자와 구글 provider 연동 기록이 따로 만들어진다. ③ 데이터 구조상 한 사용자에 여러 provider 연동 기록을 둘 수 있다(연동 화면은 MVP 밖). ④ 구글 OAuth 클라이언트 ID·Secret은 사용자가 발급해 넣는다. |
| R16 | MVP는 웹만 제공하며 모바일 화면에 맞춘 반응형이다. | [사용자 확정] | [AI 제안] ① 랜딩페이지·크리에이터 편집·운영자 화면을 웹으로 제공한다. ② 390px 폭과 1280px 폭에서 가로 넘침 없이 쓸 수 있다. |
| R17 | 크리에이터 프로필 이미지가 없을 경우 기본 프로필을 보여 준다. | [사용자 확정] | [AI 제안] ① 프로필 사진이 없는 랜딩페이지(`/p/{publicId}`)에 기본 프로필 이미지가 보인다(R12의 "빈 항목은 보이지 않음"의 예외). ② 크리에이터 편집 화면의 프로필 사진 자리에도 사진이 없으면 기본 프로필이 보인다. ③ 사진을 올리면 기본 프로필 대신 그 사진이 보인다. |

수용 기준 표기: 요구 문장은 사용자 확정입니다. 2026-10-06 사용자가 R1~R14의 `[AI 제안]` 수용 기준 전체를 MVP 구현 기준으로 채택했습니다(MVP를 써 본 뒤 조정). R15·R16의 수용 기준은 같은 날 사용자 답변(구글 로그인, 웹만)을 옮긴 것입니다. 수용 기준 안의 `미정` 값은 MVP 임시값으로 [기술 설계](../specs/crelink-mvp.md)에서 정하고, 아래 미정 사항으로 남깁니다.

요구별 참고 사실:

- R1: 인스타그램은 프로필 편집 > 링크에서 웹사이트를 최대 5개까지 추가할 수 있습니다([Instagram 고객센터](https://help.instagram.com/362497417173378), 2026-10-06 확인). 링크 추가는 크리에이터가 인스타그램 앱에서 직접 하며, 크리링이 대신 등록하는 것은 전제하지 않습니다.

## 위험과 미정 사항

사용자에게 결정받을 질문(2026-10-06 사용자 결정: MVP 이후에 정함. MVP는 기술 설계의 임시값으로 진행):

- R6: 유료 서비스의 가격과 n의 값(이후 버전).
- R12: 포트폴리오 한 항목의 구성(제목·이미지·링크·설명·날짜 등)과 개수 제한.
- R12: SNS 채널 아이콘으로 지원할 플랫폼 목록(인스타그램, 유튜브, 틱톡, 네이버 블로그 등).
- R13: 숨긴 링크의 보관 상한(없으면 무제한 보관).
- R14: MVP 이후 외부 악성 URL 검사 서비스를 붙일지, 저장된 링크를 주기적으로 다시 검사할지, 방문자 신고 기능을 둘지. 참고: Google Safe Browsing API는 비상업용이며 상업 서비스는 Web Risk로 안내됩니다([Usage Restrictions](https://developers.google.com/safe-browsing/v4/usage-limits), 2026-10-06 확인).
- 이 서비스를 쓰는 사용자군은 누구인가(광고주, 크리에이터, 운영자 외 다른 주체 포함 여부)?
- 첫 버전에서 사용자가 끝까지 할 수 있어야 하는 흐름은 무엇인가?
- 대상 채널(인스타그램, 블로그, 유튜브, 숏폼 등)은 무엇인가?
- 금전 거래(원고료 지급·수수료·정산)를 플랫폼이 다루는가?
- 제공 형태는 웹, 모바일 앱, 둘 다 중 무엇인가?
- 첫 버전의 성공을 무엇으로 판단하는가?

알려진 위험:

- R9·R11: IP 원문·유입 경로·기기 정보·IP 기반 위치·순 방문자 식별자(쿠키 등)는 개인정보에 해당할 수 있어, 개인정보 처리방침에 수집 항목·목적·보관 기간(원본 1년)을 고지해야 합니다. IP 원문을 1년 보관하므로 접근 권한 제한·접근 기록 등 안전성 확보 조치가 필요합니다. 해외 방문자를 받으면 국가별 쿠키 동의 요건도 확인해야 합니다. 법률 검토 전입니다.
- R7: 서비스 랜딩은 보이지 않고 즉시 이동하지만, 단축 URL → 크리에이터 랜딩페이지로 이동이 한 번 더 생겨 인스타그램 인앱 브라우저의 첫 화면 표시가 그만큼 늦어집니다.
- R4: 랜딩페이지가 임의 외부 URL로 보내므로 피싱·악성 링크 유포에 쓰이면 크리링 도메인의 평판(브라우저·인스타그램의 링크 차단)이 떨어질 수 있습니다.
