# 크리링 지표·통계 화면과 조회 권한

- 상태: 구현·로컬 검증
- 작성일: 2026-11-06
- 실행 근거: 사용자 명시 요청 “지표 페이지와 통계 페이지”, “관리자는 통합”, “각 사용자는 지표/통계”. 기존 내부 전용 R10을 본인 집계 조회로 확대하는 결정이다. 구체 배치·계산은 아래 구현 선택으로 남긴다.
- 요구: [PRD](../product/crelink.md) R10·R11·R27·R28.
- 전제: [방문자 수집](crelink-visitor-data.md)의 미커밋 구현·검증을 보존해 이어간다. 커밋·push·main 병합·운영 배포는 이번 요청에 포함하지 않는다.

## 사용자 흐름과 화면

| 대상 | 지표(요약) | 통계(상세) | 범위 |
| --- | --- | --- | --- |
| 크리에이터 | /me/landings/{publicId}/metrics | /me/landings/{publicId}/stats | 로그인한 본인. 기존 레이아웃이 랜딩 소유 확인 |
| 운영자 | /admin/metrics | /admin/stats | 전체 서비스 또는 선택 크리에이터. 계정 검색으로 선택 |

관리 메뉴에 지표·통계를 추가한다. 크리에이터 분석 메뉴는 휴대폰 미리보기·편집 토글을 숨기고 본문을 넓힌다. 관리자 기존 목록·개별 상세 통계는 보존하고 새 통합 메뉴를 연결한다. 디자인은 [인계](../../design/analytics/handoff.md)와 기존 승인된 스튜디오 라이트의 카드·표·폼·토큰을 사용한다.

지표는 페이지 열람·익명 방문자·세션·클릭·클릭한 페이지 비율·평균 활성 시간과 일별 추이를 보여 준다. 통계는 일별 수치, 대상별 클릭/노출, 스크롤 도달 수, 유입·캠페인·국가/도시·기기/브라우저/OS·언어/시간대·표시 환경을 제공한다. 모든 화면에 서울 날짜 기준 7/30/90일·직접 기간 선택을 연결하고 동일 필터로 두 화면을 오간다.

## API와 권한

구현 원본은 `packages/shared/src/analytics.ts`와 `crelink.ts`의 경로, API 서비스·controller·migration이다.

- `GET /api/me/analytics`: SessionGuard, CurrentUser.id로만 조회 범위를 결정. 본인 랜딩이 있는 사람 운영자도 자기 집계를 조회할 수 있다. 계정/타인 랜딩/시험계정 포함 같은 관리자 필터는 거부한다.
- `GET /api/admin/analytics`: OperatorGuard. 날짜 외에 선택 creatorId·landingPublicId와 includeExcluded=1을 받는다. 잘못된 형식은 400, 없는 대상·서로 맞지 않는 필터는 404. 일반 사용자는 403, 비로그인은 401.
- 두 화면은 역할별 하나의 AnalyticsReport를 공유해 불필요한 중복 API를 만들지 않는다. 기존 `GET /api/admin/metrics`(운영 목표)은 변경하지 않고 관리자 요약 화면이 별도 기간·정의로 병행한다.
- 서비스 기본 집계는 기존 실사용 지표와 맞춰 human creator 중 지표 제외 표시가 없는 계정이다. 관리자는 “시험 계정 포함”으로 제외 표시 계정도 통합하거나 해당 크리에이터를 직접 골라 볼 수 있다. 본인 조회는 제외 표시와 무관하다.
- 조회 결과는 집계값·콘텐츠 대상·필터 범위만 포함한다. 방문자 IP·원문 UA·방문자/세션/페이지뷰/이벤트 UUID, 타인 계정의 개인 상세 기록은 내리지 않는다.
- BFF는 해당 GET만 허용하고 기존 세션 전달 경로를 재사용한다. 클라이언트가 보낸 소유자 ID로 범위를 넓히지 않는다.

## 방문자 지표 보강(0232)

새 데이터를 수집하지 않고 저장된 값으로 세 가지를 더한다. 응답 원본은 `AnalyticsReport`의 `sources`, `visitorRecency`, `botExclusions`이고 근거와 적용 위치는 [0232](../work/orchestrator/0232-visitor-metrics.md)다.

- 봇 제외: `isBotUserAgent`(`packages/shared/src/bot-user-agent.ts`, 패턴 목록)로 저장된 `user_agent`를 판별해 `landing_events`와 `visits`·`link_clicks`·`creator_banner_clicks`의 합계·분포·대상에서 뺀다. 제외 건수만 응답·화면에 나타나고 원문·봇 이름은 내리지 않는다. 값이 없으면 사람으로 둔다.
- 유입별 클릭률: 유입 사이트·UTM 소스 값별 페이지뷰, 한 번 이상 클릭한 페이지뷰, 그 비율. 상위 20개 뒤는 기타로 합쳐 분모·분자를 보존한다.
- 신규·재방문: 선택 기간 익명 방문자를 같은 소유 범위의 기간 시작 전 사람 `page_view` 유무로 나눈다. 비교는 남아 있는 원본(365일) 안에서만 하며 화면에 적는다.
- 보존 합계가 선택 기간에 섞이면 세 지표는 `null`이고 화면에 `집계 불가`로 표시한다. 보존 합계에는 User-Agent가 없어 봇을 뺄 수 없고 그대로 남는다.
- 값별 합계만 보여 주고 날짜×유입 교차, 개별 방문자 목록, 봇 종류는 만들지 않는다.

## 지표 계산과 누락

- 일반 열람/클릭/노출 수는 사건이 발생한 서울 날짜 기준. 기존 서버 단축 요청·302 클릭 합계는 별도 영역으로 표시하고 브라우저 클릭과 합산하지 않는다.
- 익명 방문자·세션은 선택된 소유 범위의 page_view에서 전체 기간 DISTINCT. 관리자 전체에서 사용자별 고유 수를 더하지 않는다. 보존 합계가 섞여 정확히 중복 제거할 수 없으면 null로 표시하고 일별·페이지별 합계를 별도 설명한다.
- 활성 시간은 page_view 앵커의 누적 최댓값만 합한다. engagement의 누적 행들을 다시 더하지 않는다. 평균은 활성 시간 합 / pageViews이며 분모가 없으면 null이다.
- 클릭률은 해당 기간에 시작한 열람 중 클릭이 한 번 이상인 비율이다. 클릭 횟수 / 열람 수와 다르다. 대상별 비율은 해당 기간의 관측 노출 중 동일 열람·대상에 후속 클릭이 있는 비율이다. 자정 뒤 클릭도 해당 시작 열람/노출에 연결한다.
- 스크롤은 시작 열람 중 25/50/75/100% 도달 수이다. 실제 읽음을 보증하지 않는다.
- 분포는 page_view 기준. 값이 없으면 알 수 없음, 상위 20개 밖은 기타로 합쳐 분모를 보존한다. 삭제된 대상 이름은 삭제/미상 안내로 표시한다.
- coverage의 원본 보존 경계·가용 자료 첫 날짜·보존 합계 포함·복원 불가 분포를 이용해 미수집과 0을 구분한다. 첫 관측 자료일을 서비스의 실제 최초 도입일로 설명하지 않는다.

## 보존과 조회 일관성

0010은 기존 합계를 지우지 않고 클릭한 열람·스크롤 도달·노출 후 클릭 카운터를 nullable로 더하고, 날짜·페이지·항목별 분포 집계를 추가한다. 과거에 지운 원본에서 계산할 수 없는 항목은 null을 유지한다. 보존 작업이 새 카운터·분포를 만든 뒤 같은 트랜잭션에서 원본을 지운다. IP·방문자 식별자를 장기 집계에 넣지 않는다.

새 통계는 단일 REPEATABLE READ READ ONLY 스냅샷에서 원본과 보존 합계를 읽어 이동 중 중복·누락을 막는다. 기존 StatsService도 이 경계를 적용하고 별도 등록된0186을 실제 동시성 회귀로 확인한 경우에만 완료로 바꾼다.

## 상태·접근성·개인정보

- 로딩·데이터 있음·빈 기간·과거 자료 부족·잘못된 날짜·403·404·네트워크/서버 오류와 다시 시도 상태를 제공한다. 401은 기존 홈 복귀 흐름을 사용한다.
- 새 차트 패키지 없이 기존 카드/표와 작은 SVG·막대를 쓴다. 차트에 요약 설명과 같은 수치의 표/상세 경로를 주고 색만으로 정보를 전달하지 않는다. 키보드·초점·폼 레이블·표 헤더를 유지한다.
- 390px에서는 필터가 줄바꿈하고 KPI는 두 열 또는 한 열로 접는다. 표 스크롤은 컨테이너 안에만 한정하며 문서 가로 넘침을 만들지 않는다.
- 개인정보 고지·제품 요구를 관리자 전체/크리에이터 본인 집계 조회로 갱신한다. 크리에이터는 다른 크리에이터 데이터나 방문자 원본을 조회하지 않는다. 새 외부 전송·위치 권한·로그인 방식은 추가하지 않는다.

## 검토와 분담

0188 통합,0189 에픽,0190 공유 계약,0191 API/보존/일관성,0192 메뉴·화면. API와 웹이 계약·화면 상태를 상호 검토하며 별도 보안 검토가 권한·기간/분모·보존/누락을 확인한다. 새 스타일보다 기존 승인된 컴포넌트 확장을 우선하며 미정 장기 기술 선택을 만들지 않는다.

## 검증 계획

- 실제 격리 PostgreSQL HTTP: 관리자 전체·사용자 필터·시험계정 포함/제외, A/B 소유권·401/403/404·조작 필터, 날짜/빈값·자정·동일 방문자 다중 크리에이터 DISTINCT·누적 시간·중복 클릭·미관측 노출·보존 전후 nullable·분포·스냅샷 경합.
- 웹: 작은 필터/표시 함수 회귀·타입 검사. 실제 익명/크리에이터A/B/운영자 시험 세션에서 네 페이지 메뉴 이동·필터·표시 수치와 DB 대조, 권한 거부·빈 기간·조회 오류, 390/1280px 및 콘솔/가로 넘침을 ego-lite 하나의 TaskSpace에서 확인한다.
- 전체: `pnpm verify`, `pnpm work:scope 0188`, 문서/변경 기록/개인정보 고지 대조. 빌드와 개발 브라우저 검증은 순서대로 실행해 개발 자산 충돌을 피한다.
- 운영 데이터와 개인 계정/비밀번호·인증 코드는 쓰지 않고 이 작업의 합성 데이터만 생성·삭제한다. 배포·실제 휴대폰/인앱 검증 여부는 별도로 보고한다.
